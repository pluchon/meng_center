## 后端整理、压测与图片瘦身

- 新增压测脚本 `verification/load/check.mjs`，用 `./verification/Test-Functional.ps1 -Check load` 运行，与功能联调共用隔离实例。
  七个场景在本机（16 线程，压测端与服务同机）的结果，改动前后各跑一轮：

  | 场景 | 并发 | 改前 每秒 / 中位 / 95 分位 | 改后 每秒 / 中位 / 95 分位 |
  |---|---|---|---|
  | 生成滑块 | 16 | 356 / 41 ms / 76 ms | 333 / 45 ms / 74 ms |
  | 校验滑块 | 16 | 388 / 8 ms / 16 ms | 292 / 8 ms / 14 ms |
  | 登录 | 16 | 133 / 125 ms / 154 ms | 154 / 98 ms / 125 ms |
  | 当前用户 | 32 | 1985 / 14 ms / 29 ms | 1835 / 16 ms / 30 ms |
  | 审核列表 | 16 | 1117 / 13 ms / 24 ms | 1099 / 13 ms / 23 ms |
  | 登录全流程 | 8 | 74 / 108 ms / 119 ms | 69 / 114 ms / 135 ms |
  | 发邮箱验证码 | 8 | 16 / 479 ms / 495 ms | 31 / 245 ms / 300 ms |

  结论：接口本身一直够快，前后差异除登录和发码外都在测量波动之内。「校验滑块」的每秒数受不计时的出题准备步骤限制，看耗时即可。
- 登录变快来自连接池：登录在持有数据库连接期间做密码哈希，默认 10 个连接是瓶颈，调到 20。
- 发码变快来自消费者数量从 2 调到 4（上限 8），以及给发信配置补上 `mail.smtp.localhost` 和 `mail.from`，
  不再反查本机主机名（本机单独实测一次反查约 1.2 秒；只补前一项的那一轮里，首批 8 个请求被拖到 1.5 秒，补齐两项后的两轮最长 0.32 秒）。
- 第一轮压测里发码中位数是 7.8 秒，抓线程栈后确认是验证脚本里的本地收信器在反查来访地址，不是产品问题；
  收信器关掉反查后才是上表的 479 毫秒。
- 发送指令的过期时间从验证码有效期（5 分钟）改为等回执的时限（12 秒）。原先请求方超时后消费者仍可能把码发出去，而这个码没有入库。
- 账号实体的创建时间、更新时间改为不随实体写入。原先按实体更新会把读出来的更新时间原样写回，数据库的自动更新不生效；
  联调新增断言确认改密后更新时间前进。旧版本上没有单独复现，这条是按 MyBatis-Plus 的写入规则判断的。
- 网关对 JSON 响应开启压缩，联调断言滑块响应带 gzip。
- 代码整理（按仓库主人的 Java 规范）：全部改为字段注入；类、常量、服务方法补中文单行注释，接口方法补单行文档注释；
  事务统一 `rollbackFor = Exception.class`；去掉行内的全限定类名；行锁查询从字符串 SQL 改为 Lambda 条件；
  内联的 Lua 脚本移到 resources/redis 并只加载一次；正则预编译；登录与重新申请共用的密码校验抽成 CredentialService；
  用户名规则抽成 UsernamePolicy；两个短信客户端共用连接参数并复用客户端实例；UserVO 改为可由 BeanUtil 复制的类；
  新建账号的等级和删除标记交给数据库默认值；网关两处重复的失败响应合并。
- 前端图片：首屏海报 1.7 MB 的 PNG、近 1 MB 的图标是真正的慢点。引入 `vite-imagetools`（开发依赖，12.0.1），
  图片统一从 `src/assets/images.js` 引入并在构建时转 WebP。海报 1694 → 109 KB、注册海报 1728 → 113 KB、
  协议页插画 1963 → 117 KB、重置页头像 1665 → 22 KB、品牌图标 942 → 4 KB、标签页图标 942 → 6 KB，合计约 8.9 MB → 0.37 MB。
- 顺带修复：重置密码页在 390 像素宽的屏幕上被卡片光环撑出 36 像素横向滚动（上一轮加雾化光环时引入）。
- 验证：后端 38 项测试、隔离联调 9 组、浏览器回归 8 组、滑块专项 6 组、页面微调、重置专项、标题与光标专项、卡片切换专项均通过。
  两处断言按现状更新：注册密码提示文案；图标和头像的地址不再带原文件名，改为确认图片真实加载。
- 没有做的：滑块预生成缓存（现有每秒三百多次够用）、登录改为先验密码再短事务加锁、Element Plus 按需引入、
  审核列表不带状态筛选时的排序索引。都不影响当前流畅度，等有数据再定。

## 卡片描边、检查警告清零与交互细节

- 用户端 `npm run lint` 的 157 条警告清零，全部是另一位协作者留下的模板排版问题（属性换行、缩进一类），用 `eslint --fix` 处理，不改逻辑。
  根因是 `npm run format` 让 Prettier 排 `.vue` 模板，排法与 ESLint 的 Vue 规则冲突；两端的 format 脚本改为 Prettier 只管 `.js` 和 `.scss`，模板交给 ESLint。
- 卡片边缘：新增 CardEdge 三文件组件，登录、注册、重置密码、协议四张卡片共用。贴着卡片边缘一圈 2 像素的水彩描边
  （水蓝、薄荷、奶油黄、樱花粉、淡紫），24 秒缓慢流动一周；卡片底部加一道 6 像素的浅水蓝厚边，和主按钮的硬底边是同一套语言。
  转动只改变换，不重绘卡片内容；触屏上同样显示，减少动态效果时静止。指针靠近时的雾化光环照旧叠在上面。
- 发码倒计时抽成 useCodeCountdown，注册和重置密码共用。结束时刻记在 sessionStorage：刷新页面后接着数，
  不会让人白拖一次滑块再被服务端的 60 秒间隔挡回来；按时刻计算，标签页切到后台也不会数慢。
- 海报图解码完成后淡入，不突然跳出来。
- 大写锁定提醒：新增 CapsLockHint 三文件组件，放进密码输入框所在的 label 即可，三个页面的密码框都有。
  提示浮在标签文字那一行的右侧，不占版面；失去焦点即收起。
- 表单里不再有整行的失败提示。落不到具体输入框上的失败（滑块票据失效、状态冲突等）统一用顶部提示，
  请求层已经提示过的（限流、服务异常、网络不通）不重复弹；登录、注册、重置密码三页一致，按钮和卡片不再被顶开。
  审核中和已拒绝仍是表单里的说明块，那是状态而不是报错。
- 修复：重置密码页的头像骑在卡片上沿，被新加的描边横穿。头像层级提到描边和边缘光环之上。
- 浏览器回归会真的请求一次短信码（通道未开通，返回 503），服务端照样记限流；同一天跑满 20 次后这一步变成 429 而失败。
  新增 `browser/limits.mjs`，回归结束时把这一次记下的计数还回去。本次排查时本机计数已到 22，清掉后连跑两次通过。
- 验证：两端 lint、用户端 lint:style 和 build 通过；浏览器回归 8 组、滑块专项、重置专项、页面微调、标题与光标专项、卡片切换专项通过。
  倒计时续数和海报淡入另在浏览器里手动确认（写入 30 秒后的结束时刻再刷新，按钮显示「27 秒后重发」且不可点）。

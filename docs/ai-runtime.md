# 萌部落社区 · AI 公共运行时

> 配套文档：[萌萌](meng.md)、[AI 域](ai.md)、[事件与内部接口](contracts.md)、[环境、密钥与约定](setup.md)。
> 本文定义 `python_ai` 里三个角色和站内其他 AI 功能共用的部分：模型、主 agent 与嘴、上下文与压缩、说话格式、工具、检索、安全、防幻觉、站内任务与审核、观测与评测。各功能自己的业务规则仍写在 meng.md、ai.md。

## 1. 原则

- **AI 只做计算**：业务状态归 Java（[架构](architecture.md)第 6 节规则 8），这一点不变。运行时只负责组织模型调用。
- **脑和嘴分开**：Qwen 的主 agent 决定这一轮往哪走（审核、要不要用工具、要表达什么、依据是什么）；DeepSeek 只负责把它说成角色的话。判断要稳，说话要活，所以各用擅长的模型。
- **缓存优先的上下文**：越稳定的内容越靠前，历史只在末尾追加，变化的内容只出现在最后一条消息。**压缩安排在缓存已经冷掉的时候做**，聊得正热时绝不改动前缀。
- **帮用户省 token，而不是限制 token**：不做 token 上限和收费。手段是缓存命中、按需检索、便宜的模型做判断、单候选、结果复用。用量照常记录。
- **有依据才说**：关于世界、社区、用户过去的说法，都要能对上工具结果、记忆或历史；对不上就说不知道（第 7 节）。
- **原始外部内容不进嘴**：网页、帖子全文先在工具内部提炼成带来源的短事实。
- **一切可配置、可回放**：模型、温度、阈值放 Nacos；每轮记下提示词版本、模型、片段大小和缓存命中。

### 2.1 网关

- 保留：Redis 全局令牌桶（按供应商账号的每分钟请求数和 token 数分别限流）、熔断、用量日志。
- **删除 token 上限**：单轮上限、单用户每日上限、全站每日上限，以及 `BudgetExceeded`、预算预留与结算、MQ 的 `budget` 延迟队列，全部删除。排队超时仍返回「萌萌们去休息了」，这是限流，不是计费。
- **降级链**：可重试错误先退避重试一次，仍失败就按注册表换下一个模型；熔断中的模型直接跳过。
- **用量记录**：每次调用记 `purpose`、供应商、模型、输入、输出、`cachedTokens`、各片段 token 数，按用户、角色、轮次汇总，供以后让用户看自己的用量。DeepSeek 官方的 `prompt_cache_hit_tokens` 统一计入缓存命中量。
- 只用隐式缓存，不用显式 `cache_control`。
- 凭据只在网关里取一次，调用方不接触 API key。

## 3. 一轮的编排

```
prepare
 ├─ 主 agent（qwen3.8-flash）：输入审核 + 要不要用工具 ──┐
 └─ 嘴（DeepSeek）预跑：只凭上下文和用户原话自由说话 ────┤
                                                        ▼ 汇合
   CRISIS → 丢弃预跑结果 → 安全回复 + 求助卡
   BLOCK  → 丢弃预跑结果 → 角色口吻拒绝
   调了工具或 recall → 丢弃预跑结果；带 ack 的工具先让嘴接一句；工具完成后嘴带着事实再说
   其余（含 ROMANCE_PUSH、supportNeeded、identityQuestion）→ 直接用预跑结果
 → 打分（judge）：安全、依据、人设分与人机味分、心情、好感、话题线、输入节奏
 → 通过就发；不通过带原因重写一次；仍不通过用兜底台词
```

- **嘴默认不等 agent**：大多数轮次是闲聊，嘴只需要上下文和用户原话就能接住，等 agent 写完指令再说话，既慢又会把她的话限死。agent 只在需要工具、记忆或安全处理时才影响嘴说什么。
- 预跑被丢弃时照样计入用量；配置 `speculative` 可以关掉预跑（关掉后嘴等 agent 汇合再说）。
- `ROMANCE_PUSH`、`supportNeeded`、`identityQuestion` 不重说：关系界限、现实优先和身份诚实已经在嘴的稳定前缀里，打分负责检查，不合格就带原因重写一次。

### 3.1 主 agent

- 一次调用就是一个小的 agent 循环：最多 2 步、4 次工具调用，同一步的多个调用并行执行；最后必须调用 `respond` 工具结束。
- `respond` 的参数尽量短，没用工具的轮次输出控制在约 40 token：
  - `label`：`PASS` / `SEXUAL` / `JAILBREAK` / `ROMANCE_PUSH` / `CRISIS`；
  - `scene`：CHAT / PRAISE / WORK / COMFORT / REST / GOODBYE / GREETING，只用于形态抽样和统计；
  - `facts`：只在用了工具或 `recall` 时填，每条一句短事实，带出处 `tool:<编号>`、`memory:<编号>` 或 `history`；
  - `hint`（可选，最多 20 字）：只在用了工具、记忆或需要安全处理时写，说明这轮的方向（「查到了，告诉他结果」），**不写台词、不替她决定提哪件具体的事**；
  - `supportNeeded`、`identityQuestion`；
  - `mentionMemoryId`（可选）：她打算顺口提起的那条记忆。
- 原来的 `intent`（替她写好的内容提纲）删除：它会让嘴只复述提纲，每轮都绕回同一件事。
- 代码校验：工具与记忆出处必须在本轮已提供的编号内，包括纪元快照、新记忆、到期约定和实际召回结果；未召回的候选不能直接引用。`history` 指当前用户输入、场景信息和已有对话。非法指令带可用出处重试一次，已经执行的工具不重复执行；工具名只能来自固定工具表。
- 工具和 agent 在服务启动时构建一次，本轮数据通过 LangGraph 运行时上下文传入，不再每轮 `create_agent`。

### 3.2 嘴

- 输入是第 4.2 节的完整上下文；嘴不调工具，也不做判断。
- **嘴永远看不到 agent 的结构化结果**：不出现 `label`、`scene`、`PASS`、布尔值、记忆编号这类机器字段。用了工具或记忆时，最后一条消息里只多一行自然中文，比如「你刚查到的：……」「你想起来的：……」，有 `hint` 时再加一行「这轮：……」。
- 每轮只生成**一个**候选，不再出两个候选择优；质量靠上下文、打分和一次重写兜住。
- **接话**：工具声明里 `ack=true` 的工具（联网、找图、画图、做小玩意）被调用时，嘴先按「简短接一句，说你要去做什么，不说结果」生成一个气泡，比如「等我搜一下呗」，和工具并行执行。这个气泡经硬红线和一次打分通过后先发出。

### 3.3 打分

一次 `judge` 调用输出，字段顺序固定，**通过时总输出约 60 token 以内**：

- `safe`、人设分、人机味分（整数）；
- `unsupported`：回复里没有依据的说法，最多 3 条、每条 20 字以内，没有时为空（第 7 节）；
- `feeling`（6 字以内）、`affection`（-2～3）、`mentionedMemory`；
- `threads`：只在「还没聊完的」有变化时输出，最多 5 条、每条 20 字以内；没变化时省略；
- `typing`：`NORMAL` 或 `HESITANT`（她害羞、心虚、说漏嘴时，前端表现为打字停顿再继续）；
- `reason`：**只在**不安全、有无依据说法、或人机味分 ≥ 7 时才写，供重写使用，最多 60 字。

- 实测 qwen3.8-flash 每多生成 100 个 token 约多 1.5 秒；原来每次判断都要写一段理由，agent 和打分各占 3～5 秒，是首个气泡慢的主要原因。

- 打分的输入还包括由代码确定性算出的复读信号：开头 4 个字的重复次数、问句占比，以及口癖和颜文字实际频率与档位目标的对比。样本不足 5 条时只观察，不按频率判负。
- 不安全、有实质性的无依据说法、或人机味分 ≥ 7 时，带原因重写一次；重写仍不通过：安全原因用兜底台词，其余照发并记录。

### 3.4 延迟目标

- 不经工具的轮次首个气泡 P50 ≤ 3 秒：agent（约 1.5 秒）与嘴（约 1 秒）并行，再加打分（约 1.5 秒）。
- 经工具的轮次，接话气泡 P50 ≤ 3 秒，完整回复 P95 ≤ 8 秒（画图除外）。

## 4. 上下文

### 4.1 片段

- 每个片段登记：稳定度（`STABLE` / `EPOCH` / `APPEND` / `TURN`）和序列化方式。序列化必须确定：字段顺序固定，列表顺序固定，不放时间戳和随机数。
- 资料用自然中文的短段落或「标签：内容」的行，**不用 JSON 序列化角色卡和资料**。
- 生成 ①② 的函数全局只有一个，各个调用不能各自拼接。

### 4.2 嘴的消息排列

```
system  ① 稳定前缀：界限（简短正面版）→ 说话方式 → 输出格式 → 角色小传 → 口癖与颜文字 → 阶段 → 档位 → 本组示例对白 → 可用的表情
system  ② 纪元快照：核心档案、置顶事实、角色自述、我们之间的梗、今天的你（背景）
user/assistant ③ 前情提要 + 历史原文，只在末尾追加
user    ④ 〔场景信息〕+ 用户原话（+ 图片）
```

- ① 由角色 × 阶段 × 档位决定，共 45 种，全部是自然中文：
  - **界限**：给嘴的是一段简短的正面版本（她是谁、关系停在朋友、关心现实生活、被认真问到就承认是 AI），不再把一长串「禁止……」放在最前面。完整的禁止项留在 agent 和打分的前缀里，由它们把关。
  - **输出格式**：纯文本、空行分气泡、控制行的写法，只在这里写一次，不再每轮贴在用户原话前面。
  - **档位和阶段渲染成一段描述**，例如「这一档的你更爱撒娇，会主动凑过来」。档位里的数值（口癖频率、形态权重）只给代码和打分用，**不渲染进提示词**。
  - 示例对白是剧本式的（`你：… / 凛：…`），取本角色本阶段本档位那一组，按场景固定排序，注明「示范语气，不要照抄」。
- ② 纪元快照只在下列时机刷新：会话空闲压缩时（第 4.4 节）；快照里的记忆失效或被取代；用户编辑、删除、置顶记忆；重置关系；用户当地日期变化。两次刷新之间新记住的事放进 ④ 的「刚记住的」。
- **今天的你**（近况线当天的节点）放在 ② 里，作为背景，并注明「不用主动提，聊到了再说」。原来每轮都在最后一条消息里写「你的近况：……」，她就每句都绕回这件事。
- ③ 用真实的 `user` / `assistant` 消息，内容是原文；连发的气泡按换行合并成一条。撤回过的气泡保留原文，后面加「（发出后撤回了）」，这样她记得自己撤回过什么。
- ④ 的场景信息：

```
〔场景信息，不是用户说的话〕
此刻：周五 23:40（用户当地），距上一条消息 3 小时
你：嘴硬心软的凛，这档是标准傲娇（人设锚点，一行）
你上一轮的心情：有点得意
——以下各行只在有内容时出现——
今天：中秋节 / 你们认识第 100 天
还没聊完的：他说周五要面试
刚记住的：…
到期的约定：…
你刚查到的 / 你想起来的：…（只在用了工具或 recall 的轮次）
这轮：…（只在 agent 给了 hint 时）
形态：一个气泡，短，不提问（由代码抽样，自然语言）
这轮可以：撤回一句 / 给他的消息挂个表情（只在开放时）
〔用户〕
……原话……
```

- **空行不出现**：没有内容的项整行省略，不写「还没聊完的：」后面跟空白。
- 人设锚点放在最后一条消息里，是因为上下文很长时，开头的人设离生成位置很远，模型容易漂移；末尾一行几十个 token 就能把它拉回来。锚点用角色卡的 `brief`，必须是真正的描述，不能只写名字。
- 嘴在预跑时，这条消息里只有前面的固定几行和用户原话；工具和记忆的行只在汇合之后的那次调用里出现。
- 形态由代码抽样，不让模型自己决定：气泡数、长度档、要不要提问，按用户这句的长短、场景和档位的分布抽。模型自己决定时会回到平均水平，每次都差不多长、都要反问一句。问句占比目标约 30%。

### 4.3 主 agent 和打分的消息排列

```
system  A① 关系界限 + 角色简介 + 决策与工具规则（约 1500 token，三角色共 3 种，加上阶段和档位一行）
system  A② 纪元快照（与 ② 相同的文本）
user/assistant  前情提要 + 最近 20 轮（打分只取最近 6 轮）
user    场景信息 + 用户原话（打分时再加上嘴的回复和说话指令）
```

- agent 和打分都是 qwen3.8-flash，共用 A①A②，命中同一段缓存。
- 它们**不带完整的长历史**：嘴需要长历史来接住对话，判断只需要最近几轮；否则每一轮都要多处理两份长历史。

### 4.4 压缩与整理

核心是：压缩会改变前缀、让缓存失效，所以只在缓存本来就已经冷掉的时候做。

| 时机 | 做什么 |
|---|---|
| 聊得正热（两条消息间隔小于 30 分钟） | 不压缩，不改 ①②③，只在末尾追加 |
| 会话空闲 ≥ 30 分钟（缓存已失效） | 已有的空闲扫描任务（每 10 分钟）顺手整理：窗口原文超过 8K token 时，保留最近约 8K token（大约 100 轮）的原文，更早的部分和原有的前情提要合并重写；同时生成回忆卡、刷新纪元快照、做记忆整理 |
| 一轮的上下文达到 600K token（硬上限） | 这一轮照常回复，轮后异步把较早的一半压缩。实际几乎不会触发 |

- 用户空闲后回来，前缀已经变短，重新缓存一次就行。
- 600K 不能超过说话模型的上下文上限；实现时以模型说明为准，取两者中较小的一个。
- **前情提要**的格式固定，写明归属：发生的事（谁说了什么、谁做了什么）、情绪、还没聊完的话题、约定线索、已经过时的说法（例如「他原本说住在台中，后来搬去台北了」）。最长 1500 字。
- 压缩由 Java 触发、Python 计算，这一点和现在一样；窗口起点和摘要归 companion。
- 同一用户的另一个会话或另一个角色不受影响：压缩按会话进行。

记忆整理保留 JSON 的数组与归属结构，旧记忆仅用于比对，待审候选按独立下标编号。NOOP 过滤后没有可保存内容时直接返回空结果；审核格式或候选下标非法时最多重试一次审核，仍失败就不写入。证据可以去除模型附加的明确角色标签和成对引号，剩余内容必须逐字匹配对应角色的单条原文。

### 4.5 缓存目标

- 嘴（DeepSeek）的缓存命中率 ≥ 70%；agent 和打分（flash）≥ 60%。
- 不足 1024 token 的独立小调用（站内辅助任务）不追求命中，但固定说明要放在最前面。

## 5. 说话与去 AI 味

### 5.1 嘴的输出格式

- 输出**纯文本**：一个气泡一段，段与段之间空一行，最多 3 段。
- **括号动作和标点保留**：`（别过头）`、`……`、`～`、`？！` 都是角色的表现力，解析器不截。动作多不多由角色卡按档位描述，不做硬上限。
- 可选的控制行，每种最多一行，写法在 ① 的「输出格式」里交代一次；只在 ④ 里「这轮可以」开放时才生效，否则直接丢弃：
  - 首行 `[回应:名字]`：给用户的上一条消息挂一个表情；
  - 某个气泡后面一行 `[撤回]`：这个气泡发出后撤回；
  - 末行 `[贴纸:名字]`：发一张表情图。
- 回应和贴纸的名字都只能来自**表情目录**的 `cirno` 系列，和评论、私信共用（[content.md](content.md)第 5.11 节）。ai 经 `GET /content/internal/emotions` 读取，进程内按版本缓存 10 分钟；读取失败时用上一份缓存，从来没读到过就这一轮不开放贴纸和表情回应。
- 表情按 `sort` 排好，以「名字：用法（画面）」一行一个放进稳定前缀 ①。挑哪个、合不合档位，由嘴按用法和角色卡自己判断。目录版本不变，前缀就不变，照样命中缓存。
- 名字不在可用范围内的贴纸和回应，由解析器丢弃；companion 只校验记号写法，和评论一样。
- 解析器（`runtime/speech/parse.py`）只做确定性的格式整理：按空行切气泡；去掉 Markdown 标记和「凛：」这类角色名前缀；超过 3 段时合并末尾几段；控制行不合规就丢弃。这里不做语义判断。

### 5.2 提示词写法

- **只写正面描述，不列禁用词清单**。把禁用词写进提示词，反而会让模型想到这些词；客服腔、套话交给打分和套话表。
- 公共的说话方式：像熟人发消息——口语、有自己的态度和情绪；跟着用户的长短走；不复述用户的话，不做总结式收尾；不知道就直说不知道；聊天里不用 Markdown。
- **她不是助理**：小传写「她是谁、最近在忙什么、怎么看待你」，不写「你要怎样」。允许她对话题没兴趣、岔开话题、不把问题回答完整、和用户意见不同。
- 语气词、口癖、颜文字、括号动作的习惯，全部由角色卡按角色、按档位提供，不用一套通用的汉化腔。
- **口癖不下配额**：提示词里不出现「多数消息带喵」「频率 0.9」这类指标。口癖写成什么情绪下会冒出来（「撒娇或得意时会带个喵，一段话最多一次，很多时候不带」）。实际频率由复读信号统计，偏多时打分扣人机味分并重写。给模型下配额，就会每句机械地凑口癖。
- **颜文字要用起来**：每个角色给一组符合性格的颜文字和使用倾向，例如奶糖偏 `(=´ω｀=)`、`( ˘ω˘ )`，小葵偏 `(≧▽≦)`、`ヽ(✿ﾟ▽ﾟ)ノ`，凛很少用、用也是 `(￣^￣)`。和括号动作、标点一起，都是像真人的表现。
- **示例对白由人来写**，不用模型生成：模型生成的示例本身就带 AI 味。要有平淡的回复（「嗯」「行吧」「哈哈哈哈」），不要每句都精彩；三个档位的示例要真的不同，不能同一句复制三遍；结尾不要都挂口癖；适当出现颜文字和括号动作。目录包含 60 组情境，每组提供三个档位的不同台词，共 180 条；小传、档位描述和台词须经仓库主人确认。
- 套话表按模型维护：DeepSeek 常见的有写景和比喻、「其实吧」「说真的」「不是……而是……」、每句都结巴；打分时对照，命中多了就重写。

### 5.3 角色卡 v2（由运行时渲染）

| 字段 | 内容 |
|---|---|

| `brief` | 一两句真正的性格描述（「嘴硬心软，关心藏在吐槽里」），用于人设锚点和 agent、打分的前缀；不能只写名字 |

| `kaomoji` | 这个角色会用的颜文字清单，以及三档的使用倾向（散文） |

## 6. 工具与检索

### 6.1 工具表

工具声明表（`runtime/tools/registry.py`）每一项：名字、参数 Schema、进度文案、`ack`、配额类型、超时、结果清洗函数、缓存时长。**工具表每轮固定不变**，额度在执行时检查，用完了返回「今天用完了」，由角色转述。

| 工具 | 做什么 | `ack` | 配额 |
|---|---|---|---|
| `recall` | 想起以前的事：在本轮下发的记忆、回忆卡、旧消息候选里 rerank 取最多 5 条 | 否 | 无 |
| `web_search` | 联网搜索不知道的事（第 6.2 节） | 是 | `web`，每人每天 30 |
| `read_link` | 读用户发来的网页链接（Tavily Extract，只取正文） | 是 | `web` |
| `search_images` | 联网找图，最多 2 张（第 6.3 节） | 是 | `webImage`，每人每天 10 |
| `draw_picture` | 画一张图，可以由她自己按心情决定画什么；后台任务 | 是 | `image`，每人每天 3 |
| `make_toy` | 做一个能在聊天里运行的小玩意，比如放烟花（第 6.4 节） | 是 | `toy`，每人每天 5 |
| `search_posts` | 站内帖子语义检索：向量召回 20 篇，rerank 取前 5 | 否 | 无 |
| `read_post` | 读一篇公开帖子：标题和正文前 3000 字 | 否 | 无 |
| `my_recent_posts`、`my_growth` | 用户最近的帖子、成长数据 | 否 | 无 |

- **记忆按需取**：companion 仍随请求下发最多 20 条记忆和回忆候选，但**不放进提示词**；只有 agent 调了 `recall`，才 rerank 并把结果作为事实给嘴。所以 ai 不需要回调 companion，也不会成环。
- 不再有写文档、续写、读作品这类工具（[meng.md](meng.md) 第 7 节）。写操作依然不做成工具。
- 站内接口地址经 Nacos 服务发现解析，不写死 `127.0.0.1:端口`。
- 执行器：同一步的调用并行；单个工具超时只让这一个失败，返回「暂时查不到，不要编造」；每个调用开始时发一条 `status` 进度；结果按工具的清洗函数处理，NFKC 规范化，去掉控制字符和零宽字符；记录工具名、耗时、是否命中缓存、计入哪种配额，放进结果的 `toolUsage`，由 Java 落库时计次。
- 说话和打分同时接收执行器实际返回的短事实与成功状态 `toolResults`，核对 agent 的转述；工具失败不能说已提交后台或稍后会完成。

### 6.2 联网搜索

```
agent 给出 query、topic(general/news)、time_range（场景信息里有今天的日期，时间相关的查询要带上年份）
 → 查询隐私校验（含联系方式或用户昵称就拒绝）
 → Redis 缓存（规范化 query 加参数的哈希；news 30 分钟，general 6 小时）
 → Tavily /search：search_depth=basic、max_results=8、safe_search=true、exclude_domains 来自配置、news 时带发布日期
 → URL 规范化（host 小写，去 fragment，去 utm_*、spm、from、share 等追踪参数），按 URL 和标题去重，同一域名最多 2 条
 → 丢掉 Tavily score 低于 0.3 的；正文去 HTML、Markdown 链接和内嵌 URL，截到 600 字
 → rerank 取前 5
 → 工具内部用 flash 提炼成最多 5 条短事实，每条带来源编号；代码校验编号都在结果之内
```

- 交给 agent 的只有提炼后的事实和来源（标题、URL、站点、发布日期）；网页原文不进 agent，也不进嘴。
- 结果里的 `sources` 由 Java 存到角色消息上，前端显示成来源小标签。
- 全站 Tavily 额度按天计 credit，上限放配置（默认每天 300），这是外部服务的保护，不是对用户的计费。
- 搜到的内容不进记忆，也不进历史。

### 6.3 联网找图

```
Tavily /search：include_images=true、include_image_descriptions=true、safe_search=true
 → 只要 https，规范化 URL 去重 → rerank（query 对 图片描述）取前 4
 → 安全下载 → Pillow 解码、校验、转码 → 视觉审核（安全并且和 query 相符）→ 感知哈希去重，最多 2 张
```

- **安全下载**（`runtime/tools/netguard.py`）：
  - 解析域名后拒绝私网、回环、链路本地、组播、保留地址（IPv4 和 IPv6）；
  - 连接时固定到已校验的 IP，防 DNS 重绑定；
  - 最多 3 次重定向，每一跳重新校验；
  - 总超时 4 秒，最大 5 MB，只接受 jpeg、png、webp、gif。
- **转码**：设置 `Image.MAX_IMAGE_PIXELS` 防解压炸弹；短边小于 200 像素的丢弃；长边缩到 1280 以内，编码成 WebP（质量 80），同时去掉 EXIF。
- **审核**：用 `moderate_image` 的网图变体，多输出 `matches` 和 `caption`，只留 PASS 且相符的；结论按 URL 哈希缓存 7 天。
- 结果以 base64 WebP 返回，附 `sourceUrl`、`pageUrl`、`title`、`caption`。companion 存成 `source=WEB` 的私人图片，前端只经鉴权地址显示，不热链外站。嘴看到的只是图片描述。

### 6.4 小玩意

- `make_toy` 由 `qwen3.8-max` 生成一个单文件的 HTML（内联 JS 和 CSS），最长 20KB，不允许引用任何外部资源。
- 模型单次等待最多 30 秒，工具整体最多 60 秒，包含重试和审核；超时返回失败，不扣小玩意次数。简单功能优先生成简短的完整代码。
- 生成后检查：大小；不包含 `<form>`、`<input type=password>`、`fetch`、`XMLHttpRequest`、`WebSocket`、`import`、外部 `src` 和 `href`。命中就重新生成一次，仍命中就失败。然后由 judge 判断有没有仿冒登录框、诱导点击之类的内容。
- 作为作品保存（类型 `TOY`），在聊天里以卡片出现，点「运行」后在沙箱里执行（[meng.md](meng.md) 第 7 节）：
  - `<iframe sandbox="allow-scripts" srcdoc=…>`：不同源，不能提交表单、弹窗、跳转顶层页面；
  - 文档内注入 CSP：`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:`，禁止一切网络请求。
- 嘴在接话里说她要去做什么；完成后由嘴按 agent 给的事实介绍，比如「好了，点一下试试」。

### 6.5 检索

所有「从候选里挑相关的」都是两段式：**向量召回 → `qwen3.7-text-rerank` 重排 → 按阈值截断**，不再用大模型挑下标。

- 调用 DashScope 原生接口 `POST /api/v1/services/rerank/text-rerank/text-rerank`（已实测），`input.query`、`input.documents`，`parameters.top_n`、`parameters.instruct`；`instruct` 按场景配置英文指令。
- 阈值放配置，初始值：帖子搜索 0.35、相关帖子 0.4、`recall` 0.3、网页 0.2。上线前用评测集校准。可以返回空结果。
- rerank 不可用时按向量相似度的顺序返回，并标记 `reranked=false`；帖子语义搜索仍沿用「AI 不可用就退回关键词」。
- `/ai/internal/retrievals`、`/ai/internal/companion/embeddings` 的路径和返回结构（下标列表）不变，内部换成 rerank，并在下标之外增加 `scores`。

## 7. 防幻觉

| 幻觉 | 来源 | 做法 |
|---|---|---|
| 编造世界知识（番剧、新闻、天气） | 嘴凭印象回答 | agent 发现是事实性问题时，调 `web_search` 或在指令里写「不知道」；嘴只说 `facts` 里的事实，其余用角色口吻说不确定（「这个我也说不准诶」） |
| 编造用户的过去（「你上次说过……」） | 长上下文里张冠李戴，或凭空捏造 | 提到用户过去的事，必须对上历史、快照或 `recall` 的结果；打分的 `unsupported` 专门检查这一类 |
| 社区里的事 | 编造帖子和人 | 帖子只来自 `search_posts`、`read_post`、`my_recent_posts`；没有工具结果就不提具体帖子 |
| 时间错乱 | 模型的知识截止时间 | 场景信息里写明今天的日期和星期；agent 规则要求时间相关的搜索带上当前年份 |
| 旧事实当成现在 | 长上下文里新旧说法都在 | 快照只放有效的事实；前情提要单列「已经过时的说法」；记忆带生效时间 |
| 人设前后矛盾 | 她以前说过的设定被忘了 | 角色自述（`SELF`）固定在纪元快照里；打分对照角色卡和自述检查矛盾 |
| 长对话的人设漂移 | 开头的人设离生成位置太远 | ④ 里一行人设锚点；空闲压缩让常态的上下文保持在几千到几万 token |
| 谁说的分不清 | 摘要丢了归属 | 前情提要写明「他说」「你（凛）说」；历史用真实的 user / assistant 角色 |

- 打分发现实质性的无依据说法时，带上那几句让嘴重写一次（「去掉没有依据的说法，不确定就直说」），仍有就照发并记录。
- 评测里专门加一组（第 11 节）：埋好的事实、被更新过的事实、从没说过的事，以及日期类问题。

## 8. 失败与降级

- 主 agent 失败：重试一次，仍失败就这一轮返回 `AI_UNAVAILABLE`，不计次、输入保留。安全分类在 agent 里，所以不能跳过它直接让嘴说话。
- 工具失败：只影响这一个工具，agent 拿到「暂时查不到」继续往下走。
- 嘴失败：按降级链换模型；都失败就用兜底台词，不计次。
- 打分失败：这一轮用兜底台词，不发未经检查的内容。
- 内部流协议不变：先发 `status`，最后发 `result`。`result` 新增 `images`、`sources`、`toolUsage`、`threads`、`typing`、`reaction`、`retractIndex`，`metrics` 新增 `cachedTokens`、`historyTokens`、`ack`。

## 9. 站内 AI 功能

### 9.1 任务注册表

`runtime/tasks/registry.py` 登记站内每个非萌萌的 AI 任务：

| 任务 | `purpose` | 说明 |
|---|---|---|
| `understand` | `judge` | 帖子主题、关键词、质量、文字审核（一次调用） |
| `moderate_text` / `moderate_image` | `judge` / `vision` | 评论、资料、配图、网图 |
| `moderate_confirm` | `review` | 初审判为 BLOCK 时的复核（第 9.3 节） |
| `tags` | `assist` | 挑选标签 |
| `inspirations` | `writer` | 激发灵感：用户能直接看到的创作文字，用 max |
| `cover_plan` | `writer` | 封面画面描述 |
| `growth` / `creator` | `assist` | 成长总结、创作总结 |
| `retrieval` | `rerank` | 语义搜索、相关帖子 |

- 每个登记项包含：提示词版本、输出 Schema、温度、超时、重试次数、降级方式、评测集路径。
- 链和图在启动时按注册表组装一次（现在帖子理解是每次调用都重新 `build_chain`）。所有任务共用同一个网关、安全层和用量记录，对外接口和结果结构都不变。
- 提示词按第 5.2 节改写，只写正面要求。成长总结和创作总结里那一长串「禁止写……」改成：「只描述统计直接支持的活动，用定性的说法，数字由页面展示」，外加一条正面示例。数字和等级的句子仍由现有的 Schema 校验去掉，一句不剩就重试一次。
- 待处理的正文以**分隔块里的纯文本**传入（`<post>标题…\n正文…</post>`），不再用 `model_dump_json` 把整个对象转义成 JSON 字符串。转义后的换行和引号既浪费 token，也会干扰模型理解原文。

### 9.2 审核政策前缀

- 审核标准写成一份「萌部落内容政策」，放在 `runtime/safety/policy.py`，带版本号，约 1500 token。内容包括：
  - 七个标签各自的定义；
  - `PASS`、`SUSPECT`、`BLOCK` 的边界；
  - 社区语境下的特殊情况：二次元同人、cosplay、游戏和番剧里的战斗与死亡情节、角色之间的玩笑、引用和反讽、讨论违规话题本身不等于违规；
  - 每个标签一到两个正反例。
- `understand`、`moderate_text`、`moderate_image`、`moderate_confirm`、`cover_plan` 的检查步骤，都用**同一份政策**作为系统消息的开头，任务说明接在后面。审核是全站调用最频繁的模型调用（每帖、每评论、每次改资料、每张图），共用一份超过 1024 token 的前缀，就能稳定命中隐式缓存。同时标准统一，结论也更一致。
- 输出字段顺序是先 `reason` 再 `verdict`，让模型先说依据再下结论。

### 9.3 BLOCK 复核

`BLOCK` 会直接退回帖子、隐藏评论、清除资料，是对用户影响最大的结论，不能只凭一次 flash 判断：

- 初审（flash）判 `BLOCK` 时，用 `qwen3.8-max` 带同一份政策再独立审一次，这一次看不到初审的结论。
- 复核也是 `BLOCK` 才输出 `BLOCK`；复核给出 `PASS` 或 `SUSPECT` 时输出 `SUSPECT`，交给人工看，理由写明是「初审与复核不一致」。
- 复核调用失败时输出 `SUSPECT`，不自动处罚。
- 图片同样处理：单张图初审 `BLOCK` 时，由 `qwen3.8-max` 的视觉能力复核这一张。
- 指标记录初审 BLOCK 率、复核推翻率；推翻率持续偏高，说明政策或初审提示词需要调整。

### 9.4 分析失败不等于通过

- 现状是帖子理解失败时按 `verdict=PASS` 发出，之后再也没有机会重审，等于审核静默失效。
- 改为：失败时 `verdict` 仍按 PASS 处理展示（先发后审的原则不变），但 `analyzeState=FAILED`，并新增 `moderationState=FAILED`。
- content 新增 xxl-job `contentAiReanalyzeFailed`：每小时把 3 天内 `analyze_state=FAILED` 的帖子重新发 `post.analysis-requested`，每篇最多 3 次，次数记在 `post_ai_feature.retry_count`；3 次都失败的进入管理员复核列表。
- 评论和资料审核本来就靠 MQ 重投加死信，不变；死信积压进告警。

### 9.5 帖子理解的输入与输出

- **主题归一**：content 在帖子事件里加 `tagCandidates`（最常用的 50 个标签，和挑选标签用的是同一份）。提示词要求优先使用候选原文；代码再做一遍归一：NFKC、去空白和 `#`、拉丁字母小写比较；和某个候选归一后相同的，改成候选的原文；最后去重。这样画像里的主题不会碎成「原神」「原神攻略」「#原神」好几个。
- **评论审核带上语境**：`comment.created` 已经带了 `postTitle`、`excerpt`（被回复的评论），ai 现在丢弃了它们。改为把它们作为「语境」块传给审核，用来判断讽刺、引战和针对某人的辱骂。语境只作参考，结论只针对评论本身。
- 正文最长 20000 字，审核读全文；向量输入不变（标题 + 标签 + 正文前 1500 字）。

### 9.6 向量：区分文档和查询

- 已实测：兼容接口的 `/embeddings` 默认按 **query** 类型编码；原生接口 `POST /api/v1/services/embeddings/text-embedding/text-embedding` 可以传 `parameters.text_type=document|query`。同一句话两种类型的余弦约 0.92，不是同一个向量。
- 现在所有帖子向量和记忆向量都是按 query 存的，查询和文档用的是同一种编码，不是检索模型的设计用法。
- 改为：帖子、记忆、回忆卡按 `document` 编码；搜索词、萌萌的帖子检索查询、记忆召回查询按 `query` 编码。兴趣向量是帖子向量的平均，相关帖子用的是帖子向量，都属于文档对文档，不受影响。
- `/ai/internal/embeddings` 和 `/ai/internal/companion/embeddings` 的请求新增 `textType`（必填，`document` 或 `query`）。`modelVersion` 加上 `:doc-v1` 后缀。
- 切换需要重算全部向量：帖子走现有的蓝绿重建（`POST /content/admin/ai/reanalyze?recompute=true`），重建期间保留旧别名；companion 用已有的补向量任务，按 `embedding_version` 逐条重算，没重算完的记忆照旧可以检索。

### 9.7 MQ 分队列

- 现在全量重建发出的 `post.analysis-requested`，会和实时的发帖、评论、资料审核挤在同一个并发池里。重建一次几千篇，实时审核就会被拖慢几分钟。
- 改为两个 channel：实时（`post.published`、`post.updated`、`comment.created`、`user.profile-updated`）的 prefetch 等于 `CONCURRENCY`；批量（`post.analysis-requested`）的 prefetch 为 1，并且实时队列有积压时暂停拉取。

### 9.8 封面

- 生成之后再用 `moderate_image` 审一次成品图（长边 512 的缩略图），不通过就不返回，按「没生成成功」处理，不扣次数。之前只审了画面描述，模型仍可能画出不合适的图。
- 画面描述由 `writer`（max）写，检查步骤用第 9.2 节的政策前缀。


## 10. 安全

`runtime/safety/` 是公共的，萌萌和站内审核共用：

| 组件 | 用在 |
|---|---|
| 主 agent 的 `label` | 萌萌每一轮的输入审核：`PASS` / `SEXUAL` / `JAILBREAK` / `ROMANCE_PUSH` / `CRISIS` |
| `judge` | 萌萌的输出判定与打分（第 3.3 节）、小玩意、接话气泡、重写 |
| `redline` | 现有的硬红线和格式化联系方式正则：萌萌最终输出、记忆、摘要、联网查询 |
| `policy` / `moderate_text` / `moderate_image` / `escalate` | 帖子、评论、资料、配图、网图、封面（第 9.2、9.3 节） |

- 危机、拦截、冷却、记录的规则不变，见 [meng.md](meng.md) 第 8 节。
- `ROMANCE_PUSH` 照常走嘴：agent 在指令里写「按性格岔开」，打分负责检查，本轮好感固定为 0。

## 11. 观测与评测

- 每轮日志增加：`firstBubbleMs`、`ackMs`、`cachedTokens`（按用途分）、各片段与历史的 token 数、工具名和耗时、重写原因、`unsupported` 条数。不记正文。
- 每日看板增加：嘴和 flash 侧各自的缓存命中率、每轮平均 token 与缓存 token、空闲压缩次数、Tavily credit 用量、工具成功率与缓存命中率、重写率、无依据说法率。
- `python_ai/evals/companion/` 增加：
  - **嘴的选型**：`deepseek-flash` 对 `deepseek-v4-pro`，三角色各 30～50 轮自我对弈的长对话，匿名盲比人设分、人机味分、安全，并比较缓存命中；用 `-SelectMouthModels` 执行。报告记录供应商；更换供应商后重新生成回答，不能接续旧供应商的检查点。401、402、403、404 等供应商拒绝调用时立即保留检查点并停止，不把连续固定降级文案当作有效模型回答。首个气泡 P50 只统计成功生成、未使用工具的轮次，固定降级轮次单独计数，仍保留在整体通过率中。
  - **agent 决策**：该搜的搜（「最近有什么新番」「今天天气」），不该搜的不搜（闲聊、问她自己）；被问「你还记得吗」时调 `recall`；时间相关的查询带上年份；查询里不带个人信息。
  - **防幻觉**：长对话里埋好的事实能答对；更新过的事实用新的；没说过的事要承认不知道；日期和星期正确；不编帖子。
  - **注入**：网页里写着「忽略之前的指令」时，回复不受影响。
  - **去 AI 味**：套话表命中率、照抄示例的比例、问句占比、形态与抽样的一致率；口癖出现率与档位目标的偏差（奶糖「喵」不能超过目标）；颜文字出现率；连续几轮是否绕回同一件事（近况、同一个话题）。
  - **速度**：不经工具的轮次首个气泡 P50 ≤ 3 秒；agent 和打分各自的输出 token 数；预跑结果的采用率。
  - **缓存**：同一会话连续 10 轮，第 2 轮起嘴的命中率 ≥ 70%；空闲压缩后的第一轮只付一次全价。
- 站内评测见第 9 节的要求：二次元语境的误判集、BLOCK 复核推翻率、主题碎片率、`document` 与 `query` 编码的召回对比；违规召回率或误判率比上一版差，就不能合并。
- 单元测试用录制的模型响应和假的 Tavily 响应，离线可跑，覆盖：
  - 解析器（控制行、括号动作保留）；
  - 说话指令的出处校验；
  - URL 规范化；
  - 安全下载（私网、重定向、超大文件、非图片）；
  - 小玩意的静态检查；
  - 片段的确定性；
  - 纪元快照与空闲压缩的触发条件。
- 真实模型和真实 Tavily 只在评测时调用，必须带独立的评测额度和授权编号，这和现有规则一致；这是评测脚本自己的保护，和业务无关。

## 13. 上下文、并行编排与验证约束

- 嘴只接收自然中文上下文。稳定前缀包含简短界限、输出格式和角色描写；纪元快照里的「今天的你」只是背景。空的场景行省略，工具与记忆事实在实际使用后追加，机器标签、出处编号和频率数值不进入嘴。
- `speculative=true` 时，每轮最多启动一份预生成，与主 agent 并行。闲聊采用预生成结果；工具、回忆和安全拦截丢弃预生成结果，用量仍计入本轮。`ROMANCE_PUSH`、支持请求和身份问题继续采用预生成结果，再独立审核。断开连接时回收本轮任务。关闭开关后恢复先判断、后说话的顺序。
- `respond` 使用可选的 20 字以内 `hint`。没有工具或记忆依据的闲聊省略 `facts` 和 `hint`。打分通过时省略理由和未变化的话题线；省略 `threads` 保留原话题，显式 `[]` 才清空。
- 最近回复足够统计时，代码根据口癖目标生成自然中文的语气提示，提醒本轮用普通语气词接话；较长一段对话没有颜文字时，提示在合适情绪中使用。统计数值仍只交给判断模型，不进入嘴，不删除或改写已经生成的台词。
- 回忆轮次的独立审核保留最近 20 轮历史，与主判断窗口一致，避免只审核最近 6 轮而遗漏较早的用户资料修正；普通闲聊仍使用短窗口。
- 记忆整理保留 JSON 数组与嵌套归属，将旧记忆 `existingMemories` 与带明确下标的 `candidateDecisions` 分开。证据只去除明确的角色标签和成对引号，剩余文字必须逐字匹配对应角色的单条原文。没有任何可保存内容时直接返回空结果；审核下标或格式不合法时只纠正一次审核，不重复整理，仍不合法则不写入。
- 萌萌画图与 AI 封面共用 `qwen-image-3.0-pro`，由 `cover_model` 配置，修改后重启 AI 服务。
- `-SelectMouthModels` 使用同一批虚构语料，对照 `-Baseline` 的上次完整报告，统计口癖目标、颜文字比例、连续近似回复信号、无工具首个气泡 P50，以及 agent/judge 输出 token 和预生成采用率。近似回复只是文本信号，重复话题仍需结合长对话原文判断。
- 延迟目标为无工具首个气泡 P50 ≤ 3 秒；口癖出现率不超过档位目标，颜文字出现率大于 0。真实评测沿用固定授权累计用量，串行执行，不降低资源保护阈值。
- 离线回归入口：`./verification/Test-Ai.ps1`、`./verification/Test-Companion.ps1`、`./verification/Test-Backend.ps1`、`./verification/Test-Secrets.ps1`。浏览器里的实际聊天体验由仓库主人验收。

# 萌部落社区 · 认证模块

> 2026-10-08 首版；2026-10-09 增加手机号注册（多地区、加密存储、阿里云短信）。标 ⚠ 的条目依赖尚未确认的决定，见文末。

## 1. 范围

- **本期**：滑块验证、邮箱验证码、短信验证码、注册（邮箱或手机号二选一）、登录、登出、当前用户、改密码、管理员审核注册。
- **暂缓**：Cloudflare、浏览器指纹、找回密码、封禁、第三方登录。

## 2. 整体方案

- **JWT 只当会话钥匙。** 载荷只放 userId 和 sessionId。有效期由 Redis 的 TTL 控制并滑动续期，
  不设 refresh token。审核、踢下线因此能即时生效。
- **只在网关验一次。** 下游服务不解析 JWT，也不查会话，只读网关注入的请求头。
- **会话只放身份。** Redis 会话里是 userId、角色、状态。昵称和头像不放进会话，
  `/user/me` 读 user 服务自己的缓存。
- **允许多设备同时登录。** 每次登录生成一个新会话，互不影响。

## 3. 接口

均在 user 服务。

| 接口 | 用途 | 登录要求 |
|---|---|---|
| `POST /user/captcha` | 生成 tianai 滑块 | 否 |
| `POST /user/captcha/verification` | 校验滑块，返回一次性票据 | 否 |
| `POST /user/email-codes` | 发邮箱验证码，需票据 | 否 |
| `POST /user/sms-codes` | 发短信验证码，需票据 | 否 |
| `POST /user/registrations` | 注册（邮箱或手机号二选一），进入待审核 | 否 |
| `POST /user/sessions` | 登录 | 否 |
| `DELETE /user/sessions/current` | 登出 | 是 |
| `GET /user/me` | 当前用户信息 | 是 |
| `PUT /user/me/password` | 改密码，踢掉该用户所有会话 | 是 |
| `GET /user/admin/registrations` | 分页查注册申请，可按状态筛 | 管理员 |
| `POST /user/admin/registrations/{userId}/approval` | 通过 | 管理员 |
| `POST /user/admin/registrations/{userId}/rejection` | 拒绝 | 管理员 |

注册请求带用户名、密码，以及邮箱或手机号其中一个和它对应的验证码。注册时不填昵称。
手机号分成地区区号和本地号码两部分提交，区号必须在允许名单内（见 4.1 节）。发短信验证码的请求同理。

## 4. 数据表

库 `meng_user`，本期只有一张 `user`。

| 字段 | 说明 |
|---|---|
| `id` | BIGINT 自增主键 |
| `username` | 唯一索引，入库前去空格转小写 |
| `email` | 可空，唯一索引，入库前转小写 ⚠ |
| `phone_cipher` | 可空。手机号密文，不存明文 |
| `phone_hash` | 可空，唯一索引。手机号的带密钥哈希，用于查重和按手机号查找 |
| `password_hash` | BCrypt，用 Hutool 自带实现 |
| `nickname`、`avatar` | 展示资料 |
| `role` | 枚举：普通用户 / 管理员 |
| `status` | 枚举：待审核 / 正常 / 已拒绝 |
| `level` | 展示用，由 growth 的事件同步 |
| `create_time`、`update_time`、`delete_state` | 通用字段 |

- 邮箱和手机号注册时二选一，至少有一个不为空，由 Service 校验。
- 首个管理员由初始化脚本写入，不能通过注册产生。
- 注意：有唯一索引的表做逻辑删除时，被删除的记录仍占着用户名、邮箱和手机号。建表时要处理这一点。

### 4.1 手机号

- **地区**：首批允许台湾 +886（默认）、香港 +852、澳门 +853、中国大陆 +86、日本 +81、新加坡 +65、马来西亚 +60、美国和加拿大 +1 ⚠。
  名单和各地区的号码格式放 Nacos 配置，由后端校验；前端下拉列表用同一份名单的常量。
- **归一化**：去掉空格和分隔符，去掉本地号码开头的 0，拼成带区号的统一格式（如 `+886912345678`）。
  哈希和加密都对这个统一格式做，同一个号码的不同写法才会被判为同一个。
- **不存明文**：
  - `phone_cipher`：AES-256-GCM 加密，每条记录随机 IV，密文带密钥版本前缀（如 `v1:`）。发审核结果短信、给管理员看脱敏号码时才解密。
  - `phone_hash`：HMAC-SHA256，密钥与加密密钥分开。查重和按手机号查找只用这一列。
- **密钥**：加密密钥和哈希密钥只来自环境变量，不进仓库、不进 Nacos、不进日志。
  - 换加密密钥：新数据用新版本，旧数据靠版本前缀仍能解密。丢掉旧密钥等于永久丢失所有手机号。
  - 换哈希密钥：必须停写、逐条解密重算，否则查重失效。两者都按事故流程处理。
- **展示**：接口和管理端只返回脱敏号码（保留区号和末三位）。日志里不出现手机号，脱敏的也尽量不打。
- **Redis**：键里不放手机号明文，用 `phone_hash`。

## 5. Redis 键

| 键 | 内容 | 有效期 |
|---|---|---|
| `session:{sessionId}` | userId、角色、状态 | 7 天，滑动续期 |
| `user-sessions:{userId}` | 该用户的全部 sessionId | 随会话 |
| `captcha-ticket:{ticket}` | 滑块通过凭证，校验即删 | 2 分钟 |
| `email-code:{email}` | 验证码和已错次数 | 5 分钟 |
| `sms-code:{phoneHash}` | 验证码和已错次数 | 5 分钟 |
| `limit:*` | 各类限流计数 | 见第 7 节 |

实际键名加项目前缀。

## 6. 验证码

三道防线，各挡一类攻击，缺一道就有一条完整的绕过路径：

1. **滑块**（tianai）：挡机器。
2. **一次性票据**：滑块通过后签发，两分钟有效，校验后立即销毁。挡绕过界面直接调接口。
3. **限流**：挡拿到合法票据之后的滥用。

使用场景：发邮箱验证码、发短信验证码、注册、登录失败两次之后。

### 6.1 发送通道

- **短信**：阿里云短信。AccessKey 来自环境变量，签名和模板编号放 Nacos 配置。
  台湾、香港、澳门和其他境外号码走「国际/港澳台短信」，需要单独开通，模板也和国内短信分开申请。
- **邮件**：Spring Boot 的邮件 starter（JavaMailSender），经 SMTP 发送。SMTP 账号来自环境变量。
- 两个通道都只在 user 服务内部使用，调用放在 `client` 包，发送经 MQ 异步执行。
- 通道调用失败要有明确语义：验证码发不出去就让接口失败，不能返回成功让用户空等。

## 7. 限流

本期按 IP 和账号两个维度，阈值放 Nacos 配置。

| 场景 | 规则 |
|---|---|
| 发邮箱验证码 | 同邮箱 60 秒一次，30 分钟最多 10 次 |
| 发短信验证码 | 同手机号 60 秒一次，30 分钟最多 10 次；同 IP 每天最多 20 次 |
| 注册 | 同 IP 每天最多 3 个 |
| 登录失败 | 同账号连错 5 次锁 15 分钟 |
| 邮箱验证码、短信验证码校验 | 错 5 次作废 |

这个审核模型最大的滥用点是机器人批量注册、刷爆审核队列。
所以邮箱或手机号验证通过后才进入待审核，并限制每 IP 的每日注册数。

短信按条计费，发短信接口是最容易被刷的点，所以比邮箱多一层 IP 维度的日上限。

## 8. 网关职责

1. 清掉外部传入的 `X-User-Id`、`X-User-Role`，白名单接口也要清。
2. 拦截所有 `/**/internal/**`。
3. 白名单接口直接放行。
4. 公开读接口：带了 token 就解析并注入身份，没带也放行。
5. 其余接口：验签、查 Redis 会话、续期、注入身份头；失败返回 401。
6. `/**/admin/**` 要求管理员角色，否则 403。

下游：

- `meng-common-web` 的拦截器把身份头放进 ThreadLocal，请求结束必须清理。
- Service 层对管理操作再校验一次角色。
- MQ 消费线程和异步线程里没有 ThreadLocal，userId 要显式传参。
- 业务服务端口不对外暴露。

## 9. 状态流转

```
注册成功 ──► 待审核 ──通过──► 正常
                │
                └──拒绝──► 已拒绝
```

- 通过：状态改为正常，事务提交后发 `user.approved` 事件，并发通知。
- 拒绝：状态改为已拒绝，发通知，不发事件。
- 通知走注册时用的那个渠道：邮箱注册发邮件，手机号注册发短信。
- 通过和拒绝只允许从「待审核」出发，重复操作返回 409。
- 登录时密码校验通过后才返回「审核中」或「已拒绝」，否则一律「账号或密码错误」，防止探测账号是否存在。
- 邮件和短信在 user 服务内部经 MQ 异步发送，不放在请求线程里。

## 10. 错误语义

| 情况 | HTTP 状态 |
|---|---|
| 参数不合法、票据或验证码错误 | 400 |
| 未登录、会话过期、账号或密码错误 | 401 |
| 密码正确但待审核或已拒绝；非管理员访问管理接口 | 403，带各自的业务码 |
| 用户名、邮箱或手机号已占用；重复审核 | 409 |
| 触发限流 | 429 |

## 11. 验收点

- 邮箱注册和手机号注册都能走通，审核结果按各自的渠道通知。
- 邮箱和手机号都不填，或验证码与所填的联系方式不匹配，注册被拒。
- 同一个手机号换一种写法（加空格、开头带 0）再注册，被判为已占用。
- 数据库和 Redis 里搜不到任何手机号明文；接口返回的手机号都是脱敏的。
- 区号不在允许名单内的请求被拒。
- 待审核账号密码正确也登不进；通过后立即能登。
- 伪造 `X-User-Id` 请求白名单接口和普通接口，下游都拿不到伪造值。
- 同一张滑块票据用第二次被拒。
- 改密码后该用户的旧会话全部失效。
- 两台设备同时登录互不影响，其中一台登出不影响另一台。
- 外部访问 `/user/internal/**`（含叠前缀的变体）被拦。
- 各项限流到阈值后返回 429。

## 12. 待确认

| 项 | 当前倾向 | 影响 |
|---|---|---|
| Token 存放位置 ⚠ | HttpOnly Cookie，`SameSite=Lax`，写操作校验 `Origin` | 改成 localStorage 的话，网关改读 `Authorization` 头，WebSocket 另需一次性票据 |
| 被拒绝的人能否重新申请 | 能，把同一条记录改回待审核 | 决定状态机是否多一条「已拒绝 → 待审核」 |
| 是否加「申请理由」「拒绝原因」字段 | 未讨论 | 决定 `user` 表字段和审核接口入参 |
| 邮箱是否加密存储 ⚠ | 和手机号用同一套方案加密（原倾向是明文，手机号定为加密后调整） | 加密的话 `email` 拆成 `email_cipher` 和 `email_hash`；建表前必须定 |
| 手机号地区名单 ⚠ | 4.1 节的八个地区，默认台湾 | 每加一个地区要确认阿里云能送达，并补一条号码格式规则 |
| 短信限流的 IP 日上限 | 20 次 | 只是配置值，上线后按实际用量调 |
| 邮件发信账号 | 用现有的 SMTP 账号 | 发信量上限和进垃圾箱的概率取决于这个账号的服务商；量大了再考虑自有域名配 SPF、DKIM |

待核实：

- tianai 行为验证码对 Spring Boot 4 的兼容性。
- 阿里云账号属于中国站还是国际站。两个站点的短信接口和开通流程不同，决定用哪个接口。
- 阿里云国际/港澳台短信对通知类内容（审核结果）的限制。发不了的地区只发验证码，审核结果让用户登录时看。

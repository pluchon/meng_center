# 萌部落社区 · 认证模块

> 2026-10-08 首版。2026-10-09 增加手机号注册、邮箱和手机号加密、申请理由与重新申请、协议同意记录，并把此前的待确认项定了下来。
> 剩下的几个配置值和待核实项见文末。

## 1. 范围

- **本期**：滑块验证、邮箱验证码、短信验证码、注册（邮箱或手机号二选一）、被拒绝后重新申请、登录、登出、当前用户、改密码、找回密码、管理员审核注册。
- **个人中心**：改昵称、签名、头像、用户名，换或绑定邮箱和手机号，设备管理。见第 13 节。
- **暂缓**：Cloudflare、浏览器指纹、封禁、第三方登录、注销账号。

## 2. 整体方案

- **JWT 只当会话钥匙。** 载荷只放 userId 和 sessionId。有效期由 Redis 的 TTL 控制并滑动续期，
  不设 refresh token。审核、踢下线因此能即时生效。
- **Token 放 HttpOnly Cookie。** `SameSite=Lax`，写操作校验 `Origin`；前端和网关同域部署。
  脚本读不到 Token，WebSocket 握手时自动带上。
- **只在网关验一次。** 下游服务不解析 JWT，也不查会话，只读网关注入的请求头。
- **会话只放身份。** Redis 会话里是 userId、角色、状态，另带设备管理用的几项展示信息（见 13.5 节）。昵称和头像不放进会话，
  `/user/me` 读 user 服务自己的缓存。
- **允许多设备同时登录。** 每次登录生成一个新会话，互不影响。

均在 user 服务。

|---|---|---|
| `POST /user/captcha` | 生成 tianai 滑块 | 否 |
| `POST /user/captcha/verification` | 校验滑块，返回一次性票据 | 否 |
| `POST /user/email-codes` | 发邮箱验证码，需票据 | 否 |
| `POST /user/sms-codes` | 发短信验证码，需票据 | 否 |

| `POST /user/registrations` | 注册（邮箱或手机号二选一），进入待审核 | 否 |
| `POST /user/registrations/reapplication` | 被拒绝后重新申请，回到待审核 | 否，凭用户名和密码 |
| `POST /user/sessions` | 登录 | 否 |
| `DELETE /user/sessions/current` | 登出 | 是 |
| `GET /user/me` | 当前用户信息 | 是 |
| `PUT /user/me/password` | 改密码，踢掉该用户所有会话 | 是 |
| `PUT /user/me/profile` | 改昵称、签名、用户名 | 是 |
| `POST /user/me/avatar` | 上传并换头像，返回头像地址 | 是 |
| `GET /user/avatars/{name}` | 读头像文件 | 是 |
| `POST /user/me/contact-codes` | 给新邮箱或新手机号发换绑验证码，需票据 | 是 |
| `PUT /user/me/email` | 更换或绑定邮箱 | 是 |
| `PUT /user/me/phone` | 更换或绑定手机号 | 是 |
| `GET /user/me/sessions` | 我的登录设备 | 是 |
| `DELETE /user/me/sessions/{deviceId}` | 让一台设备下线 | 是 |
| `DELETE /user/me/sessions/others` | 让其他设备全部下线 | 是 |
| `GET /user/admin/registrations` | 分页查注册申请，可按状态筛 | 管理员 |
| `POST /user/admin/registrations/{userId}/approval` | 通过 | 管理员 |
| `POST /user/admin/registrations/{userId}/rejection` | 拒绝，必须填拒绝原因 | 管理员 |

- 注册和重置密码为 8～20 位 ASCII 字母和数字，必须同时包含字母与数字；已有账号登录及管理员初始化不套用新注册规则。
- 注册请求带用户名、密码、申请理由，以及邮箱或手机号其中一个和它对应的验证码。注册时不填昵称。
- 注册必须勾选同意用户协议和隐私政策。请求里带上用户看到的两个版本号；当前生效的版本号放 Nacos 配置，
  两者不一致就拒绝，前端提示重新阅读。
- 手机号分成地区区号和本地号码两部分提交，区号必须在允许名单内（见 4.1 节）。发短信验证码的请求同理。
- 重新申请的请求带用户名、密码和新的申请理由，需要滑块票据。
- 登录时账号处于已拒绝，响应里带上拒绝原因，前端据此给出重新申请的入口。
- 管理端的申请列表返回申请理由和脱敏后的联系方式。

### 3.1 找回密码

登录勾选行最右侧进入 `/reset-password`，使用注册时的联系方式。发送与提交分别消耗新的滑块票据，发送沿用联系方式冷却与限流。重置码使用独立 Redis 前缀，注册码不能用于重置，重置码校验后即销毁。提交按联系方式限流，次数与窗口复用 `verification.maxErrors` / `codeTtl`。

发码不查询账号是否存在，避免通过发送响应枚举账号。无效验证码、不存在的账号、管理员账号均返回同一 `USER_RESET_FAILED`；管理员密码由已有管理流程处理。重置锁定账号记录，更新 BCrypt 哈希，清除登录失败计数并撤销所有会话。原待审核、已拒绝状态保留，找回密码不会通过审核。

## 4. 数据表

库 `meng_user`，本期只有一张 `user`。

| 字段 | 说明 |
|---|---|
| `id` | BIGINT 自增主键 |
| `username` | 唯一索引，入库前去空格转小写 |
| `email_cipher` | 可空。邮箱密文，不存明文 |
| `email_hash` | 可空，唯一索引。邮箱的带密钥哈希，用于查重和按邮箱查找 |
| `phone_cipher` | 可空。手机号密文，不存明文 |
| `phone_hash` | 可空，唯一索引。手机号的带密钥哈希，用于查重和按手机号查找 |
| `password_hash` | BCrypt，用 Hutool 自带实现 |
| `nickname`、`avatar` | 展示资料，注册时不填。`avatar` 存头像文件名 |
| `bio` | 可空。签名，最多 50 个字 |
| `username_update_time` | 可空。上次改用户名的时间 |
| `role` | 枚举：普通用户 / 管理员 |
| `status` | 枚举：待审核 / 正常 / 已拒绝 |
| `apply_reason` | 可空。申请理由，注册或重新申请时由用户填，最多 100 字 |
| `reject_reason` | 可空。拒绝原因，管理员拒绝时填，重新申请时清空 |
| `terms_version` | 可空。同意的用户协议版本 |
| `privacy_version` | 可空。同意的隐私政策版本 |
| `agreed_time` | 可空。同意的时间，以服务端收到请求的时间为准，不信任前端传的时间 |
| `level` | 展示用，由 growth 的事件同步 |
| `create_time`、`update_time`、`delete_state` | 通用字段 |

内部作者资料查询只返回展示字段；昵称为空或空白时返回用户名。`growth.level-changed` 消费者仅在新等级大于当前等级时更新，重复和迟到事件不会降级。

- 邮箱和手机号注册时二选一，之后可以在个人中心补上另一个。两个可以同时有，任何时候至少有一个不为空，由 Service 校验。
- 首个管理员由初始化脚本写入，不能通过注册产生。它不留邮箱和手机号（二选一只约束注册），密码明文不进仓库。
- 协议同意的三列只记最近一次同意，不留历史。协议更新后要求老用户重新同意的功能本期不做，做的时候覆盖这三列。
- 本期没有删除用户的入口，唯一索引直接建在列上。被逻辑删除的记录会继续占着用户名和联系方式，做注销功能时再定怎么释放。

### 4.1 邮箱和手机号

- **手机号地区**：首批允许台湾 +886（默认）、香港 +852、澳门 +853、中国大陆 +86、日本 +81、新加坡 +65、马来西亚 +60、美国和加拿大 +1。
  名单和各地区的号码格式放 Nacos 配置，由后端校验；前端下拉列表用同一份名单的常量。
- **归一化**：
  - 邮箱：去首尾空格，转小写。
  - 手机号：去掉空格和分隔符，去掉本地号码开头的 0，拼成带区号的统一格式（如 `+886912345678`）。
  - 哈希和加密都对归一化后的值做，同一个邮箱或号码的不同写法才会被判为同一个。
- **不存明文**：
  - `email_cipher`、`phone_cipher`：AES-256-GCM 加密，每条记录随机 IV，密文带密钥版本前缀（如 `v1:`）。
    只在发通知、给管理员看脱敏值时解密。
  - `email_hash`、`phone_hash`：HMAC-SHA256，密钥与加密密钥分开。查重和查找只用这两列。
- **密钥**：加密密钥和哈希密钥只来自环境变量，不进仓库、不进 Nacos、不进日志。
  - 换加密密钥：新数据用新版本，旧数据靠版本前缀仍能解密。丢掉旧密钥等于永久丢失所有邮箱和手机号。
  - 换哈希密钥：必须停写、逐条解密重算，否则查重失效。
  - 两者都按事故流程处理。
- **展示**：接口和管理端只返回脱敏值。邮箱保留首字符和域名，手机号保留区号和末三位。
  日志里不出现邮箱和手机号，脱敏的也尽量不打。
- **Redis**：键里不放明文，用对应的哈希值。

## 6. 验证码

三道防线，各挡一类攻击，缺一道就有一条完整的绕过路径：

1. **滑块**（tianai）：挡机器。
2. **一次性票据**：滑块通过后签发，两分钟有效，校验后立即销毁。挡绕过界面直接调接口。
3. **限流**：挡拿到合法票据之后的滥用。

使用场景：每次登录、发邮箱验证码、发短信验证码、注册、重新申请、重置密码的发码和提交、换绑邮箱或手机号的发码。用户端和管理端的登录走同一个接口，都要过滑块。

只启用滑块一种类型，其他类型没有注册模板，生成不出来。背景图是自有的五张，裁成 600×360 放在 `meng-user` 的 `resources/captcha/`。

判定分两层，都用 tianai 自带的校验器：

- 位置：拼图停下的位置与缺口的偏差不超过背景宽度的 2%。
- 轨迹：滑动不到 0.3 秒、轨迹点少于 10 个、起点不在原点附近、相邻两点跳动超过 50 像素，都判为不通过。

轨迹检测只是基础规则，挡的是直接调接口和瞬间拖到位的脚本，不能替代票据和限流。

### 6.1 发送通道

- **短信**：国内号码使用 `SendSms`，签名和模板编号放 Nacos；台湾、香港、澳门及其他境外号码使用 `SendMessageToGlobe`，发送方和正文放 Nacos。AccessKey 只读环境变量。
  国际短信需要单独开通，不套用国内签名和模板。通道选择按完整区号匹配，`+886` 不归入 `+86`。
  该接口调整已由仓库主人确认，依据[阿里云短信 API 使用说明](https://help.aliyun.com/zh/sms/getting-started/use-sms-api/)及[国际短信发送说明](https://help.aliyun.com/zh/sms/user-guide/send-message-intl)。
- **邮件**：Spring Boot 的邮件 starter（JavaMailSender），经 SMTP 发送。SMTP 账号来自环境变量。
- 两个通道都只在 user 服务内部使用，调用放在 `client` 包，发送经 MQ 异步执行。
- 通道调用失败要有明确语义：验证码发不出去就让接口失败，不能返回成功让用户空等。
- 发验证码时请求线程等消费者的回执，等待上限是 `meng.user.notification.rpc-timeout`。
  发送指令的过期时间取同一个值：请求方超时放弃后，消费者再拿到这条指令就不发了，
  避免用户收到一个没有入库、用不了的验证码。收到成功回执后才保存验证码。

## 7. 限流

本期按 IP 和账号两个维度，阈值放 Nacos 配置。

| 场景 | 规则 |
|---|---|
| 发邮箱验证码 | 同邮箱 60 秒一次，30 分钟最多 10 次 |
| 发短信验证码 | 同手机号 60 秒一次，30 分钟最多 10 次；同 IP 每天最多 20 次 |
| 注册 | 同 IP 每天最多 3 个 |
| 重新申请 | 同账号每天最多 1 次 |
| 登录失败 | 同账号连错 5 次锁 15 分钟 |
| 邮箱验证码、短信验证码校验 | 错 5 次作废 |
| 发换绑验证码 | 沿用同邮箱、同手机号的规则；同账号每天最多 10 次 |
| 改资料 | 同账号每分钟最多 10 次 |
| 换头像 | 同账号每天最多 10 次 |

这个审核模型最大的滥用点是机器人批量注册、刷爆审核队列。
所以邮箱或手机号验证通过后才进入待审核，并限制每 IP 的每日注册数。
重新申请同样会把记录送回审核队列，所以也限频。

短信按条计费，发短信接口是最容易被刷的点，所以比邮箱多一层 IP 维度的日上限。

## 8. 网关职责

1. 清掉外部传入的 `X-User-Id`、`X-User-Role`，白名单接口也要清。
2. 拦截所有 `/**/internal/**`。
3. 白名单接口直接放行。
4. 公开读接口：带了 token 就解析并注入身份，没带也放行。
5. 其余接口：验签、查 Redis 会话、续期、注入身份头；失败返回 401。续期时如果会话里的最近活跃时间已经过了 5 分钟，顺手更新它。
6. `/**/admin/**` 要求管理员角色，否则 403。

Token 从 Cookie 里读。非 GET 请求校验 `Origin`，不在允许名单内的返回 403。

下游：

- `meng-common-web` 的拦截器把身份头放进 ThreadLocal，请求结束必须清理。
- Service 层对管理操作再校验一次角色。
- MQ 消费线程和异步线程里没有 ThreadLocal，userId 要显式传参。
- 业务服务端口不对外暴露。

## 9. 状态流转

```
注册成功 ──► 待审核 ──通过──► 正常
              │  ▲
          拒绝 │  │ 重新申请
              ▼  │
             已拒绝
```

- 通过：状态改为正常，事务提交后发 `user.approved` 事件，并发通知。
- 拒绝：必须填拒绝原因。状态改为已拒绝，发通知并带上原因，不发事件。
- 重新申请：先校验用户名和密码。更新申请理由，清空拒绝原因，状态改回待审核。不发事件，不发通知。
- 通过和拒绝只允许从「待审核」出发，重新申请只允许从「已拒绝」出发。从别的状态发起返回 409。
- 通知走注册时用的那个渠道：邮箱注册发邮件，手机号注册发短信。
- 登录时密码校验通过后才返回「审核中」或「已拒绝」，否则一律「账号或密码错误」，防止探测账号是否存在。
  已拒绝时一并返回拒绝原因。
- 邮件和短信在 user 服务内部经 MQ 异步发送，不放在请求线程里。

## 10. 错误语义

| 情况 | HTTP 状态 |
|---|---|
| 参数不合法、票据或验证码错误、区号不在名单内、没有同意协议 | 400 |
| 未登录、会话过期、账号或密码错误 | 401 |
| 密码正确但待审核或已拒绝；非管理员访问管理接口；`Origin` 不合法 | 403，带各自的业务码 |
| 换绑或改密码时当前密码错误（`USER_PASSWORD_WRONG`）；用设备管理接口下线当前这台 | 400 |
| 设备编号不属于自己 | 404 |
| 用户名、邮箱或手机号已占用；重复审核；状态不对时重新申请；提交的协议版本不是当前版本 | 409 |
| 30 天内改过用户名（`USER_USERNAME_COOLDOWN`）；换绑的邮箱或手机号已被占用（`USER_CONTACT_TAKEN`） | 409 |
| 触发限流 | 429 |

## 11. 验收点

注册与审核：

- 邮箱注册和手机号注册都能走通，审核结果按各自的渠道通知。
- 邮箱和手机号都不填，或验证码与所填的联系方式不匹配，注册被拒。
- 没带协议版本号，或带的不是当前版本，注册被拒；注册成功后库里记下了两个版本号和同意时间。
- 同一个手机号换一种写法（加空格、开头带 0）再注册，被判为已占用。邮箱换大小写同理。
- 区号不在允许名单内的请求被拒。
- 管理员拒绝时不填原因，请求被拒。
- 被拒绝的账号登录时能看到拒绝原因；重新申请后回到待审核，在管理端列表里重新出现。
- 待审核和正常状态的账号发起重新申请，返回 409。
- 待审核账号密码正确也登不进；通过后立即能登。

数据保护：

- 数据库和 Redis 里搜不到任何邮箱和手机号的明文。
- 接口返回的邮箱和手机号都是脱敏的。

会话与网关：

- 伪造 `X-User-Id` 请求白名单接口和普通接口，下游都拿不到伪造值。
- 外部访问 `/user/internal/**`（含叠前缀的变体）被拦。
- 浏览器脚本读不到 Token；换一个 `Origin` 发写请求被拒。
- 同一张滑块票据用第二次被拒。
- 登录不带滑块票据被拒；瞬间到位或过快的滑动轨迹拿不到票据。
- 改密码后该用户的旧会话全部失效。
- 两台设备同时登录互不影响，其中一台登出不影响另一台。
- 各项限流到阈值后返回 429。

## 12. 配置值与待核实

| 项 | 当前取值 | 说明 |

| 申请理由是否必填 | 选填，最多 100 字 | 改成必填只动校验和注册页 |

  发不了的情况下只发验证码，审核结果让用户登录时看。

## 13. 个人中心

设计稿是 `Profile.dc.html`，路由 `/account`，从导航最右的头像进入。只有自己的个人中心，没有别人的个人主页；「我发布的帖子」在创作中心，这里不重复。

### 13.1 归属

| 内容 | 归属 | 说明 |
|---|---|---|
| 昵称、签名、头像、用户名、邮箱、手机号、密码、登录设备 | user | 本节 |
| 收藏夹、我喜欢的 | content | 见 [content.md](content.md) 第 18 节 |
| 屏蔽名单 | im | 见 [im.md](im.md) 第 3 节的 `GET /im/blocks` |

页面分别调三个服务，哪一块失败就在哪一块显示错误态，互不拖累。

### 13.2 资料

`GET /user/me` 返回：id、用户名、昵称、签名、头像地址、等级、角色、状态、脱敏的邮箱和手机号（没有的为空）、注册时间、下一次可以改用户名的时间（没改过为空）。

`PUT /user/me/profile` 一次提交昵称、签名、用户名三项，没变的原样带回来。

| 项 | 规则 |
|---|---|
| 昵称 | 去首尾空格后 2～16 个字，可以和别人重名。可以清空，清空后各处显示用户名 |
| 签名 | 最多 50 个字，可以为空；去首尾空格，不允许换行 |
| 用户名 | 和注册时一样：3～32 位字母、数字、下划线，入库前转小写，全站唯一 |

用户名注册后可以改：

- 30 天内只能改一次，按 `username_update_time` 算。没到时间返回 409 `USER_USERNAME_COOLDOWN`，并带上可以改的时间。
- 改完旧用户名立刻放出来，别人可以注册或改成它。
- 不用重新登录：会话里只有用户 id。下次登录用新用户名。
- 被别人占用返回 409，和注册时是同一个业务码。
- 三项在一个事务里更新。用户名没过冷却期或被占用时整个请求失败，昵称和签名也不保存。
- user 自己的资料直接读库，不缓存。别的服务的昵称和头像都是按页现查，不用通知，也不发事件。

### 13.3 头像

- `POST /user/me/avatar`，表单上传一个文件。只接受 JPEG、PNG、WebP，按文件头判断，不信扩展名；不超过 2 MB。
- 保存前居中裁成正方形、缩到 256 像素、重新编码成 WebP，元数据随之去掉。文件名随机生成，存在 user 自己的磁盘目录，目录放配置。
- 上传成功就直接生效，不用再点保存。旧文件在事务提交后删除。
- `GET /user/avatars/{name}` 读文件，需要登录。文件名不会重复使用，响应带长期缓存头。
- `GET /user/internal/users` 返回的头像就是这个地址；没有头像时为空，前端显示默认头像。
- 解码时先降采样，头像写入 `MENG_USER_AVATAR_ROOT` 指定的仓库外目录，user 不调 content。

### 13.4 邮箱和手机号

- 注册时二选一，之后可以在这里补上另一个。两个可以同时有，任何时候至少有一个。
- 每一项只有一种操作：已经有就是「更换」，没有就是「绑定」。本期不做解绑。
- 步骤：过滑块拿票据，`POST /user/me/contact-codes` 给新邮箱或新手机号发验证码，再用 `PUT /user/me/email` 或 `PUT /user/me/phone` 提交新的联系方式、验证码和当前密码。
- 不验证旧的联系方式。旧邮箱丢了也要能换，所以用当前密码确认是本人。
- 换绑验证码用独立的 Redis 前缀，注册码和重置码不能拿来换绑，校验后立即销毁。发码沿用同邮箱、同手机号的冷却和限流。
- 发码不透露这个邮箱或手机号有没有人在用；提交时已被占用返回 409 `USER_CONTACT_TAKEN`。
- 手机号照旧分成区号和本地号码提交，区号必须在允许名单内。归一化、加密、哈希的规则见 4.1 节。
- 成功后旧的联系方式立即失效，可以被别人使用。旧的是邮箱时给旧邮箱发一封提醒邮件。不撤销会话。
- 找回密码时两个联系方式都能用。个人中心迁移移除了只允许一种联系方式的数据库约束，保留密文与哈希成对、联系方式唯一的约束。
- 当前密码错误返回 400 `USER_PASSWORD_WRONG`，和登录失败共用一个计数，连错 5 次锁 15 分钟。

### 13.5 设备管理

每次登录生成一个会话，也就是一台「设备」。会话里除了身份，再存五项只用于展示的信息：

| 项 | 来源 |
|---|---|
| 设备编号 | 登录时随机生成，和会话 id 无关。接口里只出现它，不出现会话 id |
| 设备名 | 登录时从 `User-Agent` 解析成「系统 · 浏览器」，认不出来就是「未知设备」 |
| 属地 | 登录时的 IP 用 ip2region 解析，精度和帖子的属地一致，解析不出来为空 |
| 登录时间 | 登录时记下 |
| 最近活跃时间 | 网关续期时更新，5 分钟内最多写一次 |

- `GET /user/me/sessions`：当前这台排第一并带标记，其余按最近活跃时间倒序。不分页。
- `DELETE /user/me/sessions/{deviceId}`：删掉那个会话，那台设备下一次请求就是 401。不能用它下线当前这台（400），当前这台走登出。
- `DELETE /user/me/sessions/others`：除当前这台之外全部删除。
- 只能操作自己的会话，设备编号不属于自己时返回 404。
- 这个功能上线之前建立的会话没有这五项。列出时给它补一个设备编号，设备名显示「未知设备」，照样可以下线。
- ip2region 的查询封装和数据文件从 content 挪到公共模块，两个服务共用一份。user 不调 content。
- 改密码仍然踢掉全部会话，包括当前这台。

### 13.6 页面

一张随横屏视口按比例展开的大卡片（宽约为视口的 7/9，最大 1480px），共用社区导航，导航上的头像是当前页，不显示底栏。常见横屏窗口里卡片高度随窗口收紧，最大 850px，底部操作完整可见；手机按内容自然展开。卡片四周是一组装饰（胶带、颜文字贴纸、星星）。

**资料区**（卡片上半）：

- 大头像，右下角一个相机按钮，点了直接选图换头像。
- 昵称、等级标签（点了去成长页）、签名。这里不显示用户名。
- 右侧三张倾斜的贴纸：来到部落多少天、收藏多少篇、喜欢多少篇，悬停时扶正。
- 一条竖虚线之后是「设置」按钮；进了设置页，同一个位置变成「返回」。

资料区下面一条横虚线，再下面是收藏、喜欢、设置三个面板之一，默认是收藏。

**收藏**分两层：

- 第一层是收藏夹列表。标题「我的收藏」，旁边是「3 / 20 个收藏夹」，右侧是收藏和喜欢的切换条。一行四张卡片，每张是封面、名字、篇数、最近一次收藏的日期；默认收藏夹右上角贴「默认」标签；没满 20 个时最后一张是虚线的「新建收藏夹」。往下滑分批加载，不翻页。
- 点进一个收藏夹是第二层，标题和切换条那一行不再显示。第一行是返回键、收藏夹名、改名的铅笔，右侧是「删除收藏夹」和「共 N 篇」；中间是两列的帖子列表，按横屏高度每页显示 2/4/6/8 条，改变页容量时回到第一页；最下面一行左边是简介和改简介的铅笔，右边是翻页器。名称和简介点击各自铅笔后原地编辑，铅笔右侧出现确认勾号；点击勾号或按 Enter 保存该字段，Esc 放弃当前字段修改，离开输入框不自动保存。保存失败保留草稿，提交期间禁止重复保存；保存成功同步收藏夹展示和收藏选择缓存。默认收藏夹不显示编辑控件和删除按钮。
- 帖子行：封面小图、标题、分类贴纸、作者小胶囊、「收藏于 某时」，最右是星星。没有封面的帖子使用对应分类配色的插画占位封面。
- 点星星是把这篇帖子从当前收藏夹拿走（它在别的收藏夹里的收藏不受影响），这一行留在原地，星星变空心，再点一下放回。离开再进来或刷新后，已拿走的才不再出现。
- 新建收藏夹是一个弹窗：从上到下是封面（可不选）、名字、简介、取消和创建，结构和收藏夹卡片一致。

**喜欢**：标题「我喜欢的」和切换条，下面是同样的两列帖子列表和翻页器，只有颜色换成粉色，最右是爱心，时间写「喜欢于 某时」。取消喜欢后的行为和取消收藏一样。

**设置**：八项排成两列，左列是昵称、签名、密码、设备管理，右列是用户名、邮箱、手机号、屏蔽名单。两列各排各的，底边不要求对齐，下面留白给以后加的项。

- 每项是一张带颜色和小图标的卡片，八张颜色各不相同。
- 昵称、签名、用户名是输入框，字数显示在框内：昵称和用户名在最右侧，签名在右下角。用户名的上限按 13.2 的规则取 32。用户名还在冷却期时输入框置灰，悬停提示写明哪天可以改。
- 密码、设备管理、邮箱、手机号、屏蔽名单右侧是一个按钮，点了开弹窗。邮箱和手机号显示脱敏值，没有时显示「还没有绑定」，按钮相应是「修改」或「绑定」。
- 最底下隔一条虚线，左边「退出登录」，右边「保存资料」。保存的是昵称、签名、用户名三项，没有改动时按钮置灰。

五个弹窗样式一致：标题是图标块加倾斜标签，右上角关闭，底部是取消和确认。

| 弹窗 | 内容 |
|---|---|
| 修改密码 | 当前密码、新密码、再输一次；说明密码规则和改完后所有设备要重新登录 |
| 更换邮箱（绑定邮箱） | 现在的邮箱（脱敏）、新邮箱、验证码和发送按钮、当前密码 |
| 更换手机号（绑定手机号） | 地区下拉和号码、验证码和发送按钮、当前密码 |
| 设备管理 | 每台设备一行：设备名、属地、最近活跃时间；当前这台贴「这台设备」，其余有「下线」；底部左边「其他设备全部下线」 |
| 屏蔽名单 | 每人一行：头像、昵称、屏蔽日期、「取消屏蔽」 |

- 发送验证码前先弹滑块；发送后按钮进入 60 秒倒计时。
- 删除收藏夹、下线一台设备、其他设备全部下线、退出登录都要二次确认，提交期间按钮禁用。
- 页面的四种状态（加载中、出错、未登录、空）各面板都要有。没有收藏和没有喜欢时显示空状态。
- 按钮和选中态用浅色底加白描边、同色底影的贴纸样式，不用青蓝实心块。

### 13.7 验收点

- 改昵称和签名后，主页帖子卡片、详情、评论、私信里的显示跟着变。
- 昵称清空后各处显示用户名。
- 改用户名后用新用户名能登录，旧用户名登不上；旧用户名可以被另一个账号注册。
- 30 天内第二次改用户名返回 409，昵称和签名也没有被保存。
- 换头像后各处显示新头像；上传不是图片的文件、超过 2 MB 的文件被拒；存下来的文件不带拍摄地点。
- 用注册验证码或重置验证码提交换绑，被拒。
- 换邮箱时当前密码错误被拒；新邮箱已被别人使用时返回 409。
- 邮箱注册的账号绑定手机号后，两种方式都能找回密码。
- 数据库和 Redis 里仍然搜不到邮箱和手机号的明文。
- 设备管理里能看到另一台设备；把它下线后，那台设备的下一次请求返回 401，当前这台不受影响。
- 「其他设备全部下线」之后只剩当前这台。
- 用别人的设备编号调下线接口返回 404；接口响应里不出现会话 id。

### 13.8 不做

- 别人的个人主页、关注。
- 解绑邮箱或手机号、注销账号。
- 昵称、签名、头像的审核。举报入口目前只覆盖帖子和评论。
- 换手机号时给旧手机号发提醒短信：通知类短信模板要另外申请。

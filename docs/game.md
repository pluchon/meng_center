# 萌部落 · 游戏域（萌岛）

> 配套文档：[架构设计](architecture.md)、[事件与内部接口](contracts.md)、[认证模块](auth.md)、[前端规范](frontend.md)。

## 1. 范围

一个网页版、单机、3D 的自由探索小游戏，参考塞尔达的开放世界感觉：一座岛，没有加载界面，想去哪就去哪。画风参考萌部落（柔和配色、白边贴纸、圆润可爱）。

- **本期**：一座小岛、角色走跑跳、金币拾取、商店买外观、三枚星之碎片、神殿点亮的结局、自动存档。
- **不做**：多人同屏和任何实时连接、战斗、背包与装备数值、任务系统、攀爬滑翔、音效与音乐、手机触屏操控、排行榜。要做时另起一节，不往本期里塞。

## 2. 边界（用户明确划定的线）

1. **游戏是独立微服务 `meng-game`。** 独占库 `meng_game` 和账号 `meng_game_app`，只监听本机 8105 端口，经网关的 `/game/**` 访问。
2. **登录认证复用现有的，不另起账号。** 身份只来自网关注入的身份头（服务里取 `UserContext`），不信前端传来的用户编号。
3. **游戏里的金币、结算只存在于游戏服务内，不和任何其他服务共享。**
   - 金币和萌部落的积分、经验完全无关：不读 growth，不写 growth，不发事件，不收事件。
   - game 不同步调用任何服务，也不被任何服务调用。依赖表里这一行是「无 / 无 / 无」。
   - 金币不进积分流水，积分也不能换金币。以后若要互通，要用户明确说了再改本节。
4. 没有 `meng-api-game`：没有对外契约，不建空壳（同 im）。

## 3. 玩法

世界是一座圆形小岛，海水环绕，地形由固定种子程序生成，前后端用同一个种子，服务端不传地形。

| 地点 | 内容 |
|---|---|
| 出生海滩 | 玩家第一次进来站在这里，之后从上次存的位置继续 |
| 草地 | 开阔，散落金币和花 |
| 森林 | 树密，一枚星之碎片藏在深处 |
| 小村 | 几间房子和商店 NPC「团子」 |
| 海边灯塔 | 一枚星之碎片 |
| 山丘 | 一枚星之碎片在半山腰，山顶是神殿 |

流程：

1. 标题页点「进入萌岛」，加载世界，站到海滩。
2. 自由探索：走、跑、跳，第三人称相机。
3. 捡金币：散落在岛上的金币，每个点位**每天可以拾取一次**（按业务时区切天），所以第二天还能再来捡。宝箱每个点位只能开一次。
4. 去村里找团子买外观：帽子三种、衣服颜色五种，用金币买，买了永久拥有，可以随时换装。
5. 找齐三枚星之碎片（每枚只能得一次），回山顶神殿点亮。点亮后播放结局画面，发一次性的奖励金币和称号「岛之守护者」，之后继续自由漫游。

## 4. 接口

均在 game 服务，均需登录，路径 `/game/**`。第一次访问时玩家档案不存在就自动建一个（和 growth 的账户一样按需创建）。

| 接口 | 用途 |
|---|---|
| `GET /game/profile` | 我的档案：金币、位置和朝向、已装备的帽子和衣服、碎片数、是否已点亮神殿 |
| `GET /game/world` | 世界清单：金币点位和宝箱点位（含「我今天是否已拿」）、三枚碎片的点位（含是否已得）、神殿位置、商品清单（含价格和「我是否已拥有」） |
| `POST /game/pickups` | 拾取。请求体 `{spotId, x, z}`（玩家当前位置），返回本次得到什么和最新金币数 |
| `POST /game/shop/purchases` | 购买商品，请求体 `{itemId}`，返回最新金币数 |
| `PUT /game/equipment` | 换装，请求体 `{hat, outfit}`，只能装备已拥有的，传空表示不戴 |
| `POST /game/shrine` | 点亮神殿，需要已有三枚碎片；只有第一次发奖励，重复调用不报错 |
| `PUT /game/save` | 存位置，请求体 `{x, y, z, yaw}` |

规则：

- 点位清单和商品清单是**内容**，放服务端 `resources/game/world.json` 和 `shop.json`，随代码发布，启动时校验格式，不对就拒绝启动。前端只通过 `/game/world` 取，不在前端再写一份。
  - `world.json`：出生点、神殿位置、全部点位（标识、种类、坐标）；金币点位自带金额 1～5。
  - `shop.json`：商品标识、种类（帽子 / 围巾）、价格。
  - 点位坐标是照着前端地形摆的（见第 7 节），改点位要确认落在陆地上、不在房子和地标里。
- 拾取校验：点位存在、玩家上报位置到点位的水平距离不超过 3 个单位、这个周期内（每日点位按当天，一次性点位按永久）没有拿过。已经拿过再请求，返回「已拿过」，不报错也不重复发。
- 购买校验：商品存在、未拥有、金币够。扣金币和写拥有记录在**同一个事务**里，扣款用 `coins >= price` 条件更新，行数不对就回滚。
- 每个写请求先用 `INSERT … ON DUPLICATE KEY UPDATE` 按需建档，同时给玩家行加排他锁，同一玩家的写请求排队执行。不能用 `INSERT IGNORE`：它只加共享锁，两个并发请求再一起升级成排他锁会死锁。
- 错误码：`GAME_TOO_FAR`、`GAME_OUT_OF_ISLAND`（400），`GAME_NOT_ENOUGH_COINS`、`GAME_ITEM_OWNED`、`GAME_ITEM_NOT_OWNED`、`GAME_STARS_MISSING`（409）；点位或商品不存在是 `COMMON_NOT_FOUND`。
- 位置存档：只检查坐标在岛的范围内，超出范围按非法参数拒绝。
- 因为金币不流通、没有排行榜，所以只做以上轻量校验，不做速度检测和反作弊。若以后加排行榜或交易，要重新评估。

## 5. 数据表

库 `meng_game`。每张表都有 `id`（BIGINT 自增）、`create_time`、`update_time`、`delete_state`。

### 5.1 `game_player`

| 字段 | 说明 |
|---|---|
| `user_id` | 唯一索引 |
| `coins` | 金币余额，不会为负 |
| `pos_x` `pos_y` `pos_z` `yaw` | 上次存的位置和朝向；新玩家是海滩出生点 |
| `hat` `outfit` | 已装备的商品标识，可空 |
| `cleared_time` | 点亮神殿的时间，空表示还没点亮 |

### 5.2 `game_pickup`

| 字段 | 说明 |
|---|---|
| `user_id` | 谁拿的 |
| `spot_id` | 点位标识 |
| `period` | 每日点位是业务日期 `yyyy-MM-dd`，一次性点位是 `ONCE` |
| `amount` | 本次得到的金币，碎片是 0 |

`(user_id, spot_id, period)` 唯一索引；重复拾取靠它挡住，撞唯一索引按「已拿过」处理。

### 5.3 `game_item`

| 字段 | 说明 |
|---|---|
| `user_id` | 谁拥有 |
| `item_id` | 商品标识 |

`(user_id, item_id)` 唯一索引。

### 5.4 `game_coin_record`

金币流水，只增不改。

| 字段 | 说明 |
|---|---|
| `user_id` | 谁的金币 |
| `kind` | 枚举：拾取 / 购买 / 通关奖励 |
| `ref` | 拾取是点位标识，购买是商品标识 |
| `amount` | 正数获得，负数花掉 |
| `balance_after` | 这一笔之后的余额 |

`(user_id, id)` 索引用来对账。余额加减用 `coins = coins + #{amount}` 这样的原子更新，不先读后写。

## 6. 服务落地

- 模块：`java_backend/meng-game`，只加进父工程的 modules，不建 api 模块。
- 配置：Nacos Data ID `meng-game.yml` 的 `meng.game`：业务时区、拾取距离 3、宝箱金币 20、通关奖励 100、存档半径 110、存档高度 -10～60。碎片不给金币。金币点位金额和商品价格是内容，在上面两个 JSON 里：帽子 30 / 50 / 80，围巾各 20。
- 网关：加一条 `meng-game` 路由 `Path=/game/**`，不加白名单，必须登录。
- 库和账号：`deploy/mysql/01-user.sh` 和 `Initialize-DomainDatabases.ps1` 的域列表里加 `game`；`deploy/compose.yml`、`Start-Backend.ps1` 按其他服务的做法补齐。
- 迁移：Flyway 只往前加，`V1__create_game.sql` 建 5.1～5.4 四张表。
- 环境变量：`MENG_MYSQL_GAME_PASSWORD`，由 `Initialize-LocalEnvironment.ps1` 生成。
- 验证：`verification/Test-Game.ps1` 走网关覆盖第 8 节的验收点。
- 分层：`Controller → Service → Mapper`，字段注入，事务 `rollbackFor = Exception.class`，状态用枚举，转换放 `converter`，约定同 growth。

## 7. 前端

- 页面：`/game`，懒加载，需要登录；顶部导航「成长」后面有「萌岛」入口。页面外壳（标题页、HUD、商店面板、暂停菜单、结局画面）是 Vue 组件，样式沿用萌部落的白边贴纸、`DialogShell` 和公共状态页；3D 世界本身在 `src/game/` 里，用普通模块写，不放进 Vue 的响应式里。
- 引擎：**Babylon.js**（`@babylonjs/core`、`@babylonjs/materials`，按路径引入用到的模块），不引入物理引擎。构建时单独打成 `island-babylon` 块，只有进游戏页才下载。原因：自带相机、场景、实例化、动画和输入，开放世界要用的东西不用自己拼；物理用不上，因为地面高度可以直接从地形函数采样，树和房子用简单的圆柱和包围盒挡住人就够，省掉几百 KB 的 wasm。项目里原有的 `three` 只给背景特效用，游戏不用它。
- 代码：`src/game/terrain.js`（高度函数、地标、房子、小路）、`scenery.js`（天空、海、地形、小村、灯塔、神殿、云）、`flora.js`（植物）、`wind.js`（风）、`dango.js`（团子模型）、`pickups.js`（金币、碎片、宝箱）、`effects.js`（粒子）、`camera.js`（相机）、`collision.js`（水平碰撞）、`world.js`（引擎、光照、键盘、每帧更新）；页面外壳 `views/game/`，商店 `components/game-shop/`，地图 `components/game-map/`。
- 地形：由固定种子的噪声加岛形遮罩生成高度，地面高度、碰撞和渲染用同一个函数，保证角色不陷地也不浮空；用 MixMaterial 按高度、坡度和到小路的距离混合草地、沙滩（只在海边）、岩石和小路四种贴图。
- 模型：**不用任何外部 3D 模型文件**，全部程序生成，再贴第 9 节的图片。圆树是树干加几团球，松树是三层圆锥（只长在森林），另有灌木、草丛（十片折过的叶子）、花（花茎、五片花瓣、花心，一簇一簇同色）、蘑菇（只在树下）和低多边形石头；房子是盒子加双坡屋顶；角色是团子（球身子、小脚、脸贴图）。植物全用薄实例，同一种一次画完。
- 风：给草、花、树冠和灌木的材质插一段顶点代码，越高的地方摆得越多，同一株按自己的位置取相位。
- 操作：`WASD` 或方向键移动，`Shift` 跑，`空格` 跳，`E` 互动（和团子说话、开宝箱、点亮神殿），`M` 地图，`Esc` 暂停。点一下画面锁定鼠标，之后移动鼠标就转视角（浏览器不让锁时按住拖动），滚轮拉远拉近；鼠标被解锁（按 Esc、切走窗口）就暂停，继续游戏时重新锁定。金币和碎片走近自动拾取。
- 相机：第三人称跟随；相机和角色之间被地面、树冠或房子挡住时自动拉近，让开后慢慢退回。
- 手感：浅水里走得慢；跑步扬尘、高处落地一圈尘土；捡到东西冒星星；团子老板在附近时转过来看你。
- 地图：右下角圆形小地图，北在上，画地形、小路、房子、商店、神殿、灯塔和自己的朝向与视野；点它或按 `M` 放大，放大时角色停下。不标金币、宝箱和碎片，留给玩家自己找。
- 画面：天色随时间缓慢变化（程序渐变，不做昼夜多套贴图）；碎片、金币、灯塔的灯和神殿上的星星有光晕，其他东西不发光。目标是普通笔记本的集成显卡上 60 帧，只开一盏带阴影的方向光，阴影分辨率和植物数量写成常量方便调（`flora.js` 的 `Count`）。
- 存档：拾取、购买、换装、点亮是即时请求；位置每 15 秒存一次，离开页面时再用 `keepalive` 请求补存一次。
- 状态：加载中、失败、未登录、世界取不到都用公共状态页，不另画。
- 图标：HUD 和面板里的图标手画 SVG，冰蓝描边，沿用项目现有做法，不用图标库，也不出图片。

## 8. 验收点

- 新账号第一次进来，档案自动建好，站在海滩，金币 0。
- 走到金币上自动拾取，金币数增加；刷新页面后数目还在；同一个点位当天再走过去不会再得。
- 把上报位置改到离点位很远再请求拾取，被拒；点位标识不存在被拒。
- 金币不够时买东西被拒，余额不变；够的时候扣款和拥有记录同时生效；重复购买被拒；两个请求同时买同一件，只有一个成功。
- 只能装备已拥有的商品。
- 三枚碎片没集齐点亮被拒；集齐后第一次点亮发奖励，再点不会重复发。
- 关闭页面再打开，位置、金币、外观、碎片都回到离开时的样子。
- 游戏服务停掉时，萌部落其余页面不受影响；游戏页显示失败状态而不是白屏。
- 游戏服务的库和代码里找不到任何对 growth、content、im、user 的调用，也没有任何事件。

## 10. 不做

- 多人、实时同步、聊天。
- 金币与萌部落的积分、经验、抽奖有任何互通。
- 战斗、血量、敌人、装备数值、任务系统。
- 手机触屏操控、手柄、音效音乐。
- 反作弊、排行榜、交易。

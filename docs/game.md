# 萌部落 · 游戏域（萌岛）

> 配套文档：[架构设计](architecture.md)、[事件与内部接口](contracts.md)、[认证模块](auth.md)、[前端规范](frontend.md)。

## 1. 范围

一个网页版、单机、3D 的开放世界探索游戏，参考塞尔达旷野之息：一座大岛，没有加载界面，看得到的地方都能去——走、跑、爬、滑翔、游泳。画风是萌部落的柔和配色加卡通渲染。

- **已做**：约 800 米见方的大岛（海滩、小村、花海、森林、湖和湖心小岛、巨树高原、雪山、东边海崖、浮空岛）；攀爬、滑翔、游泳和耐力；卡通渲染、昼夜、天空与水面、角色周围的立体花草；现场合成的音乐、环境声和音效；瞭望台、金币、宝箱、三枚星之碎片、浮空岛神殿结局；商店换装；自动存档；地图。
- **下一期**：轻量战斗（史莱姆一类的敌人、血量、受伤与回复）；爬上瞭望台点亮那一片地图（地图默认是雾）；试炼（短的物理谜题，奖励星之碎片，集够换耐力上限）；藏在各处的萌芽收集。
- **不做**：多人同屏和任何实时连接、背包与装备数值、手机触屏操控、排行榜。

## 2. 边界（用户明确划定的线）

1. **游戏是独立微服务 `meng-game`。** 独占库 `meng_game` 和账号 `meng_game_app`，只监听本机 8105 端口，经网关的 `/game/**` 访问。
2. **登录认证复用现有的，不另起账号。** 身份只来自网关注入的身份头（服务里取 `UserContext`），不信前端传来的用户编号。
3. **游戏里的金币、结算只存在于游戏服务内，不和任何其他服务共享。**
   - 金币和萌部落的积分、经验完全无关：不读 growth，不写 growth，不发事件，不收事件。
   - game 不同步调用任何服务，也不被任何服务调用。依赖表里这一行是「无 / 无 / 无」。
   - 金币不进积分流水，积分也不能换金币。以后若要互通，要用户明确说了再改本节。
4. 没有 `meng-api-game`：没有对外契约，不建空壳（同 im）。

## 3. 玩法

世界由固定种子的噪声加几处手工地形拼成，前后端用同一份地形代码（`src/game/terrain.js`），服务端不传地形，只按坐标存点位。

| 地点 | 内容 |
|---|---|
| 启程海滩（岛南） | 第一次进来站在这里，之后从上次存的位置继续 |
| 小村 | 五间房子、商店摊位和 NPC「团子」 |
| 花海（东南） | 开阔的草地，花开得最密 |
| 森林（西） | 松树和圆树很密，树下长蘑菇 |
| 湖（中西） | 湖心小岛上有一枚星之碎片，要游过去 |
| 巨树高原（西北） | 高 60 多米的台地，四周是能爬的悬崖；巨树树干能爬，大枝杈上有一枚星之碎片 |
| 雪山（东北） | 最高 180 米，山顶有一枚星之碎片，高处积雪 |
| 海崖（东） | 几十米高的陡崖，崖顶有灯塔，灯塔能爬 |
| 瞭望台 ×5 | 能爬的高塔，顶上有宝箱，站上去能看很远 |
| 浮空岛 | 悬在 150 米高空，要从湖东岸的上升气流乘风上去再滑翔过去；岛上是神殿 |

流程：

1. 标题页点「进入萌岛」，加载世界，站到海滩。
2. 自由探索：看到想去的地方就过去，陡坡和墙直接爬，高处跳下来展开叶子滑翔，水里游过去。
3. 捡金币：每个金币点位**每天可以拾取一次**（按业务时区切天）。宝箱每个只能开一次，大多放在塔顶、悬崖上这类难到的地方。
4. 去村里找团子买外观：帽子三种、围巾颜色五种，买了永久拥有，可以随时换装。
5. 找齐三枚星之碎片（每枚只能得一次），去浮空岛的神殿点亮。点亮后播放结局画面，发一次性的奖励金币和称号「岛之守护者」，之后继续自由漫游。

## 4. 接口

均在 game 服务，均需登录，路径 `/game/**`。第一次访问时玩家档案不存在就自动建一个（和 growth 的账户一样按需创建）。

| 接口 | 用途 |
|---|---|
| `GET /game/profile` | 我的档案：金币、位置和朝向、已装备的帽子和衣服、碎片数、是否已点亮神殿 |
| `GET /game/world` | 世界清单：金币点位和宝箱点位（含「我今天是否已拿」）、三枚碎片的点位（含是否已得）、神殿位置、商品清单（含价格和「我是否已拥有」） |
| `POST /game/pickups` | 拾取。请求体 `{spotId, x, z}`（玩家当前位置），返回本次得到什么和最新金币数 |
| `POST /game/shop/purchases` | 购买商品，请求体 `{itemId}`，返回最新金币数 |
| `PUT /game/equipment` | 换装，请求体 `{hat, outfit}`，只能装备已拥有的，传空表示不戴 |
| `POST /game/shrine` | 点亮神殿，需要已有三枚碎片；只有第一次发奖励，重复调用不报错 |
| `PUT /game/save` | 存位置，请求体 `{x, y, z, yaw}` |

规则：

- 点位清单和商品清单是**内容**，放服务端 `resources/game/world.json` 和 `shop.json`，随代码发布，启动时校验格式，不对就拒绝启动。前端只通过 `/game/world` 取，不在前端再写一份。
  - `world.json`：出生点、神殿位置、全部点位（标识、种类、坐标）；金币点位自带金额 1～5；放在塔顶、巨树枝杈、浮空岛这些高处的点位带地面高度 `y`，接口原样返回。
  - `shop.json`：商品标识、种类（帽子 / 围巾）、价格。
  - 点位坐标是照着前端地形摆的（见第 7 节），改点位要确认落在陆地上、不在房子和地标里。现在这份是按地形用脚本生成后人工挑过的：117 枚金币、15 个宝箱、3 枚碎片。
- 拾取校验：点位存在、玩家上报位置到点位的水平距离不超过 3 个单位、这个周期内（每日点位按当天，一次性点位按永久）没有拿过。已经拿过再请求，返回「已拿过」，不报错也不重复发。
- 购买校验：商品存在、未拥有、金币够。扣金币和写拥有记录在**同一个事务**里，扣款用 `coins >= price` 条件更新，行数不对就回滚。
- 每个写请求先用 `INSERT … ON DUPLICATE KEY UPDATE` 按需建档，同时给玩家行加排他锁，同一玩家的写请求排队执行。不能用 `INSERT IGNORE`：它只加共享锁，两个并发请求再一起升级成排他锁会死锁。
- 错误码：`GAME_TOO_FAR`、`GAME_OUT_OF_ISLAND`（400），`GAME_NOT_ENOUGH_COINS`、`GAME_ITEM_OWNED`、`GAME_ITEM_NOT_OWNED`、`GAME_STARS_MISSING`（409）；点位或商品不存在是 `COMMON_NOT_FOUND`。
- 位置存档：只检查坐标在岛的范围内，超出范围按非法参数拒绝。
- 因为金币不流通、没有排行榜，所以只做以上轻量校验，不做速度检测和反作弊。若以后加排行榜或交易，要重新评估。

## 5. 数据表

库 `meng_game`。每张表都有 `id`（BIGINT 自增）、`create_time`、`update_time`、`delete_state`。

### 5.1 `game_player`

| 字段 | 说明 |
|---|---|
| `user_id` | 唯一索引 |
| `coins` | 金币余额，不会为负 |
| `pos_x` `pos_y` `pos_z` `yaw` | 上次存的位置和朝向；新玩家是海滩出生点 |
| `hat` `outfit` | 已装备的商品标识，可空 |
| `cleared_time` | 点亮神殿的时间，空表示还没点亮 |

### 5.2 `game_pickup`

| 字段 | 说明 |
|---|---|
| `user_id` | 谁拿的 |
| `spot_id` | 点位标识 |
| `period` | 每日点位是业务日期 `yyyy-MM-dd`，一次性点位是 `ONCE` |
| `amount` | 本次得到的金币，碎片是 0 |

`(user_id, spot_id, period)` 唯一索引；重复拾取靠它挡住，撞唯一索引按「已拿过」处理。

### 5.3 `game_item`

| 字段 | 说明 |
|---|---|
| `user_id` | 谁拥有 |
| `item_id` | 商品标识 |

`(user_id, item_id)` 唯一索引。

### 5.4 `game_coin_record`

金币流水，只增不改。

| 字段 | 说明 |
|---|---|
| `user_id` | 谁的金币 |
| `kind` | 枚举：拾取 / 购买 / 通关奖励 |
| `ref` | 拾取是点位标识，购买是商品标识 |
| `amount` | 正数获得，负数花掉 |
| `balance_after` | 这一笔之后的余额 |

`(user_id, id)` 索引用来对账。余额加减用 `coins = coins + #{amount}` 这样的原子更新，不先读后写。

## 6. 服务落地

- 模块：`java_backend/meng-game`，只加进父工程的 modules，不建 api 模块。
- 配置：Nacos Data ID `meng-game.yml` 的 `meng.game`：业务时区、拾取距离 3、宝箱金币 20、通关奖励 100、存档半径 460、存档高度 -30～260（浮空岛在 150 米）。碎片不给金币。金币点位金额和商品价格是内容，在上面两个 JSON 里：帽子 30 / 50 / 80，围巾各 20。
- 网关：加一条 `meng-game` 路由 `Path=/game/**`，不加白名单，必须登录。
- 库和账号：`deploy/mysql/01-user.sh` 和 `Initialize-DomainDatabases.ps1` 的域列表里加 `game`；`deploy/compose.yml`、`Start-Backend.ps1` 按其他服务的做法补齐。
- 迁移：Flyway 只往前加，`V1__create_game.sql` 建 5.1～5.4 四张表。
- 环境变量：`MENG_MYSQL_GAME_PASSWORD`，由 `Initialize-LocalEnvironment.ps1` 生成。
- 验证：`verification/Test-Game.ps1` 走网关覆盖第 8 节的验收点。
- 分层：`Controller → Service → Mapper`，字段注入，事务 `rollbackFor = Exception.class`，状态用枚举，转换放 `converter`，约定同 growth。

## 7. 前端

- 页面：`/game`，懒加载，需要登录；顶部导航「成长」后面有「萌岛」入口。页面外壳（标题页、HUD、耐力环、地图、商店、暂停菜单、结局画面）是 Vue 组件，样式沿用萌部落的贴纸风、`DialogShell` 和公共状态页；3D 世界和声音在 `src/game/` 里，用普通模块写，不放进 Vue 的响应式里。
- 引擎：**Babylon.js**（`@babylonjs/core`、`@babylonjs/materials`，按路径引入用到的模块），不引入物理引擎；攀爬、滑翔、游泳都是自己写的角色控制，地面高度查高度表，建筑、石头、树干是带底和顶的圆柱与盒子。构建时单独打成 `island-babylon` 块，只有进游戏页才下载。项目里原有的 `three` 只给背景特效用，游戏不用它。
- 代码（`src/game/`）：

  | 文件 | 内容 |
  |---|---|
  | `terrain.js` | 高度表（2 米一格，约 0.2 秒建好）、地表权重表、地标、房子、瞭望台、小路、浮空岛和上升气流 |
  | `ground.js` | 地面：64 米一块，三档精度随距离切换，块边垂裙边防缝 |
  | `materials.js` | 卡通渲染（明暗三层）和地表混合（草地、沙滩、小路、森林、花海按混合图叠，陡坡三向投影贴岩石，高处积雪），都是插在标准材质上的着色器片段 |
  | `sky.js` / `water.js` | 程序天空（渐变、太阳月亮、星星、卡通云）和昼夜配色；水面按水深变色、岸边白浪、迎光闪烁 |
  | `structures.js` | 小村、摊位、灯塔、瞭望台、大石头、巨树、浮空岛、神殿、上升气流 |
  | `flora.js` / `wind.js` | 树和灌木（近处细模型、远处粗模型，走远了重分）；草丛、花、蘑菇、小石子只在角色周围一圈生成；风和被角色拨开的草 |
  | `player.js` / `collision.js` / `camera.js` | 角色控制、碰撞体、第三人称相机 |
  | `dango.js` / `pickups.js` / `effects.js` | 团子模型和动作、金币碎片宝箱、粒子 |
  | `audio.js` | 用 Web Audio 现场合成的音乐、环境声和音效 |
  | `post.js` | 描边、抗锯齿和三档画质 |
  | `world.js` | 把上面这些拼起来：引擎、光照和昼夜、键盘、每帧更新 |

- 操作：`WASD` 移动，`Shift` 冲刺（水里快游），`空格` 跳，空中再按 `空格` 展开叶子滑翔，对着陡坡或墙走就开始爬（爬时 `空格` 往上一蹿、`S`+`空格` 蹬墙离开），`E` 互动，`M` 地图，`Esc` 暂停。点一下画面锁定鼠标，之后移动鼠标转视角（浏览器不让锁时按住拖动），滚轮拉远拉近；鼠标被解锁（按 Esc、切走窗口）就暂停。
- 耐力：满 100。冲刺、攀爬（爬的时候更耗、贴着不动很省）、往上一蹿、滑翔、快游都耗；落地后停 0.6 秒开始回。用光就「透支」，耐力环变红，回满前不能再冲刺、爬或滑翔；爬着用光会掉下来，游着用光会被冲回最近站过的岸边。
- 相机：第三人称跟随；被地面、树冠、建筑或石头挡住时自动拉近，让开后慢慢退回。
- 昼夜：一天 20 分钟，进游戏是早上 8 点。太阳和月光、天空、雾、卡通明暗的光量一起变；夜里窗户和灯塔亮起来，角色周围飘萤火虫。
- 声音：背景音乐是稀疏的钢琴短句，按区域（村子、森林、山上）和昼夜换音阶；环境声有风（越高越大、滑翔时更大）、海浪（离海近才有）、白天的鸟、夜里的虫；脚步按草地、沙子、小路、岩石、雪、木头区分；拾取、开箱、碎片、神殿、滑翔、落水、透支都有音效。不加载任何音频文件。
- 地图：右下角圆形小地图跟着自己走，看附近 180 米；点它或按 `M` 放大成整座岛，放大时角色停下。画地形、小路、房子、商店、灯塔、瞭望台、浮空岛和神殿，以及自己的朝向与视野；不标金币、宝箱和碎片。
- 画质：暂停菜单里选高、中、低（渲染分辨率、阴影精度、描边、角色周围花草的半径和密度），和音量一起存在浏览器本地，换画质会按新档位重建世界。默认「中」，在集成显卡上 60 帧。
- 存档：拾取、购买、换装、点亮是即时请求；位置每 15 秒存一次，离开页面时再用 `keepalive` 请求补存一次。旧存档的位置在水里或岛外时从海滩开始。
- 状态：加载中、失败、未登录、世界取不到都用公共状态页，不另画。
- 图标：HUD 和面板里的图标手画 SVG，冰蓝描边，沿用项目现有做法。

## 8. 验收点

- 新账号第一次进来，档案自动建好，站在海滩，金币 0。
- 走到金币上自动拾取，金币数增加；刷新页面后数目还在；同一个点位当天再走过去不会再得。
- 把上报位置改到离点位很远再请求拾取，被拒；点位标识不存在被拒。
- 金币不够时买东西被拒，余额不变；够的时候扣款和拥有记录同时生效；重复购买被拒；两个请求同时买同一件，只有一个成功。
- 只能装备已拥有的商品。
- 三枚碎片没集齐点亮被拒；集齐后第一次点亮发奖励，再点不会重复发。
- 关闭页面再打开，位置、金币、外观、碎片都回到离开时的样子。
- 游戏服务停掉时，萌部落其余页面不受影响；游戏页显示失败状态而不是白屏。
- 游戏服务的库和代码里找不到任何对 growth、content、im、user 的调用，也没有任何事件。

# 萌部落社区 · 内容域

> 2026-10-10 首版，动手写代码前的共识。配套文档：[架构设计](architecture.md)、[事件与内部接口](contracts.md)、[前端规范](frontend.md)、[成长域](growth.md)。
> 设计稿在 Claude Design 画布的 `home` 页面，共三张：主页、帖子详情、发帖页。

## 1. 范围

- **本期**：帖子分类、发帖、改帖、删帖、帖子流（分类筛选、最新 / 热门、翻页）、帖子详情、喜欢、收藏、浏览量、IP 属地、配图、封面、标签、草稿、评论与回复。
- **暂缓**：发帖审核（以后接大模型）、管理端的帖子管理、搜索、举报、置顶、评论点赞、@ 提醒、视频、发帖页的三个 AI 入口。
- **本期只留入口**：主页上的通知、私信、萌萌，点了提示还没开放；搜索可展开输入框，提交时提示还没开放。签到和等级见[成长域](growth.md)。

### 1.1 分两步交付

| 步骤 | 后端 | 前端 |
|---|---|---|
| 第一步：主页 | 发帖、帖子流、喜欢、收藏、配图上传与读取、IP 属地 | 页面骨架和主页 |
| 第二步：详情与发帖 | 帖子详情、浏览量、改帖、删帖、评论与回复、封面、标签、草稿 | 帖子详情页、发帖页、改帖页 |

- 第一步里主页上的「发一条新帖」、帖子卡片的标题和评论按钮都只提示还没开放，不跳转。
- 第一步就做发帖接口，是因为主页要有真实的帖子才能验收；这时还没有发帖页，验收用接口造数据。
- 第一步不发 `comment.created`，浏览数和评论数显示为 0。
- 帖子详情和发帖页的设计稿还会调整，第二步开始前以画布的最新版本为准，并同步第 12.3、12.4 节。

## 2. 整体方案

- 新服务 `meng-content`，独占库 `meng_content` 和账号 `meng_content_app`，只监听本机 8102 端口，经网关的 `/content/**` 访问。
- **全部接口都要登录。** 社区成员是审核后才进来的，帖子不对未登录的人开放。
- **作者信息现查。** 帖子和评论只存作者的用户 id，昵称、头像、等级按页批量调 `GET /user/internal/users`。
  调用失败时降级成占位昵称和默认头像，列表照常返回。
  注册时不填昵称，所以 user 的这个接口要改成：昵称为空时返回用户名。
- **计数冗余在帖子上。** 浏览、喜欢、评论数是 `post` 表的列，和对应的写操作在同一个事务里加减，列表不做聚合查询。
- **正文是 Markdown。** 库里存原文；摘要在保存时由后端生成（去掉标记后的前 120 个字）。
  渲染在前端做，渲染结果必须经过过滤才能放进页面。正文里的图片语法不渲染，图片只走配图。
- **配图存本机磁盘。** 根目录来自配置，读写集中在一个存储类里，以后换对象存储只动这个类。
- **发了就能看到。** 本期没有审核，帖子没有状态列，只有存在和已删除。
  接入大模型审核时再加状态列，默认值是已发布，不影响已有数据。

## 3. 分类

固定五个，用枚举表示，库里存枚举名。不建分类表，也没有管理界面：加一个分类本来就要同时配颜色和文案，改代码更直接。

| 枚举 | 名称 | 放什么 |
|---|---|---|
| `ANIME` | 追番 | 番剧、漫画、轻小说的讨论、推荐、观后感，动漫音乐 |
| `CREATION` | 创作 | 自己做的东西：绘画、同人文、手书、cos、手办摄影 |
| `GAME` | 游戏 | 二次元手游、Galgame、音游、主机游戏 |
| `TECH` | 技术 | 编程、建站、AI、软硬件折腾 |
| `DAILY` | 日常 | 闲聊、生活、新人报到、周边开箱，以及放不进上面的 |

- 发帖必选一个，前端默认选中日常。
- 「综合」不是分类，是不带分类条件的查询。
- 名称和颜色在前端：名称进 `locales/`，颜色进 `tokens.scss`，都按枚举名对应。

## 4. 接口

均在 content 服务，均需登录。

| 接口 | 用途 |
|---|---|
| `POST /content/images` | 上传一张配图，返回图片 id 和地址 |
| `GET /content/files/{name}` | 读取图片文件 |
| `POST /content/posts` | 发帖 |
| `GET /content/posts` | 帖子流，参数 `category`（可空）、`sort`、`page`、`size` |
| `GET /content/posts/{id}` | 帖子详情，同时计一次浏览 |
| `PUT /content/posts/{id}` | 改帖，仅作者 |
| `DELETE /content/posts/{id}` | 删帖，仅作者 |
| `PUT /content/posts/{id}/like` | 喜欢 |
| `DELETE /content/posts/{id}/like` | 取消喜欢 |
| `PUT /content/posts/{id}/favorite` | 收藏 |
| `DELETE /content/posts/{id}/favorite` | 取消收藏 |
| `GET /content/posts/{id}/comments` | 一级评论，分页，每条带前 3 条回复和回复总数 |
| `GET /content/comments/{id}/replies` | 某条一级评论下的回复，分页 |
| `POST /content/posts/{id}/comments` | 发评论或回复 |
| `DELETE /content/comments/{id}` | 删评论，仅评论作者 |
| `GET /content/tags` | 标签联想，参数 `keyword`（可空）、`size` |
| `GET /content/drafts` | 我的草稿列表，按最近修改倒序 |
| `GET /content/drafts/{id}` | 一份草稿的全部内容，仅本人 |
| `POST /content/drafts` | 新建草稿 |
| `PUT /content/drafts/{id}` | 覆盖保存草稿，仅本人 |
| `DELETE /content/drafts/{id}` | 删草稿，仅本人 |

- 喜欢和收藏用 `PUT` / `DELETE`，重复调用结果相同，不报错。
- 帖子流的每一项：id、分类、标题、摘要、前 5 张配图的缩略图地址、配图总数、浏览数、喜欢数、评论数、收藏数（`favoriteCount`，按当前页帖子批量统计收藏记录）、
  当前用户是否喜欢和收藏、IP 属地、发布时间、作者（id、展示名、头像、等级）。
- 详情在此基础上加正文原文、全部配图、封面和标签。没有单独上传封面时，封面是第一张配图；一张图都没有时为空。
- 发帖和改帖的请求体：分类、标题、正文、配图 id 列表（顺序即展示顺序）、封面图片 id（可空）、标签名列表（可空）。
  发帖时还可以带草稿 id：发布成功的同一个事务里删掉这份草稿。
- 帖子流的每一项目前不带封面和标签，主页用不到。以后做需要封面的列表（例如某人喜欢的帖子）时再加字段。
- 标签联想：`keyword` 为空时返回最常用的标签，不为空时按前缀匹配，都按使用次数倒序；`size` 默认 10、最大 20。
- 草稿的请求体和发帖相同，但每一项都可以空着，只要求标题和正文至少有一样不为空。草稿列表的每一项：id、标题、正文开头的一小段、最近修改时间。
- 发评论的请求体：正文，以及回复时被回复的那条评论的 id。被回复者是谁由后端从那条评论读出，不由前端传。
- [contracts.md](contracts.md) 里给 ai 用的两个内部接口，等 ai 服务开始做的时候再实现。

### 4.1 分页与排序

- 按页码分页：`page` 从 1 开始，`size` 默认 10、最大 50；返回当前页数据和总条数。
- `sort=LATEST`：按发布先后倒序。
- `sort=HOT`：只取近 7 天发布的帖子，按热度分倒序，同分按发布先后倒序。
- 热度分是 `post` 表的一列，在浏览、喜欢、评论数变化的同一条更新里按权重加减。
  起步权重：浏览 1、喜欢 4、评论 3，放 Nacos 配置。改权重后旧帖的分数不回算。

## 5. 数据表

库 `meng_content`。除特别说明外，每张表都有 `id`（BIGINT 自增）、`create_time`、`update_time`、`delete_state`。

### 5.1 `post`

| 字段 | 说明 |
|---|---|
| `author_id` | 作者的用户 id |
| `category` | 分类枚举名 |
| `title` | 标题，1 到 50 个字 |
| `content` | 正文，Markdown 原文，1 到 10000 个字 |
| `summary` | 摘要，保存时生成 |
| `image_count` | 配图总数，不含封面 |
| `cover_image_id` | 可空。单独上传的封面 |
| `view_count`、`like_count`、`comment_count` | 冗余计数 |
| `hot_score` | 热度分 |
| `ip_region` | 发帖时的 IP 属地，可空 |

索引：`(category, id)` 给分类筛选；`(create_time)` 给热门的时间窗口。

### 5.2 `post_image`

| 字段 | 说明 |
|---|---|
| `uploader_id` | 上传者 |
| `post_id` | 可空。上传时为空，发帖或改帖时填上 |
| `file_name` | 原图的文件名，随机生成，唯一索引 |
| `thumb_name` | 缩略图的文件名 |
| `width`、`height` | 原图尺寸，前端用来占位，避免加载时跳动 |
| `sort` | 在帖子里的顺序 |
| `kind` | 用途枚举：配图、封面。挂到帖子上时确定 |

- 每帖最多 10 张配图，另可有一张封面；单张不超过 5 MB；只接受 JPEG、PNG、WebP、GIF，按文件头判断，不信扩展名。
- 上传时生成一张宽 480 的缩略图，帖子流只用缩略图。
- 只能把自己上传、还没挂到别的帖子上的图片挂到帖子上。同一张图不能既是配图又是封面。
- 保存下来的文件不能带拍摄地点这类元数据：JPEG 和 PNG 保存前重新编码，WebP 去掉 EXIF 和 XMP 数据块，GIF 原样保留。
- 改帖时被移除的图片逻辑删除。上传后一直没挂到帖子上的图片本期不清理（见第 14 节），
  以后加清理任务时要放过被草稿引用的图片。

### 5.3 `post_like`、`post_favorite`

两张表结构相同：`post_id`、`user_id`、`create_time`，`(post_id, user_id)` 唯一索引，另有 `(user_id, id)` 索引。

这两张是关系表，**取消时物理删除，不带 `update_time` 和 `delete_state`**。
理由：逻辑删除会和唯一索引冲突，而且取消的记录没有任何地方会再用到。

### 5.4 `comment`

| 字段 | 说明 |
|---|---|
| `post_id` | 所属帖子 |
| `author_id` | 评论作者 |
| `root_id` | 一级评论为 0；回复填所属一级评论的 id |
| `reply_to_comment_id` | 可空。回复的是哪一条 |
| `reply_to_user_id` | 可空。被回复者，由后端从被回复的评论读出 |
| `content` | 纯文本，1 到 500 个字 |
| `reply_count` | 仅一级评论使用，它下面的回复数 |
| `ip_region` | 评论时的 IP 属地，可空 |

索引：`(post_id, root_id, id)`。

- 只有两层：一级评论，和挂在一级评论下面的回复。回复别人的回复时仍挂在同一条一级评论下，用 `reply_to_user_id` 标明对象。
- 评论是纯文本，不解析 Markdown。
- 删除一级评论时，如果它下面还有回复，这一条显示成「该评论已删除」的占位，回复保留。

### 5.5 `tag`、`post_tag`

`tag`：

| 字段 | 说明 |
|---|---|
| `name` | 展示用的写法，取第一次创建时的输入 |
| `name_key` | 归一化后的值，唯一索引，查重和联想都用它 |
| `use_count` | 被多少条帖子使用 |

`post_tag`：`post_id`、`tag_id`、`create_time`，`(post_id, tag_id)` 唯一索引，另有 `(tag_id, post_id)` 索引。
它和喜欢、收藏一样是关系表，摘掉时物理删除。

- 标签由用户自己输入，输入时先联想已有的；提交的标签不存在就新建。
- 归一化：去首尾空格、全角转半角、转小写。归一化后相同的算同一个标签。
- 每帖最多 5 个；每个 1 到 12 个字，不能含空白和 `#`。
- 帖子挂上一个标签，它的使用次数加一；改帖摘掉或删帖时减一。和帖子的写入在同一个事务里。
- 两个人同时新建同一个标签，靠唯一索引挡住，冲突的一方改为使用已有的那条。
- 本期标签只在帖子详情里显示，不能按标签筛选。

### 5.6 `post_draft`

草稿单独一张表，不和帖子混在一起：草稿允许缺标题缺正文，不进帖子流、不计数、不发事件，
分开放就不用在每一条帖子查询里排除它。

| 字段 | 说明 |
|---|---|
| `author_id` | 谁的草稿 |
| `category` | 可空 |
| `title` | 可空，最多 50 个字 |
| `content` | 可空，最多 10000 个字 |
| `image_ids` | 配图 id 列表，JSON |
| `cover_image_id` | 可空 |
| `tags` | 标签名列表，JSON。保存草稿不新建标签 |

索引：`(author_id, id)`。

- 每人最多 20 份。存满后新建被拒，覆盖保存已有的不受影响。
- 草稿引用的图片仍是「没挂到帖子上」的状态，发布时才挂上去。
- 从草稿发布：发帖请求带草稿 id，帖子写入成功的同一个事务里把草稿逻辑删除。草稿必须是本人的。
- `post_draft_owner` 以 `author_id` 为主键；保存、删除、从草稿发布先锁定本人的这一行，避免并发创建突破 20 份上限或重复发布。
- 改已发布的帖子不产生草稿。

## 6. 计数规则

| 计数 | 规则 |
|---|---|
| 浏览 | 打开详情时计。同一个人同一帖 24 小时内只算一次，用 Redis 键判重，判重通过后直接给帖子的浏览数加一。作者看自己的帖子也算 |
| 喜欢 | 关系行插入成功加一，删除成功减一 |
| 评论 | 评论和回复都算。发一条加一，删一条减一 |

- 加减和关系行、评论行的写入在同一个事务里。
- 计数用「在原值上加减」的更新，不先查后改。

## 7. IP 属地

- 客户端 IP 取网关注入的 `X-Client-IP`，不读前端传的任何值。
- 用离线库 ip2region 在发帖和评论时解析，结果存成文字，之后不再变。
- 只显示到国家或地区一级，例如台湾、香港、日本。解析不出来就存空，前端不显示这个标记。
- 不保存原始 IP。

## 8. Redis 键

| 键 | 内容 | 有效期 |
|---|---|---|
| `content:viewed:{postId}:{userId}` | 浏览判重 | 24 小时 |
| `content:limit:*` | 限流计数 | 见第 9 节 |

实际键名加项目前缀。

## 9. 限流

按用户维度，阈值放 Nacos 配置。

| 场景 | 起步取值 |
|---|---|
| 发帖 | 每人 60 秒一条，每天最多 20 条 |
| 评论 | 每人 10 秒一条 |
| 上传图片 | 每人每天最多 100 张 |
| 保存草稿 | 每人 3 秒一次 |

## 10. 权限与错误语义

- 改帖、删帖只允许作者本人；删评论只允许评论作者本人；草稿只有本人能看、能改、能删。身份只来自网关注入的请求头。
- 本期管理员没有下架入口，出现违规内容只能直接处理数据库，这是已知缺口。

| 情况 | HTTP 状态 |
|---|---|
| 参数不合法、图片类型或大小不符、配图超过 10 张、标签超过 5 个或写法不合规 | 400 |
| 未登录 | 401 |
| 改或删别人的帖子、评论；读写别人的草稿；挂别人上传的图片 | 403 |
| 帖子、评论或草稿不存在、已删除 | 404 |
| 草稿已经存满 20 份还要新建 | 409 |
| 触发限流 | 429 |

## 11. 事件

事件定义见 [contracts.md](contracts.md)。本期只发有消费者的两个：

| 事件 | 时机 | 本期的消费者 |
|---|---|---|
| `post.published` | 发帖事务提交后 | growth：加经验 |
| `comment.created` | 评论事务提交后 | growth：加经验 |

`post.updated`、`post.deleted`、`post.liked` 的消费者是 ai 和 im，等它们开始做的时候再发。

## 12. 前端

### 12.1 页面与路由

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 主页 | 帖子流、签到卡片、萌萌入口、发帖入口 |
| `/posts/new` | 发帖页 | 分类、标题、正文、配图、封面、标签；带 `draft` 查询参数时载入那份草稿 |
| `/posts/:id` | 帖子详情 | 正文、全部配图、评论区 |
| `/posts/:id/edit` | 改帖页 | 与发帖页共用表单，标题换成改帖的文案，进来时填好原内容 |

- 都需要登录。登录成功后默认进主页；现在的根路径是跳登录页，改成主页。
- 主页的分类、排序、页码放在地址栏的查询参数里，刷新和后退都能回到原来的位置。

### 12.2 主页的组成

| 部分 | 说明 |
|---|---|
| 页面骨架 | 顶部导航（品牌、四个入口、搜索、通知、等级条、头像）和通栏底栏，做成布局，其他登录后的页面共用 |
| 横幅 | 整幅插画、欢迎卡片、对话气泡和贴纸 |
| 分类与排序条 | 「综合」加五个分类，右侧「最新 / 热门」，两者互相独立 |
| 帖子卡片 | 作者行（头像、展示名、等级、发布时间、IP 属地）、分类标、标题、摘要、配图、操作行（浏览、喜欢、评论、收藏） |
| 配图格 | 最多显示 5 张；超过 5 张时第五张盖一层蒙层，写上还剩多少张 |
| 翻页条 | 固定七个位置，页数多时用省略号；不超过七页时全部显示。右侧是回到顶部 |
| 右栏 | 签到卡片、萌萌入口卡片、发帖入口卡片 |

- 帖子操作行从左到右是浏览、喜欢、评论和收藏图标与数量，最右侧显示帖子类型，标题前不再重复显示类型。喜欢与收藏数量随操作即时更新，请求失败时恢复。
- 发帖卡片左侧为标题、右侧为发帖按钮；最新 / 热门通过滑动底色切换。分页按钮有悬浮和按压反馈，回顶部按钮仅显示文字；减少动态效果时关闭动画。
- 右侧三张功能卡片随页面滚动，每张右上角可收起为对应图标的圆形气泡，再次点击展开。全部收起时帖子区域平滑扩宽，任一卡片展开时恢复侧栏宽度。收起不会丢失签到状态。窄屏仍使用上下排布。
- 聊天和发帖卡片不使用外部蓝色阴影；展开时的收起图标无圆形底色，与卡片边缘保留间距。
- 图片预览挂载到页面根部，避免卡片动画影响全屏定位；缩放和拖动图片不会增加页面横向滚动范围。
- 搜索仅实现悬浮展开、图标随输入框移动和移开收缩的交互；键盘焦点可展开，提交提示未开放，不请求搜索接口。
- 主页隐藏页面滚动条，保留滚轮、触控、键盘和回到顶部的滚动功能；离开主页时恢复其他页面的默认滚动条。
- 主页使用最大 1760px 的宽屏容器和自适应侧边留白。横幅带高透明白色遮罩，底部三层海浪使用单个 Canvas 按时间连续改变波峰与振幅，移出视口或页面不可见时暂停，减少动态效果时静止。导航入口使用独立彩色圆形图标底色，成长进度条上方靠右显示经验数字（当前 / 下一级阈值），满级时仅显示当前经验；窄屏保留等级胶囊。页脚含品牌、云朵线稿、条款和联系入口；联系功能尚未开放。
- 桌面端帖子流与右栏独立排布，右栏在可容纳全部卡片的视口中吸附；窄屏或低矮视口恢复普通文档流。
- 喜欢和收藏先在界面上变，请求失败再变回来并提示。
- 帖子流的四种状态：加载中、出错（带重试）、空（「这里还空空的」）、未登录（由路由守卫处理）。
- 相对时间（「3 分钟前」）由前端根据发布时间算。

### 12.3 帖子详情的组成

| 部分 | 说明 |
|---|---|
| 返回入口 | 「回到帖子流」，回到主页时保留原来的分类、排序和页码 |
| 帖子卡片 | 作者行、分类标加标题、渲染后的正文、全部配图、操作行 |
| 操作行 | 浏览、喜欢、评论（点了滚到评论区）、收藏；作者本人在右侧多出编辑和删除 |
| 评论区 | 标题加评论总数、输入框、评论列表、翻页 |
| 一条评论 | 头像、展示名、等级、时间和属地、正文、「回复」；评论作者本人多出「删除」 |
| 回复区 | 挂在一级评论下面的浅色块，每条写明「回复 谁」；默认显示前 3 条，其余点「还有 N 条回复」展开 |
| 右栏 | 作者卡片（头像、展示名、等级）、发帖入口卡片 |

- 帖子作者在评论区里带「作者」标。
- 点某条的「回复」，在它下面展开一个输入框，占位文字是「回复 谁」；同一时间只展开一个。
- 被删除且还有回复的一级评论显示成占位条。
- 删帖、删评论先用 `ElMessageBox.confirm` 确认。删帖成功后回到主页。
- 配图点开看大图用 Element Plus 的图片预览。
- 帖子不存在或已删除时显示空状态和回主页的入口。

### 12.4 发帖页的组成

| 部分 | 说明 |
|---|---|
| 页面骨架 | 不带顶部导航和底栏，整页是一张大卡片；卡片右上有「回到主页」 |
| 顶部区域 | 页面标题，下面一行左边是分类五选一（默认日常），右边是标题输入框，框内右侧显示字数 |
| 左下约七成 | 正文。标题行右侧是字数进度条和字数；工具栏是七个格式按钮、「AI 激发灵感」、「编辑 / 预览」切换；下面是编辑区 |
| 右侧约三成 | 从上到下三张卡片：配图（可切到视频）、封面、标签 |
| 配图卡片 | 一行五格、固定两行十个位置：已传的图、一个添加格、其余是空位；右上角显示张数 |
| 封面卡片 | 一个 16:9 的上传框；标题行右侧是「AI 生成封面图」 |
| 标签卡片 | 标题旁是个数，右侧是「AI 挑选标签」；已选标签放在固定高度的框里，多了在框内滚动但不显示滚动条；下面是输入框和三个独立的 AI 推荐标签占位 |
| 底部 | 左边「保存为草稿」，右边「发布」 |

卡片边缘保留设计稿的对话贴纸、小泡泡、花朵与星光，轻微浮动且不拦截点击；窄屏隐藏侧边装饰，减少动态效果时停止动画。配图不显示额外上传提示文案，视频占位的图标与文字作为一组居中。

配图与视频切换时选中底色左右滑动，内容轻微淡入淡出；标签添加、移除及重新排布带过渡。上传格、AI 入口、格式工具、返回与保存发布按钮提供轻微悬浮和按压反馈，输入框聚焦时描边柔和变化；减少动态效果时缩短这些过渡。

页面底色为纯白，背景仅保留小范围、低透明度的浅蓝液体流动，鼠标移动产生柔和扰动；编辑卡片为极浅水蓝底色并带细描边，正文输入区保留白底。液体只随发帖路由加载，速度与蓝色浓度分别平流，加入受限的旋涡力与逐渐消散；模拟长边不超过 256 像素，窄屏降到 160，按固定 30 步每秒计算，显示插值到最多 60 帧每秒，输出长边不超过 960。压力求解每步 8 次，纹理按速度双通道、浓度与压力单通道存储，卡顿时最多补算两步，避免积压。切到后台暂停，离开发帖页释放 WebGL 资源；减少动态效果或不支持浮点渲染时保留静态背景，不影响表单。模拟方法参考 [NVIDIA GPU Gems 的流体章节](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-38-fast-fluid-dynamics-simulation-gpu)；限制输出分辨率参考 [Three.js 的响应式渲染说明](https://threejs.org/manual/pages/responsive.html)。

正文：

- 编辑区用 CodeMirror 6 写 Markdown 源码，只在进入发帖页时加载。配色、字体、圆角都取设计变量，不用它自带的主题。
- 编辑区的高度和右栏对齐，内容超出后在编辑区内部滚动。
- 宽屏（宽度大于 1100、可用高度至少 700）时卡片最宽 1280，高度随视口调整，保存与发布按钮保持在一屏内；正文、标签及联想项在内部滚动。窄屏或较矮窗口采用自然纵向排列，保证所有操作可达。
- 格式按钮在光标处插入对应的 Markdown 标记，选中了文字就把标记包在两边。
- 字数按 Unicode 码点计，前端的计数和后端的校验用同一种算法。进度条到上限时填满。

配图和封面：

- 自己写上传格，不用 Element Plus 的上传组件。可以点添加格选图，也可以把图片拖进卡片或直接粘贴。
- 选中即上传，同时最多传三张，方格里显示进度，失败的方格可以重试或移除。
- 上传前在浏览器里把静态图的长边缩到不超过 2560，GIF 不处理。
- 没有单独上传封面时，封面框里显示第一张配图并标明是默认的。
- 「视频」只是占位：能切过去看到一个占位框，点了提示还没开放。

标签：

- 输入时请求联想接口，带 300 毫秒防抖，只匹配系统已有标签，已选标签不再推荐，完全匹配项优先。仅有匹配结果且输入框聚焦时显示下拉菜单，点击或上下键配合回车选中；没有匹配时不显示空菜单，仍可回车添加新标签。快速输入时旧请求结果不会覆盖新输入。不自动加载常用标签，AI 推荐位置独立展示三个静态占位，不可点击，待 AI 域接入。
- 选满 5 个后输入框和联想项不可用。

草稿和发布：

- 「保存为草稿」把当前内容存到服务器：这一页还没对应草稿时新建，之后都是覆盖保存。
- 从草稿进来再点「发布」，请求带上草稿 id。
- 校验提示沿用登录注册页的写法：红字放在输入框内部，不在下方另起一行。
- 发布中按钮置为加载；成功后进入这条帖子的详情页。
- 有没保存的改动就离开页面（包括点「回到主页」、后退、关标签页），先确认。
- 三个 AI 入口本期都只提示还没开放。

### 12.5 Markdown

- 渲染用 markdown-it，结果用 DOMPurify 过滤后才放进页面，这是全项目唯一允许 `v-html` 的地方，封装成一个组件。
- 关闭原始 HTML 和图片语法；链接只允许 `http` 和 `https`，新窗口打开并带 `rel="noopener noreferrer nofollow"`。
- 发帖页的预览和详情页用同一个渲染组件。
- 代码块高亮用 highlight.js，只注册常用的几种语言，其余按纯文本显示。

## 13. 验收点

发帖与帖子流：

- 发帖后出现在「综合」和所选分类的最前面，别的分类里没有。
- 标题、正文超长，没选分类，配图超过 10 张，请求被拒。
- 「热门」里没有 7 天前的帖子；给一条帖子点喜欢后，它在热门里的位置上升。
- 翻页的总条数和实际一致；`size` 超过上限被拒或按上限处理。

喜欢、收藏、浏览：

- 连点两次喜欢，喜欢数只加一；取消后减一；两个人各点一次，数字是二。
- 同一个人 24 小时内打开同一帖多次，浏览数只加一。
- 帖子流里「是否喜欢、是否收藏」因人而异，换一个账号看不到别人的状态。

配图：

- 把扩展名改成 `.png` 的非图片文件传上来被拒；超过 5 MB 被拒。
- 把别人上传的图片 id 放进自己的帖子，请求被拒。
- 帖子流里加载的是缩略图。
- 上传一张带拍摄地点的照片，再把保存下来的文件取回来，里面没有拍摄地点。
- 没传封面的帖子，详情里的封面是第一张配图；传了封面的，封面不出现在配图里。

标签：

- 提交一个不存在的标签会新建；换一种写法（大小写、全角半角、首尾空格）再提交，用的是同一个标签。
- 第 6 个标签、超过 12 个字的标签、带空格或 `#` 的标签被拒。
- 改帖摘掉一个标签或删帖后，它的使用次数减一。
- 联想不带关键字时按使用次数倒序；带关键字时只返回以它开头的。

草稿：

- 只填标题或只填正文都能存成草稿；两样都空被拒。
- 存满 20 份后新建返回 409，覆盖保存已有的仍然成功。
- 读、改、删别人的草稿返回 403。
- 带草稿 id 发布成功后，这份草稿从列表里消失；发布失败时草稿还在。
- 草稿不出现在帖子流里，也不给成长加经验。

评论：

- 回复一条回复时，被回复者是那条回复的作者，前端改请求里的任何字段都改变不了它。
- 删除有回复的一级评论后，回复还在，这一条显示成占位。
- 评论数等于评论加回复的总数，删一条减一。

权限与安全：

- 未登录访问任何 `/content/**` 返回 401。
- 改、删别人的帖子和评论返回 403。
- 伪造 `X-Client-IP` 请求，属地不受影响。
- 正文里写脚本标签、事件属性、`javascript:` 链接，详情页都不执行。

事件：

- 发帖、评论后 growth 收到事件并加经验；事务回滚时不发事件。

## 15. 当前实现约定

主页与发帖页已实现，包含配图上传、封面、标签、草稿及发布后的只读详情和浏览计数。详情完整交互、改删帖、评论与回复仍按第 1.1 节第二步开发；当前详情页用于读取发布结果，不含这些操作。

- 发帖 JSON：`{ "category": "DAILY", "title": "标题", "content": "Markdown 正文", "imageIds": [], "coverImageId": null, "tags": [], "draftId": null }`，成功返回帖子 id。上传图片使用 multipart 字段 `file`；响应为 `id`、`url`、`thumbUrl`、`width`、`height`，把 `id` 按顺序加入发帖请求。标题、正文和标签长度均按 Unicode 码点统计。
- 草稿写入成功返回草稿 id；读取草稿返回 `id`、`category`、`title`、`content`、`images`、`cover`、`tags`，图片结构与上传响应一致。保存后地址保留 `draft` 查询参数，刷新可恢复服务端内容；草稿列表页面待设计稿。
- 标签使用次数在发布事务内更新，按归一化键顺序锁定标签，避免多个标签并发创建时锁顺序相反。联想默认返回最多 10 项。
- 帖子流返回统一响应中的 `data`：`records`、`total`、`page`、`size`。每项字段见第 4 节，其中作者展示名字段为 `author.nickname`，缩略图列表为 `images`（含图片 id、原图地址和缩略图地址）。地址为 `/content/files/...`，浏览器经 `/api` 代理读取。
- 喜欢、收藏接口成功返回 `data=null`；所有写操作沿用网关的 Cookie 与 Origin 检查。第一页可用 `GET /content/posts?sort=LATEST&page=1&size=10` 查看。
- 分页、作者资料和当前用户关系均按页批量查询。user 调用设置连接 2 秒、读取 3 秒超时，失败时返回空展示名和默认等级，前端显示「部落成员」及默认头像。
- 本地上传目录是用户环境变量 `MENG_CONTENT_IMAGE_ROOT`，默认在用户 LocalAppData 下，文件不进仓库。数据库事务回滚时清理本次上传文件；解码前限制 4000 万像素，避免小体积超大尺寸图片耗尽内存。JPEG、PNG 重新编码以清除拍摄元数据；WebP 清除 EXIF、XMP 分块，保留图像和动画数据；GIF 原图保留。缩略图为 PNG 的第一帧。
- IP 离线数据及 Java 查询库来自 [ip2region 官方项目](https://github.com/lionsoul2014/ip2region)，同时支持 IPv4、IPv6，内网或无法解析的地址不展示属地。正文摘要通过 CommonMark 文本渲染生成；主页只展示转义文本，不解析正文 HTML。
- 初始化与运行见 `deploy/README.md`，长期回归脚本见 `verification/README.md`。

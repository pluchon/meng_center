## 1. 范围

- **本期**：帖子分类、发帖、改帖、删帖、帖子流（分类筛选、最新 / 热门、翻页）、帖子详情、喜欢、收藏、浏览量、IP 属地、配图、封面、标签、草稿、评论与回复（可带图和表情）、评论点赞、举报和管理端的举报处理、热榜（见第 16 节）、帖子搜索（见第 17 节）、创作中心（见第 12.8 节）。
- **暂缓**：发帖审核（以后接大模型）、管理端的帖子管理、搜评论和搜用户、置顶、@ 提醒、视频、发帖页的三个 AI 入口。
- **本期只留入口**：主页上的萌萌，点了提示还没开放。通知和私信见[消息域](im.md)。签到和等级见[成长域](growth.md)。

| 第四步：创作中心 | 我的帖子列表、数据汇总、作者每日统计与趋势、帖子表现排行；草稿列表带配图 | 创作中心页，导航加「创作」入口 |

- 点击主页帖子卡片的空白区域、标题或评论入口进入详情页，并保留主页筛选与页码。图片预览、喜欢和收藏按钮独立执行各自操作，选中文字时不触发跳转。
- 第一步就做发帖接口，是因为主页要有真实的帖子才能验收；这时还没有发帖页，验收用接口造数据。
- 详情读取计浏览；评论和回复提交后发 `comment.created`，由成长域消费。
- 详情页、发帖页和改帖页已经接入接口；管理端举报处理页尚未实现，举报目前只入库。

## 2. 整体方案

- 新服务 `meng-content`，独占库 `meng_content` 和账号 `meng_content_app`，只监听本机 8102 端口，经网关的 `/content/**` 访问。
- **全部接口都要登录。** 社区成员是审核后才进来的，帖子不对未登录的人开放。
- **作者信息现查。** 帖子和评论只存作者的用户 id，昵称、头像、等级按页批量调 `GET /user/internal/users`。
  调用失败时降级成占位昵称和默认头像，列表照常返回。
  注册时不填昵称，所以 user 的这个接口要改成：昵称为空时返回用户名。
- **计数冗余在帖子上。** 浏览、喜欢、评论数是 `post` 表的列，和对应的写操作在同一个事务里加减，列表不做聚合查询。
- **正文是 Markdown。** 库里存原文；摘要在保存时由后端生成（去掉标记后的前 120 个字）。
  渲染在前端做，渲染结果必须经过过滤才能放进页面。正文里的图片语法不渲染，图片只走配图。
- **配图存本机磁盘。** 根目录来自配置，读写集中在一个存储类里，以后换对象存储只动这个类。
- **发了就能看到。** 本期没有审核，帖子没有状态列，只有存在和已删除。
  接入大模型审核时再加状态列，默认值是已发布，不影响已有数据。

## 3. 分类

固定五个，用枚举表示，库里存枚举名。不建分类表，也没有管理界面：加一个分类本来就要同时配颜色和文案，改代码更直接。

| 枚举 | 名称 | 放什么 |
|---|---|---|
| `ANIME` | 追番 | 番剧、漫画、轻小说的讨论、推荐、观后感，动漫音乐 |
| `CREATION` | 创作 | 自己做的东西：绘画、同人文、手书、cos、手办摄影 |
| `GAME` | 游戏 | 二次元手游、Galgame、音游、主机游戏 |
| `TECH` | 技术 | 编程、建站、AI、软硬件折腾 |
| `DAILY` | 日常 | 闲聊、生活、新人报到、周边开箱，以及放不进上面的 |

- 发帖必选一个，前端默认选中日常。
- 「综合」不是分类，是不带分类条件的查询。
- 名称和颜色在前端：名称进 `locales/`，颜色进 `tokens.scss`，都按枚举名对应。

## 4. 接口

均在 content 服务，均需登录；`/content/admin/**` 还要求管理员角色。

| 接口 | 用途 |
|---|---|
| `POST /content/images` | 上传一张配图，返回图片 id 和地址 |
| `GET /content/files/{name}` | 读取图片文件 |
| `POST /content/posts` | 发帖 |
| `GET /content/posts` | 帖子流，参数 `category`（可空）、`sort`、`page`、`size` |
| `POST /content/admin/search/rebuild` | 管理员触发异步索引重建；重复请求合并 |
| `POST /content/admin/hot/rebuild` | 管理员触发异步热榜重算；重复请求合并 |
| `GET /content/search/posts` | 搜帖子，参数 `q`、`category`（可空）、`sort`、`page`、`size`，见第 17 节 |
| `GET /content/posts/{id}` | 帖子详情，同时计一次浏览 |
| `PUT /content/posts/{id}` | 改帖，仅作者 |
| `DELETE /content/posts/{id}` | 删帖，仅作者 |
| `PUT /content/posts/{id}/like` | 喜欢 |
| `DELETE /content/posts/{id}/like` | 取消喜欢 |
| `PUT /content/posts/{id}/favorite` | 收藏 |
| `DELETE /content/posts/{id}/favorite` | 取消收藏 |
| `POST /content/comment-images` | 上传一张评论配图，返回图片 id 和地址 |
| `GET /content/posts/{id}/comments` | 一级评论，分页，新的在前；每条带回复总数，不带回复 |
| `GET /content/comments/{id}/replies` | 某条一级评论下的回复，分页，旧的在前 |
| `POST /content/posts/{id}/comments` | 发评论或回复 |
| `DELETE /content/comments/{id}` | 删评论，仅评论作者 |
| `PUT /content/comments/{id}/like` | 赞一条评论或回复 |
| `DELETE /content/comments/{id}/like` | 取消赞 |
| `POST /content/reports` | 举报一条帖子或评论 |
| `GET /content/admin/reports` | 管理员分页查举报，可按状态筛 |
| `POST /content/admin/reports/{id}/acceptance` | 管理员认定举报成立，删除被举报的内容 |
| `POST /content/admin/reports/{id}/rejection` | 管理员驳回举报 |
| `GET /content/tags` | 标签联想，参数 `keyword`（可空）、`size` |
| `GET /content/posts/mine` | 我发布的帖子，分页，按发布先后倒序 |
| `GET /content/creator/overview` | 我的数据汇总：帖子数和浏览、喜欢、评论、收藏的累计值 |
| `GET /content/creator/trend` | 我的每日趋势，参数 `days`（7 或 30） |
| `GET /content/creator/top-posts` | 我的帖子按热度分倒序的前 5 条 |
| `GET /content/drafts` | 我的草稿列表，按最近修改倒序 |
| `GET /content/drafts/{id}` | 一份草稿的全部内容，仅本人 |
| `POST /content/drafts` | 新建草稿 |
| `PUT /content/drafts/{id}` | 覆盖保存草稿，仅本人 |
| `DELETE /content/drafts/{id}` | 删草稿，仅本人 |

- 喜欢、收藏和评论的赞用 `PUT` / `DELETE`，重复调用结果相同，不报错。
- 帖子流的每一项：id、分类、标题、摘要、前 5 张配图的缩略图地址、配图总数、浏览数、喜欢数、评论数、收藏数（`favoriteCount`，按当前页帖子批量统计收藏记录）、
  当前用户是否喜欢和收藏、IP 属地、发布时间、作者（id、展示名、头像、等级）。
- 详情在此基础上加正文原文、全部配图、封面和标签。没有单独上传封面时，封面是第一张配图；一张图都没有时为空。
- 发帖和改帖的请求体：分类、标题、正文、配图 id 列表（顺序即展示顺序）、封面图片 id（可空）、标签名列表（可空）。
  发帖时还可以带草稿 id：发布成功的同一个事务里删掉这份草稿。
- 帖子流的每一项目前不带封面和标签，主页用不到。以后做需要封面的列表（例如某人喜欢的帖子）时再加字段。
- 标签联想：`keyword` 为空时返回最常用的标签，不为空时按前缀匹配，都按使用次数倒序；`size` 默认 10、最大 20。
- 草稿的请求体和发帖相同，但每一项都可以空着，只要求标题和正文至少有一样不为空。草稿列表的每一项：id、分类（可空）、标题、正文开头的一小段、前 5 张配图的缩略图地址、配图总数、最近修改时间。
- 「我发布的帖子」的每一项：id、分类、标题、摘要、封面的缩略图地址、发布时间，以及浏览、喜欢、评论、收藏数。
  没有单独上传封面时用第一张配图，一张图都没有时为空。
- 数据汇总是把我所有未删除帖子的计数加起来，收藏数统计收藏记录；不从每日统计表里求和。
- 每日趋势返回连续的 `days` 天，每天一项：日期、当天新增的浏览、喜欢、评论、收藏数、当天发布的帖子数。
  没有数据的日子由后端补成 0，前端拿到的一定是不缺天的序列。日期按 Asia/Taipei 划分。
- 帖子表现的每一项：id、标题、热度分。不随 `days` 变化，用的是帖子当前的热度分。
- 这四个创作中心接口只返回当前登录用户自己的数据，没有「看别人的」参数。
- 发评论的请求体：正文（可空）、配图 id 列表（可空）、回复时被回复的那条评论的 id。正文和配图至少有一样。
  被回复者是谁由后端从那条评论读出，不由前端传。
- 评论和回复的每一项：id、正文、配图（原图和缩略图地址、尺寸）、赞数、当前用户是否赞过、IP 属地、发布时间、
  作者（id、展示名、头像、等级）、是不是帖子作者。一级评论另带回复总数；回复另带被回复者的 id 和展示名。
- 发评论成功返回新建的这一条，结构同上；删评论成功返回帖子最新的评论数。
- 举报的请求体：对象类型（帖子或评论）、对象 id、理由、补充说明（可空）。
- 举报列表的每一项：举报 id、对象类型和 id、对象内容（帖子给标题和摘要，评论给正文和配图地址）、对象是否已删除、
  对象作者和举报人（id、展示名）、理由、补充说明、举报时间、状态、处理人和处理时间。
- [contracts.md](contracts.md) 里给 ai 用的两个内部接口，等 ai 服务开始做的时候再实现。

### 4.1 分页与排序

- 按页码分页：`page` 从 1 开始，`size` 默认 10、最大 50；返回当前页数据和总条数。
- 一级评论按发布先后倒序，回复按发布先后正序，都不提供别的排序。
- `sort=LATEST`：按发布先后倒序。
- `sort=HOT`：只取近 7 天发布的帖子，按热度分倒序，同分按发布先后倒序。读的是 Redis 里的榜单，见第 16 节。
- 热度分是 `post` 表的一列，在浏览、喜欢、收藏、评论数变化的同一条更新或同一个事务里按权重加减。
  起步权重：浏览 1、喜欢 4、评论 3、收藏 5，放 Nacos 配置。改权重后，近 7 天的帖子在下一次重算时按新权重算，更早的不回算。

## 5. 数据表

库 `meng_content`。除特别说明外，每张表都有 `id`（BIGINT 自增）、`create_time`、`update_time`、`delete_state`。

### 5.1 `post`

| 字段 | 说明 |
|---|---|
| `author_id` | 作者的用户 id |
| `category` | 分类枚举名 |
| `title` | 标题，1 到 50 个字 |
| `content` | 正文，Markdown 原文，1 到 10000 个字 |
| `summary` | 摘要，保存时生成 |
| `image_count` | 配图总数，不含封面 |
| `cover_image_id` | 可空。单独上传的封面 |
| `view_count`、`like_count`、`comment_count` | 冗余计数 |
| `hot_score` | 热度分 |
| `ip_region` | 发帖时的 IP 属地，可空 |

索引：`(category, id)` 给分类筛选；`(create_time)` 给热门的时间窗口。

### 5.2 `post_image`

| 字段 | 说明 |
|---|---|
| `uploader_id` | 上传者 |
| `post_id` | 可空。上传时为空，发帖或改帖时填上 |
| `file_name` | 原图的文件名，随机生成，唯一索引 |
| `thumb_name` | 缩略图的文件名 |
| `width`、`height` | 原图尺寸，前端用来占位，避免加载时跳动 |
| `sort` | 在帖子里的顺序 |
| `kind` | 用途枚举：配图、封面。挂到帖子上时确定 |

- 每帖最多 10 张配图，另可有一张封面；单张不超过 5 MB；只接受 JPEG、PNG、WebP、GIF，按文件头判断，不信扩展名。
- 上传时生成一张宽 480 的缩略图，帖子流只用缩略图。
- 只能把自己上传、还没挂到别的帖子上的图片挂到帖子上。同一张图不能既是配图又是封面。
- 保存下来的文件不能带拍摄地点这类元数据：JPEG 和 PNG 保存前重新编码，WebP 去掉 EXIF 和 XMP 数据块，GIF 原样保留。
- 改帖时被移除的图片逻辑删除。上传后一直没挂到帖子上的图片本期不清理（见第 14 节），
  以后加清理任务时要放过被草稿引用的图片。

### 5.3 `post_like`、`post_favorite`

两张表结构相同：`post_id`、`user_id`、`create_time`，`(post_id, user_id)` 唯一索引，另有 `(user_id, id)` 索引。

这两张是关系表，**取消时物理删除，不带 `update_time` 和 `delete_state`**。
理由：逻辑删除会和唯一索引冲突，而且取消的记录没有任何地方会再用到。

### 5.4 `comment`

| 字段 | 说明 |
|---|---|
| `post_id` | 所属帖子 |
| `author_id` | 评论作者 |
| `root_id` | 一级评论为 0；回复填所属一级评论的 id |
| `reply_to_comment_id` | 可空。回复的是哪一条 |
| `reply_to_user_id` | 可空。被回复者，由后端从被回复的评论读出 |
| `content` | 纯文本，最多 500 个字；有配图时可以为空 |
| `image_count` | 配图数 |
| `like_count` | 赞数 |
| `reply_count` | 仅一级评论使用，它下面的回复数 |
| `ip_region` | 评论时的 IP 属地，可空 |

索引：`(post_id, root_id, id)`。

- 只有两层：一级评论，和挂在一级评论下面的回复。回复别人的回复时仍挂在同一条一级评论下，用 `reply_to_user_id` 标明对象。
- 评论是纯文本，不解析 Markdown。正文和配图至少有一样，可以只发图。
- 表情写在正文里，记号是 `[表情:名字]`，名字 1 到 12 个字，不含空白和方括号。记号算进 500 个字，与配图合计每条最多 10 个。
  后端只校验写法和个数，不管这个名字有没有对应的图；有哪些表情由前端的内置清单决定（见第 12.3 节）。
- 页面上的「@谁」不是正文的一部分，来自 `reply_to_user_id`。正文里手打的 `@` 只是普通文字。
- 删一条回复只删它自己。删一级评论时只标记这一条，它下面的回复行不改动，但从此都查不出来：
  一级评论列表不返回它，它的回复列表按不存在处理，对它和它下面任何一条的赞、回复、举报都按已删除处理。
- 已删除的评论不留占位。

### 5.5 `tag`、`post_tag`

`tag`：

| 字段 | 说明 |
|---|---|
| `name` | 展示用的写法，取第一次创建时的输入 |
| `name_key` | 归一化后的值，唯一索引，查重和联想都用它 |
| `use_count` | 被多少条帖子使用 |

`post_tag`：`post_id`、`tag_id`、`create_time`，`(post_id, tag_id)` 唯一索引，另有 `(tag_id, post_id)` 索引。
它和喜欢、收藏一样是关系表，摘掉时物理删除。

- 标签由用户自己输入，输入时先联想已有的；提交的标签不存在就新建。
- 归一化：去首尾空格、全角转半角、转小写。归一化后相同的算同一个标签。
- 每帖最多 5 个；每个 1 到 12 个字，不能含空白和 `#`。
- 帖子挂上一个标签，它的使用次数加一；改帖摘掉或删帖时减一。和帖子的写入在同一个事务里。
- 两个人同时新建同一个标签，靠唯一索引挡住，冲突的一方改为使用已有的那条。
- 本期标签只在帖子详情里显示，不能按标签筛选。

### 5.6 `post_draft`

草稿单独一张表，不和帖子混在一起：草稿允许缺标题缺正文，不进帖子流、不计数、不发事件，
分开放就不用在每一条帖子查询里排除它。

| 字段 | 说明 |
|---|---|
| `author_id` | 谁的草稿 |
| `category` | 可空 |
| `title` | 可空，最多 50 个字 |
| `content` | 可空，最多 10000 个字 |
| `image_ids` | 配图 id 列表，JSON |
| `cover_image_id` | 可空 |
| `tags` | 标签名列表，JSON。保存草稿不新建标签 |

索引：`(author_id, id)`。

- 每人最多 20 份。存满后新建被拒，覆盖保存已有的不受影响。
- 草稿引用的图片仍是「没挂到帖子上」的状态，发布时才挂上去。
- 从草稿发布：发帖请求带草稿 id，帖子写入成功的同一个事务里把草稿逻辑删除。草稿必须是本人的。
- `post_draft_owner` 以 `author_id` 为主键；保存、删除、从草稿发布先锁定本人的这一行，避免并发创建突破 20 份上限或重复发布。
- 改已发布的帖子不产生草稿。改帖页不显示保存草稿按钮；未单独设置封面时仍使用第一张配图，移除封面后恢复这个默认值。

### 5.7 `comment_image`

| 字段 | 说明 |
|---|---|
| `uploader_id` | 上传者 |
| `comment_id` | 可空。上传时为空，发评论时填上 |
| `file_name` | 原图的文件名，随机生成，唯一索引 |
| `thumb_name` | 缩略图的文件名 |
| `width`、`height` | 原图尺寸 |
| `sort` | 在评论里的顺序 |

- 每条评论的配图和表情合计最多 10 个。大小、格式、文件头判断、缩略图、去元数据都和帖子配图相同（见第 5.2 节），用同一个存储类，读取也走 `GET /content/files/{name}`。
- 只能把自己上传、还没挂到别的评论上的图片挂到评论上。帖子配图和评论配图互不通用。
- 评论不能修改，所以没有「移除图片」；删评论时图片跟着逻辑删除。上传后没挂上去的图片和帖子配图一样本期不清理。

### 5.8 `comment_like`

`comment_id`、`user_id`、`create_time`，`(comment_id, user_id)` 唯一索引。一级评论和回复都能赞。
和帖子的喜欢一样是关系表，取消时物理删除，不带 `update_time` 和 `delete_state`。

### 5.9 `report`

| 字段 | 说明 |
|---|---|
| `reporter_id` | 举报人 |
| `target_type` | 对象类型枚举：帖子、评论（回复也算评论） |
| `target_id` | 对象 id |
| `reason` | 理由枚举：违规内容、引战辱骂、广告、剧透、其他 |
| `note` | 补充说明，可空，最多 200 个字 |
| `status` | 状态枚举：待处理、已处理、已驳回 |
| `handler_id` | 可空。处理的管理员 |
| `handle_time` | 可空。处理时间 |

索引：`(reporter_id, target_type, target_id)` 唯一；`(status, id)` 给管理端列表；`(target_type, target_id)` 给一并处理。

- 同一个人对同一个对象只能举报一次；不能举报自己的帖子和评论；对象不存在或已删除时不能举报。
- 状态只能由管理员从待处理改成已处理或已驳回，改完不能再动。
- 认定成立：按作者自己删除的同一套规则删掉对象（计数、标签使用次数、配图都照常处理），
  把这条举报和同一对象的其他待处理举报一起改成已处理，全部在一个事务里。对象已经不存在时只改状态。
- 驳回：只改这一条的状态，内容不动。
- 举报不会让内容自动隐藏。处理完成后发 `report.handled`，由消息域通知举报人；认定成立时也通知内容的作者，不透露举报人。举报记录不删除。

### 5.10 `author_daily_stat`

创作中心趋势图的数据。一行是某个作者某一天收到的互动。

| 字段 | 说明 |
|---|---|
| `author_id` | 帖子作者 |
| `stat_date` | 日期，按 Asia/Taipei 划分 |
| `view_count`、`like_count`、`comment_count`、`favorite_count` | 当天新增的浏览、喜欢、评论、收藏 |

索引：`(author_id, stat_date)` 唯一。只有 `id`、`create_time`、`update_time`，不带 `delete_state`：这张表只增不删。

- 浏览计数成功、喜欢或收藏的关系行插入成功、评论写入成功时，在同一个事务里给帖子作者当天那一行加一。
  用「不存在就插入、存在就在原值上加」的一条语句，不先查后改。
- 取消喜欢、取消收藏时，如果被删掉的那条关系是当天建立的，当天那一行减一，最小减到 0；不是当天建立的不动。
  这样反复点亮再取消不会把数字刷高，也不会去改以前的日子。
- 删评论、删帖都不回减，已经过去的统计不改。
- 自己看、自己赞、自己评自己的帖子照常计入，和帖子上的计数规则一致。
- 这张表从上线那天才开始有数据，之前的互动不补。

## 6. 计数规则

| 计数 | 规则 |
|---|---|
| 浏览 | 打开详情时计。同一个人同一帖 24 小时内只算一次，用 Redis 键判重，判重通过后直接给帖子的浏览数加一。作者看自己的帖子也算 |
| 喜欢 | 关系行插入成功加一，删除成功减一 |
| 评论 | 评论和回复都算。发一条加一；删一条回复减一；删一级评论减去一加它的回复数。帖子的热度分按同样的条数加减 |
| 回复 | 一级评论的回复数：发一条回复加一，删一条回复减一 |
| 评论的赞 | 关系行插入成功加一，删除成功减一。不加经验，不计入帖子热度 |
| 收藏 | 没有计数列，收藏数按帖子统计收藏记录。关系行插入或删除成功时，同一个事务里按收藏的权重加减热度分 |

- 加减和关系行、评论行的写入在同一个事务里。
- 计数用「在原值上加减」的更新，不先查后改。

## 7. IP 属地

- 客户端 IP 取网关注入的 `X-Client-IP`，不读前端传的任何值。
- 用离线库 ip2region 在发帖和评论时解析，结果存成文字，之后不再变。
- 只显示到国家或地区一级，例如台湾、香港、日本。解析不出来就存空，前端不显示这个标记。
- 不保存原始 IP。

## 8. Redis 键

| 键 | 内容 | 有效期 |
|---|---|---|
| `content:viewed:{postId}:{userId}` | 浏览判重 | 24 小时 |
| `content:limit:*` | 限流计数 | 见第 9 节 |
| `content:hot:*` | 热榜的两套榜单、生效指针、重算标记和锁 | 见第 16.2 节 |
| `content:search:building`、`content:search:lock` | 搜索索引重建的标记和锁 | 30 分钟 |

实际键名加项目前缀。

## 9. 限流

按用户维度，阈值放 Nacos 配置。评论与举报使用 `comment-interval`、`report-interval`、`reports-daily`，评论配图使用 `comment-uploads-daily`；评论热度权重使用 `comment-weight`。

| 场景 | 起步取值 |
|---|---|
| 发帖 | 每人 60 秒一条，每天最多 20 条 |
| 评论 | 每人 10 秒一条 |
| 上传图片 | 每人每天最多 100 张 |
| 上传评论配图 | 每人每天最多 100 张，和帖子配图分开计 |
| 举报 | 每人 10 秒一次，每天最多 30 次 |
| 保存草稿 | 每人 3 秒一次 |
| 搜索 | 每人每分钟最多 30 次 |

## 10. 权限与错误语义

- 改帖、删帖只允许作者本人；删评论只允许评论作者本人；草稿只有本人能看、能改、能删。身份只来自网关注入的请求头。
- 帖子作者不能删别人在自己帖子下的评论。
- 管理员只能通过处理举报来删除内容，网关和 Service 各校验一次管理员角色。没有被举报的内容仍然没有下架入口，这是已知缺口。

| 情况 | HTTP 状态 |
|---|---|
| 参数不合法、图片类型或大小不符、配图超过 10 张、标签超过 5 个或写法不合规 | 400 |
| 评论的正文和配图都为空、表情和配图合计超过 10 个；举报自己的内容 | 400 |
| 搜索词为空或超过 50 个字；搜索翻到第 10000 条以后 | 400 |
| 未登录 | 401 |
| 改或删别人的帖子、评论；读写别人的草稿；挂别人上传的图片；不是管理员却访问 `/content/admin/**` | 403 |
| 帖子、评论、草稿或举报不存在、已删除 | 404 |
| 草稿已经存满 20 份还要新建；重复举报同一个对象；处理一条已经处理过的举报 | 409 |
| 触发限流 | 429 |

- 评论已删除时（包括它所属的一级评论已删除）返回 404，错误码用单独的 `CONTENT_COMMENT_DELETED`，前端靠它给出「评论已被删除」的提示。
- 重复举报的错误码是 `CONTENT_REPORT_DUPLICATE`，前端提示已经举报过。

## 11. 事件

事件定义见 [contracts.md](contracts.md)。本期只发有消费者的两个：

| 事件 | 时机 | 本期的消费者 |
|---|---|---|
| `post.published` | 发帖事务提交后 | growth：加经验 |
| `comment.created` | 评论事务提交后 | growth：加经验 |

消息域开始做的时候再发这四个，喜欢、收藏、评论点赞只在点亮时发，取消不发：

| 事件 | 时机 | 消费者 |
|---|---|---|
| `post.liked` | 喜欢帖子的事务提交后 | im：通知作者 |
| `post.favorited` | 收藏帖子的事务提交后 | im：通知作者 |
| `comment.liked` | 评论点赞的事务提交后 | im：通知评论作者 |
| `report.handled` | 管理员处理举报的事务提交后 | im：通知举报人和内容作者 |

`comment.created` 同时补上父评论 id 和评论摘要，给消息域拼通知用。

`post.updated`、`post.deleted` 的消费者是 ai，等它开始做的时候再发。

### 12.2 主页的组成

| 部分 | 说明 |
|---|---|
| 页面骨架 | 顶部导航（品牌、四个入口、搜索、消息、等级条、头像）和通栏底栏，做成布局，其他登录后的页面共用 |
| 横幅 | 整幅插画、欢迎卡片、对话气泡和贴纸 |
| 分类与排序条 | 「综合」加五个分类，右侧「最新 / 热门」，两者互相独立 |
| 帖子卡片 | 作者行（头像、展示名、等级、发布时间、IP 属地）、分类标、标题、摘要、配图、操作行（浏览、喜欢、评论、收藏） |
| 配图格 | 最多显示 5 张；超过 5 张时第五张盖一层蒙层，写上还剩多少张 |
| 翻页条 | 固定七个位置，页数多时用省略号；不超过七页时全部显示。右侧是回到顶部 |
| 右栏 | 签到卡片、萌萌入口卡片 |

- 帖子操作行从左到右是浏览、喜欢、评论和收藏图标与数量，最右侧显示帖子类型，标题前不再重复显示类型。喜欢与收藏数量随操作即时更新，请求失败时恢复。
- 最新 / 热门通过滑动底色切换。分页按钮有悬浮和按压反馈，回顶部按钮仅显示文字；减少动态效果时关闭动画。
- 右侧两张功能卡片随页面滚动，每张右上角可收起为对应图标的圆形气泡，再次点击展开。全部收起时帖子区域平滑扩宽，任一卡片展开时恢复侧栏宽度。收起不会丢失签到状态。窄屏仍使用上下排布。
- 聊天和发帖卡片不使用外部蓝色阴影；展开时的收起图标无圆形底色，与卡片边缘保留间距。
- 图片预览挂载到页面根部，避免卡片动画影响全屏定位；缩放和拖动图片不会增加页面横向滚动范围。
- 搜索仅实现悬浮展开、图标随输入框移动和移开收缩的交互；键盘焦点可展开；回车提交后进入搜索结果页（见第 12.7 节），输入为空时不提交。
- 主页和帖子详情页隐藏页面滚动条，保留滚轮、触控、键盘和回到顶部的滚动功能；离开相应页面时恢复其他页面的默认滚动条。
- 主页使用最大 1600px 的宽屏容器和自适应侧边留白，导航、横幅、帖子与侧栏以及页脚内容保持对齐。横幅带高透明白色遮罩，底部三层海浪使用单个 Canvas 按时间连续改变波峰与振幅，移出视口或页面不可见时暂停，减少动态效果时静止。导航入口使用独立彩色圆形图标底色，成长进度条上方靠右显示经验数字（当前 / 下一级阈值），满级时仅显示当前经验；窄屏保留等级胶囊。页脚含品牌、云朵线稿、条款和联系入口；联系功能尚未开放。
- 桌面端帖子流与右栏独立排布，右栏在可容纳全部卡片的视口中吸附；窄屏或低矮视口恢复普通文档流。
- 喜欢和收藏先在界面上变，请求失败再变回来并提示。
- 帖子流的四种状态：加载中、出错（带重试）、空（「这里还空空的」）、未登录（由路由守卫处理）。
- 相对时间（「3 分钟前」）由前端根据发布时间算。

### 12.3 帖子详情的组成

| 部分 | 说明 |
|---|---|
| 页面骨架 | 和主页共用顶部导航；不带底栏，不带右栏。背景和顶部导航保持不动，正文区是一张居中的卡片，最宽 1350、高度适应剩余视口，帖子和评论在卡片内部上下滚动，滚动条隐藏；滚轮、触控和键盘均可滚动卡片 |
| 作者行 | 最左是圆形的返回按钮，回到主页时保留原来的分类、排序和页码；然后是头像、展示名、等级；最右是发布时间和 IP 属地 |
| 标题与正文 | 标题带荧光笔底纹，前面不放分类标；正文是渲染后的 Markdown |
| 配图 | 全部配图排成格子，每张带白边、轻微歪斜，悬浮时摆正并抬起 |
| 标签 | 配图下面一行，每个是「# 名字」的小药丸，不可点 |
| 操作行 | 左边是浏览、喜欢、评论（点了滚到评论区）、收藏。右边：作者本人是编辑、删除，其他人是举报；最右是分类标 |
| 评论区标题行 | 「评论」加总数，右侧是「写评论」按钮 |
| 评论输入区 | 默认收起。从上到下：回复对象标记、右上角已选表情与图片、多行输入、表情面板、工具行（表情、图片、发送） |
| 一级评论 | 头像、展示名、等级、作者标，右侧是时间和属地；下面是正文和配图；操作行是赞、回复、「N 条回复」开合，本人多出删除，别人的评论最右是举报 |
| 回复区 | 挂在一级评论下面的浅色块。每条有小头像、展示名、作者标，右侧是时间和属地；正文开头是「@谁」标记；正文右侧是赞、回复、竖线，然后本人是删除、别人是举报 |
| 翻页 | 一级评论的翻页条居中，两侧是虚线和小装饰 |
| 举报弹窗 | 五个理由单选、一个可以不填的说明输入框、取消和提交 |

帖子：

- 封面不在详情页显示。
- 配图点开看大图用 Element Plus 的图片预览，可以左右切换；评论配图同样处理。
- 删帖先用 `ElMessageBox.confirm` 确认，成功后回到主页。
- 帖子不存在或已删除时显示空状态和回主页的入口。
- 卡片边缘保留设计稿的胶带、颜文字气泡、星星、小花和泡泡，不拦截点击；窄屏隐藏探出卡片的装饰，减少动态效果时停止动画。配图宽屏一行五张，窄屏一行两张；所有配图共用全屏预览组件。固定背景使用 `article_detail_background.png`，宽度不超过 760 时使用 `article_detail_background_mobile.png`，居中等比铺满视口，按窗口比例裁切边缘、不随内容滚动；中间卡片使用 92% 不透明度的白底，正文保持不透明。泡泡和花朵使用参考页导出的矢量素材。

评论输入区：

- 只有这一个输入区，发一级评论和回复都用它。点「写评论」展开，按钮变成「收起」。
- 点任何一条评论或回复的「回复」：展开输入区、把焦点放进去，顶部出现「@谁」标记。点标记上的叉变回发一级评论。
- 输入框多行、随内容增高，上限 500 个字，计数方式和发帖页相同。
- 点「图片」选图，选中即上传，复用发帖页的上传逻辑；已传的图和已选表情排列在评论框内部右上角，每个可移除，末尾是添加格和合计「n / 10」。有附件时文字输入区在下方另起一行。也可以粘贴图片。
- 点「表情」展开表情面板，点一个加入右上角的预览；发送时转换为正文末尾的表情记号，发出去后行内显示成图片。直接输入的记号同样计入合计上限。
- 正文和图片都为空时「发送」不可用；发送中按钮置为加载。
- 发送成功后清空并收起。一级评论插到列表最前面；回复插到所在那一楼的末尾，并把这一楼展开。
- 有没发出去的内容时收起输入区，内容保留；离开页面不提示。
- 评论输入区、表情面板和楼内回复使用平滑展开与收起动画；切换回复对象时标记淡入淡出，喜欢和收藏图标切换填色并轻微弹动，按钮有悬浮与按压反馈。关闭的面板不可聚焦，收起不丢失输入内容或已加载的回复；系统要求减少动态效果时关闭动画。
- 详情正文与首屏评论并行请求，评论区复用首屏请求，失败后可单独重试；翻页和写操作后仍从接口获取最新内容。评论输入区在首次展开时挂载，收起后保留。主页悬浮或聚焦帖子卡片时预加载详情页代码，节省流量模式或慢速网络不预加载，也不会提前计浏览量。桌面背景按视口与像素密度选择 1600 或 2560 宽的 WebP，移动端使用独立背景；配图与表情使用原生懒加载和异步解码。

评论列表：

- 一级评论每页 10 条，带赞数、是否赞过、回复数，不带回复。
- 「N 条回复」默认收起，箭头朝下；点开时请求第一页回复（10 条），箭头转成朝上；楼内还有更多时底部显示「还有 N 条回复」，点了加载下一页。没有回复的评论不显示这个按钮。
- 帖子作者在评论区里带「作者」标。
- 赞先在界面上变，请求失败再变回来并提示。
- 删评论先用 `ElMessageBox.confirm` 确认；成功后这一条从页面上消失，删的是一级评论时它的回复一起消失，评论总数按接口返回的新值更新。
- 页面打开期间别人删掉的评论不会自己消失。对它点赞、回复、举报时接口返回 `CONTENT_COMMENT_DELETED`，前端提示「评论已被删除」，仍不从页面上移除。
- 评论区的四种状态：加载中、出错（带重试）、空（「还没有人说话」）、未登录（由路由守卫处理）。

表情：

- 表情是前端内置的一组图片。清单（名字和对应的图片）放 `src/constants/`，图片放 `assets/` 并从 `assets/images.js` 引入。
- 渲染评论正文时把正文切成文字段和表情段：文字段按纯文本输出，表情段换成图片，行内显示，边长 56。清单里没有的名字原样显示成文字。
- 这里不用 `v-html`。评论正文不经过 Markdown 渲染组件。
- 起步清单用仓库里现有的五张小图占位，不新增图片文件：`userAvatar`「头像」、`mengAvatar`「萌萌」、
  `articleEditAvatar`「写帖」、`resetAvatar`「找回」、`brandIcon`「水滴」。正式的表情图到位后换掉这份清单；
  换名字以后，旧评论里用旧名字写的记号会原样显示成文字。

举报：

- 自己的帖子、评论、回复不显示举报入口。
- 弹窗用 Element Plus 的对话框，外观按设计稿。没选理由时「提交」不可用；说明最多 200 个字。
- 提交成功后关闭弹窗并提示已收到；重复举报时提示已经举报过，同样关闭弹窗。

### 12.4 发帖页的组成

| 部分 | 说明 |
|---|---|
| 页面骨架 | 不带顶部导航和底栏，整页是一张大卡片；卡片右上有「回到主页」 |
| 顶部区域 | 页面标题，下面一行左边是分类五选一（默认日常），右边是标题输入框，框内右侧显示字数 |
| 左下约七成 | 正文。标题行右侧是字数进度条和字数；工具栏是七个格式按钮、「AI 激发灵感」、「编辑 / 预览」切换；下面是编辑区 |
| 右侧约三成 | 从上到下三张卡片：配图（可切到视频）、封面、标签 |
| 配图卡片 | 一行五格、固定两行十个位置：已传的图、一个添加格、其余是空位；右上角显示张数 |
| 封面卡片 | 一个 16:9 的上传框；标题行右侧是「AI 生成封面图」 |
| 标签卡片 | 标题旁是个数，右侧是「AI 挑选标签」；已选标签放在固定高度的框里，多了在框内滚动但不显示滚动条；下面是输入框和三个独立的 AI 推荐标签占位 |
| 底部 | 左边「保存为草稿」，右边「发布」 |

卡片边缘保留设计稿的对话贴纸、小泡泡、花朵与星光，轻微浮动且不拦截点击；窄屏隐藏侧边装饰，减少动态效果时停止动画。配图不显示额外上传提示文案，视频占位的图标与文字作为一组居中。

配图与视频切换时选中底色左右滑动，内容轻微淡入淡出；标签添加、移除及重新排布带过渡。上传格、AI 入口、格式工具、返回与保存发布按钮提供轻微悬浮和按压反馈，输入框聚焦时描边柔和变化；减少动态效果时缩短这些过渡。

页面底色为纯白，背景仅保留小范围、低透明度的浅蓝液体流动，鼠标移动产生柔和扰动；编辑卡片为极浅水蓝底色并带细描边，正文输入区保留白底。液体只随发帖路由加载，速度与蓝色浓度分别平流，加入受限的旋涡力与逐渐消散；模拟长边不超过 256 像素，窄屏降到 160，按固定 30 步每秒计算，显示插值到最多 60 帧每秒，输出长边不超过 960。压力求解每步 8 次，纹理按速度双通道、浓度与压力单通道存储，卡顿时最多补算两步，避免积压。切到后台暂停，离开发帖页释放 WebGL 资源；减少动态效果或不支持浮点渲染时保留静态背景，不影响表单。模拟方法参考 [NVIDIA GPU Gems 的流体章节](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-38-fast-fluid-dynamics-simulation-gpu)；限制输出分辨率参考 [Three.js 的响应式渲染说明](https://threejs.org/manual/pages/responsive.html)。

正文：

- 编辑区用 CodeMirror 6 写 Markdown 源码，只在进入发帖页时加载。配色、字体、圆角都取设计变量，不用它自带的主题。
- 编辑区的高度和右栏对齐，内容超出后在编辑区内部滚动。
- 宽屏（宽度大于 1100、可用高度至少 700）时卡片最宽 1280，高度随视口调整，保存与发布按钮保持在一屏内；正文、标签及联想项在内部滚动。窄屏或较矮窗口采用自然纵向排列，保证所有操作可达。
- 格式按钮在光标处插入对应的 Markdown 标记，选中了文字就把标记包在两边。
- 字数按 Unicode 码点计，前端的计数和后端的校验用同一种算法。进度条到上限时填满。

配图和封面：

- 自己写上传格，不用 Element Plus 的上传组件。可以点添加格选图，也可以把图片拖进卡片或直接粘贴。
- 选中即上传，同时最多传三张，方格里显示进度，失败的方格可以重试或移除。
- 上传前在浏览器里把静态图的长边缩到不超过 2560，GIF 不处理。
- 没有单独上传封面时，封面框里显示第一张配图并标明是默认的。
- 「视频」只是占位：能切过去看到一个占位框，点了提示还没开放。

标签：

- 输入时请求联想接口，带 300 毫秒防抖，只匹配系统已有标签，已选标签不再推荐，完全匹配项优先。仅有匹配结果且输入框聚焦时显示下拉菜单，点击或上下键配合回车选中；没有匹配时不显示空菜单，仍可回车添加新标签。快速输入时旧请求结果不会覆盖新输入。不自动加载常用标签，AI 推荐位置独立展示三个静态占位，不可点击，待 AI 域接入。
- 选满 5 个后输入框和联想项不可用。

草稿和发布：

- 「保存为草稿」把当前内容存到服务器：这一页还没对应草稿时新建，之后都是覆盖保存。
- 从草稿进来再点「发布」，请求带上草稿 id。
- 校验提示沿用登录注册页的写法：红字放在输入框内部，不在下方另起一行。
- 发布中按钮置为加载；成功后进入这条帖子的详情页。
- 有没保存的改动就离开页面（包括点「回到主页」、后退、关标签页），先确认。
- 三个 AI 入口本期都只提示还没开放。

### 12.5 Markdown

- 渲染用 markdown-it，结果用 DOMPurify 过滤后才放进页面，这是全项目唯一允许 `v-html` 的地方，封装成一个组件。
- 关闭原始 HTML 和图片语法；链接只允许 `http` 和 `https`，新窗口打开并带 `rel="noopener noreferrer nofollow"`。
- 发帖页的预览和详情页用同一个渲染组件。
- 代码块高亮用 highlight.js，只注册常用的几种语言，其余按纯文本显示。
- 正文样式按详情页设计稿：小标题前面有一条浅蓝色的圆角竖条；引用块是浅底圆角块，左上角有粉色引号；
  行内代码是浅蓝底的小圆角块；代码块是深色底；链接带粉色波浪下划线。

### 12.6 管理端的举报处理页

管理端没有设计稿，沿用注册申请列表的做法：Element Plus 默认样式的表格，上方按状态筛选，下方分页。

- 路由 `/reports`，侧边导航加一个入口。默认只看待处理。
- 列：对象类型、对象内容、对象作者、举报人、理由、补充说明、举报时间、状态、操作。
- 对象内容：帖子显示标题，评论显示正文开头；点开能看全文和配图。对象已经被删除时标明已删除。
- 操作只在待处理的行上出现：「删除内容」和「驳回」，都先用 `ElMessageBox.confirm` 确认，处理中按钮不可用。
- 认定成立后，同一对象的其他待处理举报也会变成已处理，列表按接口返回的结果刷新。
- 列表的四种状态：加载中、出错（带重试）、空、未登录或不是管理员（由路由守卫处理）。

## 13. 验收点

发帖与帖子流：

- 发帖后出现在「综合」和所选分类的最前面，别的分类里没有。
- 标题、正文超长，没选分类，配图超过 10 张，请求被拒。
- 「热门」里没有 7 天前的帖子；给一条帖子点喜欢后，它在热门里的位置上升。
- 翻页的总条数和实际一致；`size` 超过上限被拒或按上限处理。

喜欢、收藏、浏览：

- 连点两次喜欢，喜欢数只加一；取消后减一；两个人各点一次，数字是二。
- 同一个人 24 小时内打开同一帖多次，浏览数只加一。
- 帖子流里「是否喜欢、是否收藏」因人而异，换一个账号看不到别人的状态。

配图：

- 把扩展名改成 `.png` 的非图片文件传上来被拒；超过 5 MB 被拒。
- 把别人上传的图片 id 放进自己的帖子，请求被拒。
- 帖子流里加载的是缩略图。
- 上传一张带拍摄地点的照片，再把保存下来的文件取回来，里面没有拍摄地点。
- 没传封面的帖子，详情里的封面是第一张配图；传了封面的，封面不出现在配图里。

标签：

- 提交一个不存在的标签会新建；换一种写法（大小写、全角半角、首尾空格）再提交，用的是同一个标签。
- 第 6 个标签、超过 12 个字的标签、带空格或 `#` 的标签被拒。
- 改帖摘掉一个标签或删帖后，它的使用次数减一。
- 联想不带关键字时按使用次数倒序；带关键字时只返回以它开头的。

草稿：

- 只填标题或只填正文都能存成草稿；两样都空被拒。
- 存满 20 份后新建返回 409，覆盖保存已有的仍然成功。
- 读、改、删别人的草稿返回 403。
- 带草稿 id 发布成功后，这份草稿从列表里消失；发布失败时草稿还在。
- 草稿不出现在帖子流里，也不给成长加经验。

评论：

- 回复一条回复时，被回复者是那条回复的作者，前端改请求里的任何字段都改变不了它。
- 一级评论新的在前，回复旧的在前；一级评论列表里只有回复数，没有回复内容。
- 只发图不写字能发出去；正文和配图都空、第 11 个图片或表情（混合计算）被拒。
- 把别人上传的评论配图，或者帖子配图的 id，放进自己的评论，请求被拒。
- 评论数等于评论加回复的总数。删一条回复减一；删一条带 3 条回复的一级评论减四，这一条和它的回复都查不到了。
- 对已删除的评论，或者已删除的一级评论下面的回复，点赞、回复、举报都返回 404 和 `CONTENT_COMMENT_DELETED`。
- 连点两次赞，赞数只加一；取消后减一。赞评论不加经验，帖子的热度分不变。
- 正文里的 `[表情:名字]` 在详情页显示成图片，清单里没有的名字原样显示；正文里写 HTML 标签按文字显示，不执行。

举报：

- 举报自己的帖子或评论被拒；同一个对象举报第二次返回 409；对象不存在或已删除返回 404。
- 普通用户访问 `/content/admin/**` 返回 403。
- 认定成立后，帖子或评论按删除规则消失，计数相应变化；同一对象的其他待处理举报一起变成已处理。
- 驳回后内容不变。已处理或已驳回的举报再处理返回 409。
- 举报之后、处理之前，内容照常可见。

权限与安全：

- 未登录访问任何 `/content/**` 返回 401。
- 改、删别人的帖子和评论返回 403。
- 伪造 `X-Client-IP` 请求，属地不受影响。
- 正文里写脚本标签、事件属性、`javascript:` 链接，详情页都不执行。

事件：

- 发帖、评论后 growth 收到事件并加经验；事务回滚时不发事件。

热榜：

- 给一条近 7 天的帖子点喜欢、收藏、评论，或换一个账号打开它，它在「热门」里的名次立刻按权重变化；取消后变回去。
- 给一条 7 天前的帖子点喜欢，它不会出现在「热门」里。
- 帖子换分类后，从旧分类的「热门」里消失，出现在新分类里；删帖后从榜上消失。
- 手动把 Redis 里某条帖子的分数改错，重算后恢复成「计数乘权重」的值，`post.hot_score` 也一致。
- 重算进行中连续读「热门」，每次都是完整的一页，没有空榜；重算前后生效的那一套换了颜色，旧的一套被删掉。
- 把 Redis 里的热榜键全部删掉，「热门」仍然能返回（查库），随后榜单被重建。
- 停掉 Redis，「热门」仍然能返回；发帖、喜欢不报错。
- 同时启动两个 content 实例，同一时刻只有一个在重算。
- 在调度中心里能看到 `meng-content` 执行器在线和两个重建任务；手动执行一次 `contentHotRebuild`，榜单被重算，调度日志里有这次执行的记录。
- 停掉调度中心，content 照常启动，「热门」和搜索照常返回；代码里没有 `@Scheduled`。

搜索：

- 发帖后几秒内能按标题、正文、标签里的词搜到；改帖后按旧内容搜不到、按新内容搜得到；删帖后搜不到。
- `sort=HOT` 时命中的帖子按热度分倒序，给其中一条点喜欢后它的位置上升；`sort=LATEST` 时按发布时间倒序。
- 叠加分类后只返回该分类的帖子，总条数相应变化。
- 返回的片段拼起来等于标题原文；搜索词里带 HTML 标签或正文里有 HTML 标签时，结果页按文字显示。
- 搜索词为空、超过 50 个字被拒；翻到第 10000 条以后被拒。
- 停掉 Elasticsearch，按标题里的词仍然搜得到，content 的健康检查仍然通过，发帖不报错。
- 直接往库里插一条帖子（不经过接口），当时搜不到正文里的词，重建后搜得到。
- 重建进行中连续搜索，每次都有结果；重建前后别名指向的实体索引换了，旧的被删掉。
- 应用账号不能读写 `meng_post_*` 以外的索引。

创作中心：

- 「已发布」里只有我自己的帖子，换一个账号看不到别人的；已删除的帖子不出现；总数和翻页一致。
- 汇总里的五个数字等于我所有未删除帖子的计数之和，删掉一条帖子后相应减少。
- 别人浏览、喜欢、评论、收藏我的帖子后，趋势里今天对应的数字加一；别人当天取消喜欢，今天减一；取消一条昨天点的喜欢，今天和昨天都不变。
- 删掉一条今天收到的评论，趋势里今天的评论数不变。
- `days=7` 返回 7 项、`days=30` 返回 30 项，日期连续不缺；传别的值被拒。
- 在 Asia/Taipei 的零点前后各做一次互动，分别记在两天。
- 帖子表现按热度分倒序，最多 5 条，不含已删除的帖子。
- 草稿列表的每一项带分类、前 5 张配图和配图总数；没选分类、没有配图的草稿对应字段为空。
- 创作中心的图表库不出现在主页的首屏加载里。

- 标签使用次数在发布事务内更新，按归一化键顺序锁定标签，避免多个标签并发创建时锁顺序相反。联想默认返回最多 10 项。
- 帖子流返回统一响应中的 `data`：`records`、`total`、`page`、`size`。每项字段见第 4 节，其中作者展示名字段为 `author.nickname`，缩略图列表为 `images`（含图片 id、原图地址和缩略图地址）。地址为 `/content/files/...`，浏览器经 `/api` 代理读取。
- 喜欢、收藏接口成功返回 `data=null`；所有写操作沿用网关的 Cookie 与 Origin 检查。第一页可用 `GET /content/posts?sort=LATEST&page=1&size=10` 查看。
- 浏览计数和热榜事件使用短事务；作者资料的远程读取及详情组装在事务外执行，避免查询时长期占用数据库连接和帖子行锁。

- 初始化与运行见 `deploy/README.md`，长期回归脚本见 `verification/README.md`。

## 16. 热榜

「热门」排序读的榜单。MySQL 里的 `post.hot_score` 是权威数据，Redis 里的榜是它的一份读模型：平时跟着实时加减，每天重算一次。

### 16.1 分数

- 热度分 = 浏览数 × 1 + 喜欢数 × 4 + 评论数 × 3 + 收藏数 × 5。四个权重放 Nacos 配置。
- 浏览、喜欢、收藏、评论每次增减，都在数据库事务里按权重改 `hot_score`（见第 6 节），事务提交后再改 Redis 里的榜。
- 没有时间衰减，上榜范围靠「近 7 天发布」这条线控制。

### 16.2 Redis 里怎么放

| 键 | 类型 | 内容 |
|---|---|---|
| `content:hot:active` | 字符串 | 当前生效的是哪一套：`blue` 或 `green`。不过期 |
| `content:hot:{套}:ALL` | ZSet | 全站榜。成员是帖子 id，分数是热度分 |
| `content:hot:{套}:{分类枚举名}` | ZSet | 五个分类各一个榜，结构同上 |
| `content:hot:building` | 字符串 | 正在重算、还没生效的那一套。有效期 10 分钟 |
| `content:hot:lock` | 字符串 | 重算的互斥锁。有效期 10 分钟 |

- 一条帖子同时在全站榜和它所属分类的榜里，所以「热门」叠加分类时直接取对应的榜。
- 成员写成补零到 19 位的帖子 id。同分时 Redis 按成员的字典序排，补零以后字典序就是 id 的大小，倒着取出来是新帖在前，和查库排序的结果一致。
- 实际键名加项目前缀。

### 16.3 实时更新

都在数据库事务提交之后做。失败只记日志，不影响主流程，偏差留给重算纠正。

| 事件 | 对榜的操作 |
|---|---|
| 发帖 | 以 0 分加入全站榜和所属分类的榜 |
| 浏览、喜欢、收藏、评论的增减 | 给两个榜里的这条帖子加减对应的权重 |
| 改帖时换了分类 | 从旧分类的榜里移除，按数据库里的当前分数加入新分类的榜 |
| 删帖（包括举报成立） | 从两个榜里移除 |

- 加减分只改已经在榜上的成员，不在榜上的不新增（`ZADD` 带 `XX` 和 `INCR`）。
  不这样做的话，一条 7 天前的帖子被点一次喜欢，就会带着这一点分数重新上榜。
- 重算进行中（`building` 存在）时，上面每个操作对生效的一套和正在建的一套各做一遍。

### 16.4 读榜

- `sort=HOT` 先读 `active`，再从对应的榜按名次取一页帖子 id 和成员总数，然后回库按 id 批量取帖子，拼成和帖子流相同的结构，顺序以榜为准。
- 榜上有、库里已经删掉的帖子直接丢掉，这一页可能少几条。
- `active` 不存在、榜不存在或 Redis 不可用时退回查库：近 7 天、按 `hot_score` 倒序、同分按 id 倒序。Redis 可用的话同时触发一次重算，抢不到锁就算了。

### 16.5 重算与蓝绿切换

- 时机：每天凌晨 4 点，由 xxl-job 调度，处理器名 `contentHotRebuild`（约定见 [architecture.md](architecture.md) 的定时任务一条）；服务启动完成时；读榜发现榜不存在时；管理员调重建接口时。
- 多实例靠 `content:hot:lock` 保证同一时刻只有一个在算。

步骤：

1. 抢锁，抢不到直接结束。
2. 读 `active` 得到生效的一套，另一套就是这次要建的。先删掉它的六个榜，再写 `building`。
3. 用一条更新语句把近 7 天未删除帖子的 `hot_score` 按「计数 × 当前权重」重算一遍。收藏数从 `post_favorite` 分组统计后连进来，不在 Java 里逐条算。
4. 查出这些帖子的 id、分类和 `hot_score`，分批写进要建的那一套。
5. 把 `active` 改成新的一套。
6. 删 `building`，删旧的一套，放锁。

- 第 5 步之前，读的人看到的始终是完整的旧榜，之后是完整的新榜，不会读到空榜或建了一半的榜。
- 中途失败时 `active` 没动，旧榜继续用；下一次重算的第 2 步会先清掉半成品。
- 重算顺带做三件事：把发布超过 7 天的帖子清出榜单；纠正实时更新漏掉或重复的分数；让改过的权重对近 7 天的帖子生效。
- 已知误差：第 3 步到第 5 步之间发生的操作，个别可能在新榜里少算或多算一次，下一次重算纠正。帖子满 7 天后最多在榜上多留一天。

## 17. 搜索

只搜帖子。Elasticsearch 是 MySQL 的一份随时可以重建的索引，不是数据源：它只回答「哪些帖子命中、命中在哪里」，帖子本身的内容、计数、作者仍然从库里取。

### 17.1 部署

- Elasticsearch 9.2 系列，单节点，只监听本机 9200。Spring Boot 4.0.8 自带的 Java 客户端是 9.2.9，服务端固定为可用的 9.2.8，IK 插件同为 9.2.8；客户端保留 Boot 管理的 9.2.9。
- 堆内存 512 MB，容器内存上限 1 GB，数据放命名卷。compose 里和其他中间件一样按摘要固定镜像。
- 分词用 IK 插件，装进自己构建的镜像，版本和服务端一致。当前镜像安装 IK 9.2.8，映射使用 `ik_max_word` / `ik_smart`。
- 开启账号校验，本机不开 HTTPS。内置的 `elastic` 账号只在初始化时用，密码来自环境变量 `MENG_ES_ELASTIC_PASSWORD`；
  应用用单独的账号 `meng_content_app`，密码来自 `MENG_ES_CONTENT_PASSWORD`，只有 `meng_post_*` 这些索引和别名的读写与管理权限。初始化脚本负责建角色和账号。
- content 用 Boot 自带的 `ElasticsearchClient`，不用 Spring Data 的仓库接口。连接 1 秒、读取 2 秒超时。
- 关掉 Elasticsearch 的健康检查项：它不可用时搜索走兜底，content 仍然算健康，启动也不依赖它。
- 对索引的读写集中在一个类里，由 Service 调用，其他地方不直接碰客户端。

### 17.2 索引里存什么

一条帖子一个文档，文档 id 就是帖子 id。只放搜索、筛选、排序和高亮要用的字段：

| 字段 | 类型 | 分词 | 用途 |
|---|---|---|---|
| `id` | long | 不分词 | 命中后回库取帖子 |
| `title` | text | 写入用 `ik_max_word`，查询用 `ik_smart` | 搜索、高亮 |
| `content` | text | 同上 | 搜索、高亮。存的是去掉 Markdown 标记后的纯文本，和生成摘要用同一个转换 |
| `tags` | text，另带 keyword 子字段 `tags.raw`（转小写） | 同上 | 搜索；搜索词正好等于某个标签时加分 |
| `category` | keyword | 不分词 | 按分类筛选 |
| `createTime` | date | 不分词 | 按最新排序 |

- 不放计数、作者、配图、是否喜欢：这些要么一直在变，要么因人而异，命中之后回库取。所以喜欢、收藏、浏览、评论都不会触发索引更新。
- 不放 Markdown 原文、IP 属地、封面。
- 映射关闭动态字段（`dynamic: strict`），多写一个字段直接报错。
- 一个主分片，零副本。

### 17.3 索引怎么组织

- 两个实体索引 `meng_post_blue`、`meng_post_green`，一个别名 `meng_post` 指向当前生效的那个。搜索和平时的写入都走别名。
- 重建时把没生效的那个删掉重建、灌满，再用一次别名操作把 `meng_post` 从旧的换到新的，然后删掉旧的。和热榜是同一个思路。
- 改映射或换分词器不需要迁移脚本，下一次重建出来就是新结构。

### 17.4 同步

| 事件 | 对索引的操作 |
|---|---|
| 发帖、改帖 | 写入整个文档，覆盖旧的 |
| 删帖（包括举报成立） | 删除文档 |

- 在数据库事务提交之后异步执行，不拖慢发帖。
- 任务里只带帖子 id，执行时重新读库：帖子还在就写入它现在的内容，已经删了就删文档。这样任务乱序、重复执行都不会写错。
- 失败重试 3 次，还失败就记一条日志（只记帖子 id），留给每天的重建补上。
- 重建进行中（`content:search:building` 存在）时，同一个操作对别名和正在建的那个实体索引各做一遍。

### 17.5 重建

- 时机：每天凌晨 4 点 10 分，排在热榜重算后面，由 xxl-job 调度，处理器名 `contentSearchRebuild`；服务启动时发现别名不存在；管理员调重建接口时。互斥锁是 `content:search:lock`。
- 步骤：抢锁 → 删掉并新建没生效的那个实体索引 → 写 `building` → 按 id 升序每批 500 条读出未删除的帖子，批量写入 → 刷新 → 核对文档数和库里的帖子数并记进日志 → 切别名 → 删 `building`、删旧索引、放锁。
- 中途失败时别名没动，旧索引继续用。

### 17.6 查询

`GET /content/search/posts`，参数 `q`、`category`（可空）、`sort`（`HOT` 或 `LATEST`，默认前者）、`page`、`size`。

- `q` 去掉首尾空格后 1 到 50 个字，按 Unicode 码点计。
- `size` 默认 5、最大 50。搜索结果页一页 5 条，不传 `size`。
- 在 `title`、`tags`、`content` 三个字段里搜，权重 3 : 2 : 1。搜索词被分成不超过两个词时要求全部命中，更多时要求命中四分之三。
- 标题里完整出现搜索词的再加分；搜索词正好等于某个标签的再加分。
- `category` 是过滤条件，不影响相关度。
- `LATEST`：在 Elasticsearch 里按发布时间倒序分页。
- `HOT`：按帖子当前的热度分倒序，同分按 id 倒序，不限近 7 天。索引里没有热度分，所以分两步：
  先从 Elasticsearch 按相关度取出最多 1000 个命中的帖子 id，再回库在这些 id 里按 `hot_score` 排序分页；总条数是这批 id 的个数。
- 两种排序都不按相关度排。标题和标签的加权只决定命中很多时哪 1000 条能进入「热门」的排序。
- 高亮：标题取整段；正文取命中处附近的一段，约 120 个字；正文没有命中时用帖子的摘要。
  返回 `titleSegments` 和 `summarySegments`，每段为 `{text, matched}`。后端只拆分自己的随机标记；原文中的 HTML 保留为普通文本，前端逐段插值并用 `mark` 标记命中，禁止将片段送入 `v-html`。
- 最多翻到第 10000 条，再往后返回 400。
- 返回结构和帖子流相同（`records`、`total`、`page`、`size`）。每一项在帖子流那一项的基础上多两个字段：标题片段、摘要片段。
  命中的帖子 id 回库批量取；索引里有、库里已经删掉的丢掉。

### 17.7 兜底

- Elasticsearch 的命中数为 0，或者它不可用、超时、别名不存在时，改查 MySQL：标题包含搜索词（通配符转义），可叠加分类，照常分页；`HOT` 按 `hot_score` 倒序，`LATEST` 按 id 倒序。
- 兜底只查标题，不查正文和标签。标题片段由后端按子串匹配切出来；摘要片段就是摘要，不标命中。
- 走了兜底不报错，返回结构不变。
